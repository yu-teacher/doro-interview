**모범 답변 (30~60초)**
용도에 따라 다릅니다. 출력이 256비트라고 해서 모든 용도에서 강도가 256비트인 것은 아닙니다. 충돌을 찾는 데는 출력 비트 수의 절반에 해당하는 작업이면 된다고 알려져 있고, NIST SP 800-57도 충돌 저항이 필요한 디지털 서명 같은 용도에서 SHA-256의 보안 강도를 128비트로 표시합니다. 반면 HMAC처럼 충돌 저항이 아니라 역상 저항을 가정하는 용도에서는 SHA-256이 256비트 이상의 강도를 지원하는 해시로 분류됩니다. 표를 보면 서명용 해시는 필요한 강도의 두 배 길이로 짝지어져 있습니다.

```
SHA-256 을 32비트로 자른 해시에서 충돌이 나온 시도 횟수(3회): 36277, 75159, 112177   (2^16 = 65536)
40비트로 자른 경우: 277008, 1632782, 1768698                                        (2^20 = 1048576)
```

(공식 문서) NIST SP 800-57 Part 1 Rev. 5 의 5.6.1.2 는 해시 함수의 보안 강도가 응용이 요구하는 성질에 따라 정해진다고 하고, 표 3 은 충돌 저항이 필요한 용도에서 128비트 강도에 SHA-256, SHA-512/256, SHA3-256 을, 256비트 이상에 SHA-512 와 SHA3-512 를 대응시키며(128, 192, 256비트 이상 강도에 각각 SHA-256, SHA-384, SHA-512 계열이어서 출력 길이가 강도의 두 배이다), HMAC·KMAC·키 유도·난수 생성 열에서는 SHA-256 이 256비트 이상 항목에 들어 있으며, 표의 각주 70은 HMAC 항목이 충돌 저항이 아니라 역상 저항을 가정한다고 적는다.
(보충) 충돌을 찾는 비용이 출력 길이의 절반 비트 수준이 되는 이유가 생일 역설이라는 설명은 위 문서에서 읽은 것이 아니라 일반적으로 알려진 설명이다.
(실험 확인) Python 3.14 로 SHA-256 앞 32비트(와 40비트)만 취한 값에서 충돌이 나올 때까지의 시도 횟수를 세 번 재서 위 블록의 값을 얻었고, 다시 실행해 같은 값이 나오는 것을 확인했다. 모두 2의 (비트 수의 절반) 제곱과 같은 자릿수 안팎으로, 해시 길이의 절반 수준 작업에서 충돌이 나온다는 것을 보여 주는 설명용 실험이며 SHA-256 전체에 대한 증명이 아니다.
