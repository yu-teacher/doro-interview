**모범 답변 (30~60초)**
코드 버그가 아니라 서버, 프레임워크, 클라우드 같은 스택의 설정이 안전하지 않은 상태를 말합니다. 대표적으로 기본 계정과 비밀번호를 그대로 두거나, 불필요한 포트·서비스·페이지·계정을 켜 두거나, 에러 응답에 스택 트레이스를 그대로 노출하거나, 보안 헤더를 보내지 않는 경우입니다. 예방은 불필요한 기능을 뺀 최소한의 플랫폼에서 시작하고, 개발·검수·운영 환경을 같은 방식으로 구성하되 자격 증명은 환경마다 다르게 쓰는 반복 가능한 하드닝 절차를 자동화하는 것입니다. 설정이 실제로 적용됐는지 확인하는 자동 검증도 함께 둡니다.

(원저자 자료) OWASP Top 10:2021 A05 페이지는 스택 어디든 보안 하드닝이 빠졌거나 클라우드 권한이 잘못된 경우, 불필요한 기능이 켜져 있는 경우, 기본 계정과 비밀번호가 그대로인 경우, 에러 처리가 스택 트레이스 등 과도한 정보를 사용자에게 보여 주는 경우, 서버가 보안 헤더를 보내지 않거나 안전하지 않은 값으로 보내는 경우를 취약 조건으로 든다. 예방책으로는 자동화된 반복 가능한 하드닝, 불필요한 기능과 샘플을 뺀 최소 플랫폼, 구성 검토와 패치 관리, 구성요소 분리, 보안 지시문(헤더) 전송, 모든 환경에서 설정 효과를 검증하는 자동화를 든다. 또 개발·QA·운영 환경은 동일하게 구성하되 자격 증명은 환경마다 다르게 쓰라고 한다. 이 페이지는 2021년 판에서 이 범주가 6위에서 5위로 올랐다고 한다.
