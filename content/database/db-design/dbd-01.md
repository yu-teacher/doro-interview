**모범 답변 (30~60초)**
정규화는 같은 사실을 한 곳에만 저장하도록 테이블을 나누는 것이고, 목적은 중복을 없애 갱신 이상을 막는 것입니다. 고객 이름을 주문 행마다 복사해 두면 이름이 바뀔 때 일부 행만 고쳐져 값이 어긋날 수 있지만, 고객 테이블을 따로 두고 외래키로 참조하면 한 곳만 고치면 됩니다. 반정규화는 읽기 성능을 위해 이 중복을 일부러 허용하는 것이라, 조인 비용이 실제 병목이라고 측정된 뒤에 집계 컬럼처럼 범위를 좁혀서 쓰고 값이 어긋나지 않게 갱신 경로도 함께 설계해야 합니다. 기본은 정규화에서 시작하는 것입니다.

```sql
-- 반정규화: 이름이 주문마다 복사되어 있다
UPDATE d_orders SET customer_name = 'Kim2' WHERE id = 1;  -- 일부 행만 고쳐지면 어긋난다
-- 정규화: 고객 이름은 n_customer 한 곳에만 있다
UPDATE n_customer SET name = 'Kim2' WHERE id = 1;
```

(공식 문서) PostgreSQL 16 ddl-constraints 페이지는 외래키가 참조하는 컬럼이 기본키이거나 유니크 제약이어야 한다고 하고, 참조되는 행을 지우거나 바꿀 때의 동작(RESTRICT, NO ACTION, CASCADE 등)을 고를 수 있다고 설명한다. 또 참조하는 쪽 컬럼에는 자동으로 인덱스가 만들어지지 않으므로 DELETE나 UPDATE 성능을 위해 보통 따로 인덱스를 거는 것이 좋다고 한다.
(실험 확인) PostgreSQL 16.15에서 고객 이름을 주문 5건에 복사해 둔 테이블은 한 행만 UPDATE하자 같은 `customer_id`에 이름이 2종류(`Kim2`, `Kim`)가 되었다. 고객/주문을 나눈 테이블은 고객 한 행만 고치자 조인 결과가 모두 `Kim2`였다. 외래키를 건 `n_orders`의 인덱스는 기본키 인덱스 하나뿐이었고(참조 컬럼 인덱스는 자동 생성되지 않음), 주문이 남아 있는 고객을 DELETE하면 외래키 위반 오류가 났다.
(보충) 정규화 단계(1NF~3NF)의 정의와 "조인이 병목이면 반정규화한다"는 판단 기준은 일반적인 설계 지침이다. PostgreSQL 문서는 정규화 이론 자체를 다루지 않으며, 반정규화가 실제로 빠른지는 데이터와 쿼리에 따라 달라 측정해야 한다.
