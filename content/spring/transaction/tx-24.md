**모범 답변 (30~60초)**
테스트 클래스에 `@Transactional`을 붙이면 테스트 메서드 전체가 하나의 트랜잭션이 되어, 서비스 메서드의 트랜잭션이 전부 그 안에 참여하게 됩니다. 그러면 서비스에서 예외가 나도 롤백 여부를 DB 레벨에서 따로 관찰하기 어렵고, 지연 로딩이나 더티 체킹도 영속성 컨텍스트가 테스트 전체로 열려 있어 결과가 왜곡됩니다. 데모의 `TxExperimentTest`가 클래스에 `@Transactional`을 붙이지 않고, `JdbcTemplate`으로 별도 커넥션에서 직접 조회하는 이유입니다. 정리는 `@AfterEach`에서 직접 delete 쿼리로 합니다.

(보충) 데모 코드의 주석("붙이면 테스트가 하나의 트랜잭션이 되어 실험이 왜곡된다")과 구조에 근거한 설명이다. Spring 테스트 장(testcontext-framework/tx)은 이번에 가져오지 않았다.
