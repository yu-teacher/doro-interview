**모범 답변 (30~60초)**
테스트 클래스에 `@Transactional`을 붙이면 각 테스트 메서드가 테스트가 관리하는 하나의 트랜잭션 안에서 실행되고, 공식 문서에 따르면 기본적으로 테스트가 끝나면 자동으로 롤백됩니다. 그러면 서비스 메서드의 트랜잭션이 전부 그 안에 참여하게 되어 커밋이 일어나지 않으므로, 서비스가 롤백했는지 커밋했는지를 DB 레벨에서 따로 관찰하기 어렵습니다. 또 공식 문서는 이 경우 영속성 컨텍스트를 수동으로 flush하지 않으면 거짓 양성이 날 수 있다고 경고합니다. 그래서 트랜잭션 동작 자체를 검증할 때는 클래스에 `@Transactional`을 붙이지 않고, `JdbcTemplate`으로 별도 커넥션에서 직접 조회하고, 정리는 `@AfterEach`에서 직접 delete 쿼리로 합니다.

(공식 문서) Spring 테스트 장(testcontext-framework/tx 페이지)은 클래스에 붙이면 각 테스트 메서드가 트랜잭션 안에서 실행되며 기본 자동 롤백이라고 하고, 영속성 컨텍스트 예시에서 "Manual flush is required to avoid false positive in test"라고 주석으로 밝힌다. 테스트 관리 트랜잭션은 `isolation`, `timeout`, `readOnly`를 지원하지 않는다고 표로 밝힌다.
(보충) 이 질문의 결론(트랜잭션 경계 자체를 검증할 때는 붙이지 말라)은 일반 테스트에는 `@Transactional`이 유용하다는 전제 위의 실무 판단이며, 별도 커넥션 조회와 `@AfterEach` 정리는 문서가 제시한 방법이 아니라 실험 구성에서 쓴 방식이다.
