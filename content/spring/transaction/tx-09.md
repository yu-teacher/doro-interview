**모범 답변 (30~60초)**
전파는 이미 트랜잭션이 진행 중일 때 호출된 메서드가 어떻게 행동할지를 정합니다. 기본값 REQUIRED는 기존 트랜잭션이 있으면 참여하고 없으면 새로 만듭니다. REQUIRES_NEW는 항상 독립된 물리 트랜잭션을 새로 만들어서 바깥과 따로 커밋, 롤백됩니다. NESTED는 하나의 물리 트랜잭션 안에서 세이브포인트를 잡아서, 안쪽만 세이브포인트까지 롤백하고 바깥은 계속 진행할 수 있습니다. 다만 JDBC 세이브포인트에 매핑되는 방식이라 JDBC 리소스 트랜잭션에서만 동작하고, `JpaTransactionManager`도 JDBC 세이브포인트로 지원하지만 `nestedTransactionAllowed`가 기본 false라서(중첩이 JDBC 연결에만 적용되기 때문) 기본 설정에서는 NESTED 호출이 예외를 냅니다. 공식 문서는 논리 트랜잭션(메서드마다)과 물리 트랜잭션(실제 커넥션)을 구분해서 설명합니다.

(공식 문서) NESTED는 보통 JDBC 세이브포인트에 매핑되며 JDBC 리소스 트랜잭션(`DataSourceTransactionManager` 등)에서만 동작한다고 되어 있다.
(실험 확인) Spring Boot 4.1.1과 `JpaTransactionManager` 기본 설정에서 이미 진행 중인 트랜잭션 안에서 NESTED 메서드를 호출하면 `NestedTransactionNotSupportedException`("Transaction manager does not allow nested transactions by default - specify 'nestedTransactionAllowed'")이 호출 진입 시점에 바로 발생한다. 안쪽 메서드가 성공할 상황이어도 마찬가지다. 진행 중인 트랜잭션이 없을 때 단독 호출하면 일반적인 새 트랜잭션처럼 동작한다. 주의: 안쪽 NESTED 호출의 예외를 바깥이 `try-catch`로 삼키면 세이브포인트가 성공한 것처럼 보일 수 있으니 예외 자체를 단언해야 한다.

```java
@Transactional
public void outer() {
    inner();   // 다른 빈의 @Transactional(propagation = Propagation.NESTED) 메서드
}
// -> NestedTransactionNotSupportedException (진입 시점)
```
