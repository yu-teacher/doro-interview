**모범 답변 (30~60초)**
대표 사례는 감사 로그나 실패 이력 저장처럼 본 작업이 롤백돼도 남겨야 하는 기록입니다. 주의할 점은 바깥 트랜잭션이 자기 커넥션을 계속 쥔 채로 안쪽이 커넥션을 하나 더 가져간다는 것입니다. 동시 요청이 많으면 커넥션 풀이 고갈되어 데드락처럼 멈출 수 있습니다. 공식 문서도 풀 크기가 동시 스레드 수보다 최소 1은 커야 한다고 경고합니다. 또 안쪽이 먼저 커밋되므로, 바깥이 나중에 롤백돼도 안쪽 결과는 되돌아가지 않아 데이터 정합성을 따져봐야 합니다.

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void saveAudit(AuditLog log) {
    auditRepository.save(log);   // 바깥이 롤백돼도 커밋됨
}
```

(공식 문서) 위 경고와 "안쪽 락은 안쪽 트랜잭션이 끝나면 바로 해제된다"는 설명은 propagation 페이지에 있다.
