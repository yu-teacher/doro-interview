**모범 답변 (30~60초)**
커밋이 확정된 이후에만 실행할 로직을 등록하는 장치입니다. 예를 들어 주문 저장 트랜잭션이 커밋된 뒤에 알림을 보내거나 메시지를 발행하고 싶을 때, 트랜잭션 안에서 바로 보내면 롤백됐는데 알림만 나가는 문제가 생깁니다. 저수준으로는 `TransactionSynchronizationManager.registerSynchronization`으로 `afterCommit`을 등록하고, 보통은 더 편한 `@TransactionalEventListener`를 씁니다. 이 어노테이션의 기본 phase는 AFTER_COMMIT이고, 트랜잭션이 없으면 `fallbackExecution = true`를 주지 않는 한 리스너가 아예 호출되지 않습니다.

```java
@Component
class OrderEventHandler {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void on(OrderCreated e) { /* 알림, 메시지 발행 */ }
}
```

(공식 문서) `TransactionSynchronization.afterCommit` API 문서는 커밋 후 확인 메일 같은 후속 작업에 쓸 수 있고, 이 시점에는 트랜잭션이 이미 커밋됐지만 리소스는 아직 활성이라 데이터 접근 코드가 원래 트랜잭션에 "참여"하게 되므로 트랜잭션 연산에는 REQUIRES_NEW를 쓰라고 설명한다. `@TransactionalEventListener` API 문서도 AFTER_COMMIT(기본값)에서는 트랜잭션이 이미 커밋됐지만 리소스가 아직 활성이라, 이 시점의 데이터 접근 코드는 원래 트랜잭션에 참여하되 변경은 커밋되지 않는다고 경고한다. 위 phase 목록(BEFORE_COMMIT, AFTER_COMMIT, AFTER_ROLLBACK, AFTER_COMPLETION)과 기본값, 트랜잭션 없을 때의 동작은 event 페이지에 근거한다.
(실험 확인) `afterCommit`은 커밋 때만 실행되고 롤백 때는 `afterCompletion(ROLLED_BACK)`만 실행됨을 확인했다.
(보충) 이 시점의 예외로는 이미 끝난 커밋을 되돌릴 수 없다는 점은 일반적인 설명이며 문서로 확인하지 않았다.
