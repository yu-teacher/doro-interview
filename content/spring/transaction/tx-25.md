**모범 답변 (30~60초)**
첫째, 문제가 되는 메서드를 별도 빈으로 분리하는 것이 가장 단순합니다. 둘째, `TransactionTemplate` 같은 프로그래밍 방식으로 필요한 구간만 직접 묶으면 프록시 제약과 무관합니다. 셋째, `@EnableTransactionManagement(mode = AdviceMode.ASPECTJ)`로 AspectJ 위빙을 쓰면 프록시 없이 클래스 바이트코드에 트랜잭션 로직이 들어가서 자기 호출도 처리됩니다. 대신 `spring-aspects` 의존성과 위빙 설정이 필요해서 빌드 복잡도가 올라갑니다.

(공식 문서) AspectJ 모드가 바이트코드를 위빙하며 `spring-aspects.jar`와 로드/컴파일 타임 위빙이 필요하다는 점, 자기 호출에 aspectj 모드를 권장하는 점은 annotations 페이지에, `AdviceMode.ASPECTJ`와 프록시가 없어 로컬 호출도 인터셉트된다는 점은 `@EnableTransactionManagement` API 문서에 근거한다. 구조 분리와 자기 주입은 AOP 프록시 문서가 자기 호출 해결책으로 제시한다.
(보충) `TransactionTemplate`이 프록시 제약과 무관하다는 점은 프로그래밍 방식이 프록시에 의존하지 않는다는 데서 오는 설명이며 문서가 해결책으로 직접 제시한 것은 아니다. 빌드 복잡도가 올라간다는 평가도 일반적인 판단이다.
