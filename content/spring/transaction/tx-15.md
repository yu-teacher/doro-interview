**모범 답변 (30~60초)**
프록시 방식에서는 외부에서 프록시를 통해 들어오는 호출만 인터셉트됩니다. 같은 객체 안에서 `this.method()`로 부르면 프록시를 거치지 않고 실제 객체의 메서드를 바로 부르기 때문에 `@Transactional`이 적용되지 않습니다. 실험으로 확인했습니다. 트랜잭션 없는 메서드가 같은 클래스의 `@Transactional` 메서드를 `this`로 호출하고 거기서 예외가 나는데, 테스트에서 확인하면 롤백되지 않고 행이 1건 남아 있습니다. 해결책은 문서가 가장 덜 침습적이라고 하는 구조 분리(별도 빈으로 분리), 자기 자신을 주입받아 프록시로 호출하기, 또는 AspectJ 모드로 전환하는 것입니다. `TransactionTemplate`로 경계를 직접 잡는 방법도 있습니다.

```java
public void outer(String email) {
    this.inner(email);   // 프록시를 안 거침 -> 롤백 안 됨
}
@Transactional
public void inner(String email) { ... throw ... }
```

(공식 문서) 프록시 모드에서는 자기 호출에 트랜잭션이 적용되지 않으며, 필요하면 `aspectj` 모드를 쓰라고 한다. 프록시가 완전히 초기화되어야 하므로 `@PostConstruct` 같은 초기화 코드에서 이 기능에 의존하지 말라는 주의도 있다.
(공식 문서) Spring AOP 프록시 문서는 자기 호출을 피하도록 리팩터링하는 것이 가장 덜 침습적인 방법이고, 자기 주입(self injection)이 대안이며, `AopContext.currentProxy()`는 코드를 Spring AOP에 묶으므로 마지막 수단으로 강하게 비권장한다고 설명한다. AspectJ 컴파일·로드 타임 위빙은 프록시가 없어 이 문제가 없다.
(보충) `TransactionTemplate`로 트랜잭션 경계를 코드로 잡으면 프록시와 무관하게 동작한다는 점은 프로그래밍 방식이 프록시에 의존하지 않는다는 데서 오는 설명이며, 자기 호출 해결책으로 문서가 직접 제시한 것은 아니다.
