**모범 답변 (30~60초)**
`readOnly`는 코드가 읽기만 한다는 힌트이고, 공식 문서는 Hibernate를 쓸 때처럼 최적화가 될 수 있다고 합니다. 실험에서 `@Transactional(readOnly = true)` 메서드 안에서 영속 엔티티의 이름을 "changed"로 바꿨는데, 테스트에서 DB를 조회하면 여전히 "original"이었습니다. 즉 더티 체킹에 의한 UPDATE가 나가지 않았습니다. 다만 이걸 "readOnly면 쓰기가 막힌다"로 이해하면 안 됩니다. 이번 실험이 보여준 건 JPA 환경에서 flush가 일어나지 않아 변경이 반영되지 않았다는 점까지입니다.

(공식 문서) read-only는 읽기만 한다는 표시이며 일부 환경(예: Hibernate)에서 최적화 효과가 있다(strategies 페이지). 참여(participating) 트랜잭션은 기본적으로 안쪽의 readOnly를 조용히 무시하며, `validateExistingTransaction`을 켜면 불일치를 거부한다(propagation 페이지). `HibernateJpaDialect` API 문서는 readOnly 여부에 따라 Hibernate flush 모드를 준비하고 트랜잭션 종료 때 되돌리며, 설정에 따라 JDBC Connection에 readOnly 플래그를 적용할 수 있다고 설명한다.
(보충) readOnly 트랜잭션에서 flush 모드가 구체적으로 어떤 값(MANUAL 등)이 되는지는 문서에서 확인하지 못했고 구현체와 버전에 따라 다를 수 있다. 실험이 보여주는 것은 "JPA 환경에서 변경이 반영되지 않았다"까지다.

```java
@Transactional(readOnly = true)
public void updateInReadOnly(Long memberId) {
    memberRepository.findById(memberId).orElseThrow().update("changed");
}
// 호출 후 DB 조회: name == "original"
```
