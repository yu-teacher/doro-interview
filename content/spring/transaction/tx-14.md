**모범 답변 (30~60초)**
지연 로딩은 프록시 객체를 실제로 접근하는 순간 영속성 컨텍스트를 통해 쿼리를 날리는 방식이라, 영속성 컨텍스트가 열려 있어야 합니다. 실험에서 `@Transactional(readOnly = true)` 메서드 안에서 `post.getMember().getName()`을 호출하면 정상으로 나옵니다. 반면 같은 코드를 트랜잭션 없이 실행하면 영속성 컨텍스트가 이미 닫혀 있어 `LazyInitializationException`이 발생합니다. 그래서 필요한 연관 데이터는 트랜잭션 안에서 DTO로 변환하거나 fetch join으로 가져오는 게 안전합니다.

(공식 문서) Spring transaction 장은 지연 로딩을 다루지 않는다. Hibernate 사용자 가이드는 LAZY 연관은 접근 전에 초기화되어야 하며 그러지 않으면 `LazyInitializationException`이 던져진다고 하고, 가장 좋은 방법은 영속성 컨텍스트를 닫기 전에 필요한 연관을 모두 가져오는 것이라며 `JOIN FETCH`를 소개한다.
(보충) "트랜잭션이 영속성 컨텍스트 범위를 정한다"는 연결과 DTO 변환은 일반적인 대응 방법이며 문서가 제시한 것은 아니다. 실험이 확인한 사실은 "트랜잭션 안에서는 성공, 밖에서는 예외"까지다.

```java
@Transactional(readOnly = true)
public String lazyLoadInTransaction(Long postId) {
    Post post = postRepository.findById(postId).orElseThrow();
    return post.getTitle() + " by " + post.getMember().getName();  // 성공
}
// 같은 본문에 @Transactional 이 없으면 -> LazyInitializationException
```
