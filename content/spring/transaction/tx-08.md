**모범 답변 (30~60초)**
기본적으로 `RuntimeException`과 `Error`가 던져지면 롤백하고, 체크 예외는 롤백하지 않고 커밋합니다. 그래서 `IOException` 같은 체크 예외를 던지면서도 롤백하고 싶다면 `rollbackFor = IOException.class`를 명시해야 합니다. 반대로 특정 런타임 예외에서 커밋하고 싶으면 `noRollbackFor`를 씁니다. 여러 규칙이 맞으면 가장 강하게 매칭되는 규칙이 이깁니다. Spring 6.2부터는 `@EnableTransactionManagement(rollbackOn = ALL_EXCEPTIONS)`로 전역 기본값을 바꿀 수도 있습니다.

```java
@Transactional(rollbackFor = IOException.class)
public void importFile(Path path) throws IOException { ... }
```

(공식 문서) `rollbackForClassName` 같은 이름 패턴은 클래스 이름에 패턴이 "포함"되면 매칭되므로 의도치 않은 클래스가 잡힐 수 있다고 경고한다. 예외 없이 롤백하려면 `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()`를 쓸 수 있으나, 문서는 POJO 지향과 어긋난다며 선언적 규칙을 권장한다.
