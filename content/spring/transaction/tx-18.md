**모범 답변 (30~60초)**
REQUIRED로 참여한 안쪽 메서드는 바깥과 같은 물리 트랜잭션을 공유합니다. 안쪽에서 롤백 대상 예외가 나면 인터셉터가 그 트랜잭션을 rollback-only로 표시합니다. 이때 바깥에서 예외를 try-catch로 삼키고 정상 종료해서 커밋을 시도하면, 이미 롤백만 가능한 상태라서 실제로는 롤백되고, Spring이 호출자가 커밋된 줄 착각하지 않도록 `UnexpectedRollbackException`을 던집니다. 해결하려면 안쪽 예외를 바깥도 롤백으로 받아들이거나, 안쪽을 REQUIRES_NEW로 분리해서 부분 실패를 허용하는 식으로 의도를 맞춥니다. NESTED도 개념상 가능하지만 JPA 환경(`JpaTransactionManager` 기본 설정)에서는 지원되지 않습니다.

```java
@Transactional
public void outer() {
    try {
        inner.doWork();          // REQUIRED 참여, 예외 -> rollback-only 표시
    } catch (RuntimeException e) {
        // 삼켜도 이미 rollback-only
    }
}   // 커밋 시도 -> UnexpectedRollbackException
```

(공식 문서) propagation 페이지가 "내부 범위가 rollback-only로 표시하면 바깥 호출자는 커밋이 아닌 롤백이 수행됐음을 명확히 알리는 `UnexpectedRollbackException`을 받아야 한다"는 취지로 설명한다. (직접 인용 최소화: 문서 표현은 "needs to receive an UnexpectedRollbackException".)
