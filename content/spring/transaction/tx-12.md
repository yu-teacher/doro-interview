**모범 답변 (30~60초)**
격리 수준은 동시 트랜잭션 사이에 서로의 변경이 얼마나 보이는지를 정합니다. READ_UNCOMMITTED는 커밋되지 않은 값도 읽는 dirty read가 가능합니다. READ_COMMITTED는 dirty read를 막지만 같은 쿼리를 두 번 읽을 때 값이 달라지는 non-repeatable read가 가능합니다. REPEATABLE_READ는 같은 행을 다시 읽어도 같은 값을 보장하고, SERIALIZABLE은 phantom, 즉 두 번째 조회에서 새 행이 나타나는 현상까지 막지만 동시성이 크게 떨어집니다. MySQL InnoDB의 기본은 REPEATABLE READ입니다. Spring의 기본은 `ISOLATION_DEFAULT`라서 DB 기본값을 그대로 따릅니다.

(공식 문서) `@Transactional`의 기본 격리는 `ISOLATION_DEFAULT`이고, `isolation` 속성은 REQUIRED/REQUIRES_NEW에만 적용된다. 격리 수준은 "커밋 전 쓰기를 볼 수 있는지" 같은 정도를 정의한다고 strategies 페이지가 설명한다.
(보충) 이상 현상 정의는 표준 SQL 설명이다. InnoDB 기본이 REPEATABLE READ라는 점은 널리 알려진 MySQL 사실이지만 이번 조사(Spring 문서)에서 확인한 것은 아니다. 또 InnoDB의 REPEATABLE READ는 MVCC 스냅샷과 갭 락 덕분에 표준보다 phantom을 더 잘 막는 것으로 알려져 있어, 표준 표와 완전히 같다고 단정하면 안 된다. 정확한 동작은 MySQL 문서로 별도 확인이 필요하다.
