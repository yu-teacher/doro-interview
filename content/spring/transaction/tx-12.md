**모범 답변 (30~60초)**
격리 수준은 동시 트랜잭션 사이에 서로의 변경이 얼마나 보이는지를 정합니다. READ_UNCOMMITTED는 커밋되지 않은 값도 읽는 dirty read가 가능합니다. READ_COMMITTED는 dirty read를 막지만 같은 쿼리를 두 번 읽을 때 값이 달라지는 non-repeatable read가 가능합니다. REPEATABLE_READ는 같은 행을 다시 읽어도 같은 값을 보장하고, SERIALIZABLE은 phantom, 즉 두 번째 조회에서 새 행이 나타나는 현상까지 막지만 동시성이 크게 떨어집니다. MySQL InnoDB의 기본은 REPEATABLE READ입니다. Spring의 기본은 `ISOLATION_DEFAULT`라서 DB 기본값을 그대로 따릅니다.

(공식 문서) `@Transactional`의 기본 격리는 `ISOLATION_DEFAULT`(기반 데이터 저장소의 기본값)이고, `isolation` 속성은 REQUIRED/REQUIRES_NEW에만 적용된다(annotations 페이지). 각 수준이 허용하는 이상 현상은 Spring `Isolation` API 문서에 정의되어 있다. READ_UNCOMMITTED는 셋 다 가능, READ_COMMITTED는 dirty read만 방지, REPEATABLE_READ는 phantom만 가능, SERIALIZABLE은 전부 방지한다. InnoDB의 기본이 REPEATABLE READ이고 일반 SELECT는 첫 읽기가 만든 스냅샷을 일관되게 읽는다는 것은 MySQL 문서에 있다.
(보충) InnoDB는 잠금 읽기(`FOR UPDATE` 등)와 UPDATE·DELETE에서 갭 락·next-key 락으로 삽입을 막는다고 MySQL 문서가 설명하므로, 표준 표와 완전히 같다고 단정하면 안 된다. InnoDB의 phantom 동작을 정확히 말하려면 MySQL 문서의 Phantom Rows 절을 별도로 읽어야 하며, 읽지 않았다.
