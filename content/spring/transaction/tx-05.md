**모범 답변 (30~60초)**
두 케이스를 비교하는 실험을 했습니다. `@Transactional` 메서드 안에서 Member와 Post를 저장하고 `IllegalStateException`을 던지면, 테스트에서 DB를 직접 조회했을 때 저장된 행이 0건입니다. 런타임 예외로 전부 롤백된 겁니다. 반대로 `@Transactional` 없이 `save` 한 번 하고 예외를 던지면 행이 1건 남습니다. Spring Data JPA 리포지토리의 `save`에 자체 `@Transactional`이 붙어 있어서 호출마다 따로 커밋되기 때문입니다. 즉 여러 저장을 한 묶음으로 롤백하려면 서비스 메서드 단위로 트랜잭션 경계를 잡아야 합니다.

```java
@Transactional
public void withTransactionThenFail(String email) {
    Member member = memberRepository.save(...);
    postRepository.save(...);
    throw new IllegalStateException(email);   // -> countByEmail == 0
}

public void withoutTransactionThenFail(String email) {
    memberRepository.save(...);               // 각각 커밋됨
    throw new IllegalStateException(email);   // -> countByEmail == 1
}
```

(공식 문서) Spring Data JPA 문서는 CRUD 메서드가 `SimpleJpaRepository`에서 트랜잭션 설정을 가져오고, 읽기는 readOnly, `save` 같은 쓰기는 기본 `@Transactional`이라고 설명한다. 바깥 트랜잭션이 있으면 그 설정이 우선해 참여한다.
(보충) "바깥 트랜잭션이 없으면 `save`가 새 트랜잭션을 시작해 커밋한다"는 기본 전파(REQUIRED)에서 오는 추론이며 문서가 명시하지는 않는다. 실험이 확인하는 사실은 "행이 남는다"까지다.
