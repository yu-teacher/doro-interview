**모범 답변 (30~60초)**
저희 데모 프로젝트에 두 케이스를 비교하는 실험이 있습니다. `withTransactionThenFail`은 `@Transactional` 안에서 Member와 Post를 저장하고 `IllegalStateException`을 던지는데, 테스트에서 DB를 직접 조회해 보면 저장된 행이 0건입니다. 런타임 예외로 전부 롤백된 겁니다. 반대로 `withoutTransactionThenFail`은 `@Transactional`이 없어서 `save`마다 `SimpleJpaRepository`의 자체 트랜잭션으로 각각 커밋되고, 이후 예외가 나도 행이 1건 남습니다. 즉 롤백은 서비스 메서드 단위로 경계를 잡아야 의미가 있습니다.

```java
@Transactional
public void withTransactionThenFail(String email) {
    Member member = memberRepository.save(...);
    postRepository.save(...);
    throw new IllegalStateException(email);   // -> countByEmail == 0
}

public void withoutTransactionThenFail(String email) {
    memberRepository.save(...);               // 각각 커밋됨
    throw new IllegalStateException(email);   // -> countByEmail == 1
}
```

(보충) 트랜잭션 없는 쪽이 저장되는 이유는 Spring Data JPA 리포지토리의 `save`가 자체적으로 트랜잭션을 가지기 때문이라고 이해하고 있다. 테스트가 확인하는 사실은 "행이 남는다"까지다.
