**모범 답변 (30~60초)**
ORM은 객체와 관계형 DB 테이블을 매핑해서, SQL 대신 객체를 다루듯 데이터를 저장하고 조회하게 해 주는 기술입니다. 둘은 모델링 방식이 달라서 불일치가 생깁니다. 객체는 상속과 다형성이 있지만 테이블은 없고, 객체는 참조로 연관을 맺지만 테이블은 외래 키로 맺습니다. 그래서 객체는 단방향 참조 두 개가 필요한 관계가 테이블에서는 FK 하나로 끝나고, 객체 그래프 탐색은 곧 SQL 실행이라 탐색 범위 문제가 생깁니다. 동일성 비교도 객체는 `==`와 `equals`, DB는 PK입니다. JPA는 이 간극을 영속성 컨텍스트와 매핑 메타데이터로 메우지만, 그 대가로 N+1 같은 문제를 이해하고 관리해야 합니다.

```java
// 객체 세계: member.getPosts() 로 탐색
// 테이블 세계: post.member_id (FK) 하나뿐, 반대 방향은 JOIN
```
