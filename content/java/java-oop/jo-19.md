**모범 답변 (30~60초)**
record의 불변은 얕은 불변입니다. 필드가 final이라 컴포넌트가 가리키는 참조를 바꿀 수는 없지만, 그 참조가 가리키는 리스트나 배열의 내용은 바꿀 수 있습니다. 생성자가 받은 객체를 그대로 저장하고 접근자가 내부 객체를 그대로 돌려주니, 호출자가 원본 리스트를 바꾸거나 접근자로 얻은 배열을 고치면 record 안의 값이 바뀝니다. 그래서 컴팩트 생성자에서 List.copyOf로 방어적 복사를 해 변경 불가 리스트를 저장하는 식으로 막습니다. 또 record의 equals는 참조 타입 컴포넌트마다 equals를 호출하는데 배열의 equals는 참조 비교라서, 내용이 같은 배열을 가진 두 record도 서로 다르다고 나옵니다. 그래서 배열 대신 List를 쓰는 편이 낫습니다.

```java
record Bag(List<String> items, int[] nums) {}
record Safe(List<String> items) { Safe { items = List.copyOf(items); } }   // 방어적 복사
```

(공식 문서) Record API 문서는 record가 "shallowly immutable"한 운반체이며 생성자·접근자를 직접 쓰는 주된 이유가 인자 검증, 가변 컴포넌트의 방어적 복사, 정규화라고 한다. JLS 8.10.3은 참조 타입 컴포넌트의 equals가 해당 컴포넌트 값의 `equals` 호출로 정해진다고 하고, Object API 문서는 `equals`의 기본 구현이 참조 동일성 비교라고 하고, JLS 10.7은 배열 타입이 `clone`을 제외한 Object의 멤버를 그대로 상속한다고 한다.
(실험 확인) 리스트와 `int[]`를 가진 record에서 원본 리스트에 추가한 요소와 접근자로 얻은 리스트·배열에 가한 변경이 모두 record에 반영됐다. 내용이 같은 리스트와 배열(다른 인스턴스)을 가진 두 record는 `equals`가 `false`였고 같은 배열 참조를 쓰면 `true`였다. `Safe`는 원본에 요소를 더해도 영향이 없었고 `add`는 `UnsupportedOperationException`이었다. 배열 컴포넌트의 `toString`은 `A[x=[I@...]`처럼 배열 객체의 기본 표기가 나왔다.
(보충) 배열 대신 List를 쓰라는 것은 일반적인 설계 조언이다.
