**모범 답변 (30~60초)**
enum은 인스턴스가 선언한 상수 몇 개로 고정되는 특수한 클래스입니다. 암묵적으로 java.lang.Enum을 상속하고, 생성자는 public·protected를 쓸 수 없고 제어자가 없으면 private이라 new로 만들 수 없으며, clone과 리플렉션 생성과 역직렬화로도 추가 인스턴스가 생기지 않게 막혀 있습니다. 그래서 == 로 비교해도 안전하고 싱글톤이나 전략 같은 용도로 씁니다. 필드, 생성자, 메서드를 가질 수 있고 상수마다 클래스 본문을 달아 추상 메서드를 각자 구현할 수도 있습니다. values()와 valueOf(String)가 자동으로 제공되고, enum을 키로 쓰는 효율적인 EnumMap과 EnumSet이 있습니다. ordinal()은 선언 순서라서 영속 데이터에 쓰는 것은 피합니다.

(공식 문서) JLS 8.9는 enum의 직접 상위 클래스가 Enum<E>이고 상수 외의 인스턴스가 없으며 명시적 인스턴스화는 컴파일 오류라고 하고, 추가 인스턴스를 막는 세 장치(최종 `Enum.clone`, 리플렉션 생성 금지, 직렬화 특수 처리)를 든다. 8.9.2는 생성자가 public·protected일 수 없고 제어자가 없으면 private이라고, enum이 추상 메서드를 가지려면 모든 상수가 본문으로 구현해야 한다고 한다. values()·valueOf(String)가 암묵적으로 선언된다는 것은 8.9.3에, 상수 본문이 있으면 enum이 암묵적으로 sealed라는 것은 8.9에 있다. Enum 문서는 키 타입이 enum일 때 전용 Set·Map 구현이 있다고 하고 `clone`이 CloneNotSupportedException을 던진다고 하며, EnumMap 문서는 컴팩트하고 효율적이며 키의 자연 순서(선언 순서)로 유지된다고 한다.
(실험 확인) `Color.valueOf("BLUE")`는 `IllegalArgumentException: No enum constant E05.Color.BLUE`, 리플렉션 생성자 호출은 `Cannot reflectively create enum objects`였다. 상수 본문이 있는 상수의 클래스는 `E05$Op$1`이고 `getDeclaringClass()`는 `Op`였으며, 그 enum의 `isSealed()`는 `true`였고 `getPermittedSubclasses()`가 상수 본문 클래스 둘이었다. 본문이 없는 enum은 `isSealed()`가 `false`이고 final이었다. 직렬화했다가 역직렬화한 상수는 원래 상수와 `==`였고, `Enum.clone`의 수정자는 `protected final`이었다. `new C()`는 `enum classes may not be instantiated`, enum 생성자에 `public`을 붙이면 `modifier public not allowed here`로 컴파일되지 않았다. `EnumMap`은 넣은 순서와 관계없이 선언 순서(`{RED=2, GREEN=1}`)로 출력됐다.
(보충) `ordinal()`을 DB 같은 영속 데이터에 쓰면 상수 순서를 바꿀 때 값의 의미가 바뀐다는 점과, enum을 싱글톤·전략 용도로 쓴다는 활용 예시는 일반적인 설명이다.
