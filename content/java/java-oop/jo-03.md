**모범 답변 (30~60초)**
public은 어디서든, protected는 같은 패키지와 다른 패키지의 하위 클래스에서, 아무것도 쓰지 않은 기본(package-private)은 같은 패키지 안에서만, private은 선언이 속한 최상위 클래스의 본문 안에서만 접근할 수 있습니다. private이 클래스 단위가 아니라 최상위 클래스 본문 기준이라 중첩 클래스끼리는 서로의 private 멤버에 접근할 수 있습니다. 다른 패키지의 하위 클래스가 protected 인스턴스 멤버를 쓸 때는 자기 타입이나 그 하위 타입의 참조로만 접근할 수 있다는 제약도 있습니다. 인터페이스 멤버는 제어자를 안 쓰면 암묵적으로 public이고, 모듈 시스템에서는 public이어도 패키지를 export하지 않으면 다른 모듈에서 쓸 수 없습니다.

(공식 문서) JLS 6.6.1은 각 접근 수준의 허용 범위와 인터페이스 멤버가 암묵적으로 public이라는 점, private이 최상위 클래스 본문 안에서 허용된다는 점, public 최상위 타입도 export되지 않은 패키지면 같은 모듈에서만 접근된다는 점을 밝힌다. 6.6.2.1은 protected 인스턴스 멤버를 다른 패키지의 하위 클래스 S가 쓸 때 한정 타입이 S 또는 S의 하위 클래스여야 한다고 밝힌다.
(실험 확인) 같은 최상위 클래스 안의 inner·static 중첩 클래스에서 바깥 클래스의 private 필드를 읽어 `42`가 나왔다. 다른 패키지의 하위 클래스에서 `Base` 타입 참조로 protected 필드를 읽으면 `x has protected access in Base`, 기본 접근 필드는 `pkg is not public in Base; cannot be accessed from outside package`로 컴파일되지 않았고, `this`나 하위 클래스 타입 참조로는 통과했고, protected static 멤버는 `Base` 타입 참조로도 접근됐다(한정 타입 제약은 인스턴스 멤버에만 적용).
(보충) 접근 제어자는 캡슐화를 위한 설계 도구이고 보안 경계로 쓰는 것이 아니라는 점은 일반적인 설계 조언이다.
