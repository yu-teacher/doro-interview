**모범 답변 (30~60초)**
static 중첩 클래스는 바깥 클래스 이름 아래에 놓였을 뿐 바깥 인스턴스와 무관하고, static이 아닌 멤버 클래스인 inner 클래스는 만들어질 때 바깥 인스턴스에 묶여 바깥의 인스턴스 멤버를 바로 쓸 수 있습니다. 지역 클래스는 메서드 안에서 선언하고, 익명 클래스는 이름 없이 선언과 생성을 한 번에 하는 것으로, 둘 다 둘러싼 메서드의 지역 변수를 쓰려면 final이거나 effectively final이어야 합니다. 바깥 인스턴스에 묶인 객체는 바깥 객체를 참조로 들고 있을 수 있어서, 오래 사는 곳에 등록되면 바깥 객체가 GC되지 못하게 붙잡을 수 있습니다. 바깥 객체가 필요 없다면 static 중첩 클래스로 만드는 것이 안전합니다.

(공식 문서) JLS 8.1.3은 static이 아닌 멤버 클래스, 정적 문맥이 아닌 곳의 지역 클래스, 익명 클래스를 inner 클래스로 분류하고, inner 클래스 인스턴스가 둘러싼 인스턴스와 연결될 수 있다고 하며(정적 문맥의 지역·익명 클래스는 둘러싼 인스턴스가 없다), 멤버 enum·record·인터페이스는 암묵적으로 static이라 inner가 아니라고 한다. 지역 클래스는 블록이 직접 포함하는 중첩 클래스(14.3)이고 익명 클래스는 클래스 인스턴스 생성 식이 암묵적으로 선언한다(15.9.5). 내부 클래스가 쓰는 지역 변수·매개변수는 final이거나 effectively final이어야 하고(8.1.3, 6.5.6.1) 람다에도 같은 규칙이 적용된다고 한다. Java 16 이전에는 inner 클래스가 static 초기화 블록과(상수가 아닌) static 멤버를 선언할 수 없었다고 8.1.3에 적혀 있다.
(실험 확인) 바깥 필드를 쓰는 inner 클래스는 리플렉션 필드 목록에 합성 필드 `this$0`이 있었고, 바깥을 쓰지 않는 inner 클래스와 static 중첩 클래스, 바깥을 쓰지 않는 익명 클래스에는 없었다(JDK 25 javac 결과. 이전 버전은 아래 추가 실험 참고). HotSpot에서 바깥 필드를 쓰는 inner 객체를 지역 리스트에 담고 바깥 객체의 다른 참조를 버린 뒤 `System.gc()`를 여러 번 불러도 `WeakReference`로 본 바깥 객체가 수거되지 않았고, 바깥을 쓰지 않는 inner 객체만 담았을 때는 수거됐다(GC 동작은 구현 의존이다). static 메서드에서 `new In()`은 `non-static variable this cannot be referenced from a static context`, 값이 바뀌는 지역 변수를 람다에서 쓰면 `local variables referenced from a lambda expression must be final or effectively final`로 컴파일되지 않았다. 익명 클래스의 이름은 `E08$2`처럼 번호가 붙었고 `isAnonymousClass()`가 `true`였다.
(실험 확인) 같은 코드를 Corretto 8, 11.0.33, 17.0.21의 javac로 컴파일하면 바깥을 쓰지 않는 inner 클래스(`NoOuter`)와 인스턴스 메서드 안의 바깥을 쓰지 않는 익명 클래스에도 합성 필드 `this$0`이 있었고, Corretto 21.0.13과 25에서는 없었다(바깥을 쓰는 클래스에는 모든 버전에 있었다). 다만 Corretto 21의 javac도 `--release 17` 이하로 컴파일하면 `this$0`가 남았고 `--release 18`부터 빠졌으며, 바깥을 쓰지 않아도 `Serializable`을 구현한 inner 클래스에는 21·25에서도 있었다. 그래서 "바깥을 쓰지 않으면 `this$0`가 없다"는 것은 javac와 대상 릴리스에 따른 구현 차이이고 항상 성립하지는 않는다. `static` 중첩 클래스와 정적 메서드 안의 익명 클래스에는 어느 버전에도 없었다. 또 inner 클래스 안의 `static int n`·`static` 초기화 블록·`static` 메서드는 Corretto 8과 11에서 `Illegal static declaration in inner class`로 컴파일되지 않았고 17에서는 컴파일·실행됐다(Corretto 17 javac의 `--release 15`는 같은 오류, `--release 16`은 컴파일됐다. 상수인 `static final int`는 8에서도 허용됐다).
(보충) 도달 가능한 객체는 수거되지 않는다는 점에서 바깥 참조가 GC를 막는다는 설명은 일반적인 설명이며 위 실험 한 번으로 재현했을 뿐 JLS에서 확인한 규칙이 아니다. 바깥 참조가 합성 필드 `this$0`로 구현된다는 것도 javac 구현 사항이고, 바깥 객체가 필요 없으면 static 중첩 클래스로 만들라는 권고도 일반적인 설계 지침이다.
