**모범 답변 (30~60초)**
Object.clone()은 protected 메서드로, 객체의 필드 값을 그대로 복사한 새 인스턴스를 만드는 얕은 복사를 합니다. 그래서 참조 필드는 원본과 복사본이 같은 객체를 가리키고, 깊은 복사를 하려면 가변 객체를 직접 복사해 교체해야 합니다. 클래스가 Cloneable을 구현하지 않았으면 CloneNotSupportedException이 던져지는데, Cloneable에는 clone 메서드가 없고 복제를 허용한다는 표시 역할만 합니다. 관례상 super.clone()을 호출해 얻고 public으로 공개하며 반환 타입을 공변으로 좁힙니다. 배열의 clone도 얕은 복사라 2차원 배열은 안쪽 배열이 공유됩니다. 이 방식이 까다로워서 복사 생성자나 정적 팩토리로 복사를 구현하는 경우가 많습니다.

```java
class Team implements Cloneable {
    List<String> members = new ArrayList<>();
    @Override public Team clone() {
        try { return (Team) super.clone(); }          // 필드를 그대로 복사: members 는 같은 리스트
        catch (CloneNotSupportedException e) { throw new AssertionError(e); }
    }
    Team(Team o) { this.members = new ArrayList<>(o.members); }   // 복사 생성자: 독립된 리스트
}
```

(공식 문서) Object API 문서의 `clone`은 기본 구현이 Cloneable이 아니면 CloneNotSupportedException을 던지고, 새 인스턴스를 만들어 필드를 대입하듯 그대로 복사하며 필드의 내용 자체는 복제하지 않아 "shallow copy"라고 밝힌다. 관례(super.clone() 호출, 가변 "deep structure" 복제), 배열이 Cloneable로 간주되고 `T[]` 반환 타입을 갖는다는 점도 같은 문서에 있다. Cloneable 문서는 이 인터페이스에 clone 메서드가 없고 관례상 public으로 오버라이드해야 한다고 한다. JLS 10.7은 다차원 배열의 clone이 얕아서 바깥 배열만 새로 만들고 안쪽 배열은 공유한다고 한다.
(실험 확인) `clone()`으로 복사할 때는 생성자 로그가 다시 출력되지 않았고(JDK 25 HotSpot에서 관찰한 동작이다. Object 문서는 생성자 호출 여부를 서술하지 않는다), 복사본의 리스트에 추가한 요소가 원본에도 보였으며(`same list=true`) 복사 생성자로 만든 객체는 독립이었다. `Cloneable`이 아닌 클래스에서 `super.clone()`은 `CloneNotSupportedException`이었다. 2차원 배열을 `clone()`하면 바깥 배열만 새로 만들어지고 안쪽 배열은 공유돼 한쪽에서 바꾼 값이 다른 쪽에도 보였고, 1차원 `int[]`의 복사본은 독립이었다.
(보충) 반환 타입을 공변으로 좁힌다는 것은 JLS 8.4.8.3이 허용하는 오버라이딩 방식을 쓰는 일반적인 관행이다. clone 대신 복사 생성자나 정적 팩토리를 권하는 것도 일반적인 실무 관행이다.
