**모범 답변 (30~60초)**
컴팩트 생성자는 record 이름 뒤에 매개변수 없이 본문만 쓰는 정규 생성자의 축약형으로, 검증과 정규화만 적으면 본문이 끝난 뒤 컴파일러가 매개변수 값을 필드에 대입해 줍니다. 그래서 본문에서 lo나 hi라고 쓰면 필드가 아니라 매개변수를 가리키고, 여기에 새 값을 대입하면 그 값이 필드에 저장되며, this.lo에 직접 대입하는 것은 컴파일 오류입니다. 정규 생성자를 매개변수까지 직접 쓰면 필드를 손수 대입해야 합니다. 정규 생성자의 접근 범위는 record만큼 또는 그보다 넓어야 합니다. 접근자는 재정의할 수 있지만, r의 접근자 값으로 새로 만든 record가 r과 equals여야 한다는 불변식을 지켜야 합니다.

```java
record Range(int lo, int hi) {
    Range {                                   // 컴팩트 생성자: 매개변수 lo, hi 를 정규화
        if (lo > hi) { int t = lo; lo = hi; hi = t; }
    }                                         // 끝나면 this.lo = lo; this.hi = hi; 가 자동 실행
}
new Range(5, 2)    // Range[lo=2, hi=5]
```

(공식 문서) JLS 8.10.4.2는 컴팩트 생성자의 본문에서 단순 이름이 필드가 아닌 암묵적 매개변수를 가리키고, 본문이 끝나면 매개변수 값으로 필드가 초기화되며, `return`·명시적 생성자 호출·필드 대입이 금지된다고 한다. 8.10.4.1은 정규 생성자의 접근 범위가 record 이상이어야 하고 매개변수 이름이 컴포넌트와 같아야 한다고 하고, 8.10.3은 명시적 접근자가 public 인스턴스 메서드여야 하며 반환 타입이 컴포넌트 타입과 같아야 한다고 한다. 접근자를 비틀어서 복사본과 equals가 아니게 만드는 `SmallPoint` 예제를 나쁜 스타일로 든다. Record API 문서의 invariant와 같은 내용이다.
(실험 확인) `new Range(5, 2)`가 `[2..5]`로 정규화됐다. 접근자 `name()`을 대문자로 돌려주게 재정의해도 `toString()`은 필드를 직접 읽어 `Person[name=kim, age=3]`로 나왔다(JLS도 equals·hashCode·toString이 접근자가 아닌 필드를 쓴다고 한다). 컴팩트 생성자 안의 `this.x = x`는 `cannot assign a value to final variable x`로 컴파일되지 않았다. 컴팩트 생성자에 `return`을 쓰면 `compact constructor must not have return statements`, `public record`의 정규 생성자를 기본 접근으로 선언하면 `attempting to assign stronger access privileges; was public`, 접근자를 public이 아니게 선언하면 `accessor method must be public`, 정규 생성자의 매개변수 이름을 바꾸면 `invalid parameter names in canonical constructor`로 컴파일되지 않았다.
