**모범 답변 (30~60초)**
추상 클래스는 일부만 구현된 미완성 클래스라서 직접 인스턴스를 만들 수 없고, 하위 클래스가 이어받아 완성합니다. 인스턴스 필드와 생성자를 가질 수 있어서 하위 클래스들이 공유하는 상태와 뼈대 로직을 담기에 좋지만, 클래스는 하나만 상속할 수 있습니다. 인터페이스는 구현 클래스가 지킬 계약을 표현하고 여러 개를 동시에 구현할 수 있으며, 필드는 암묵적으로 public static final 상수라 인스턴스 상태를 가질 수 없습니다. default 메서드로 기본 구현은 줄 수 있어도 상태가 없으니 필드를 쓰는 구현은 못 합니다. 그래서 같은 계열이 공유할 상태와 코드가 있으면 추상 클래스, 서로 다른 계층의 클래스가 공통 능력을 약속하면 인터페이스를 씁니다.

(공식 문서) JLS 8.1.1.1은 추상 클래스를 미완성 클래스로 정의하고, 직접 생성은 컴파일 오류이며 추상이 아닌 하위 클래스를 생성하면 추상 클래스의 생성자와 인스턴스 필드 초기화가 실행된다고 한다. 클래스의 extends 절은 클래스 하나만 받고(8.1.4) implements 절은 인터페이스 목록을 받는다(8.1.5). 인터페이스 필드가 암묵적으로 public, static, final이라는 점은 JLS 9.3에, 인터페이스 본문에 올 수 있는 멤버가 상수·메서드·멤버 타입뿐이라는 점은 9.1.4의 문법에 근거한다.
(실험 확인) 추상 클래스를 `new` 하면 `X is abstract; cannot be instantiated`, 인터페이스 필드에 대입하면 `cannot assign a value to static final variable V`로 컴파일되지 않았다. 인터페이스 안에 초기화 없는 필드(`int x;`)는 `= expected`, 생성자는 `<identifier> expected`, 초기화 블록은 `initializers not allowed in interfaces`로 거부됐다. 리플렉션으로 본 인터페이스 필드 수정자는 `public static final`이고 선언된 생성자는 0개였으며, 추상 클래스를 상속한 `Duck`을 만들 때 추상 클래스의 생성자가 실행됐다(`Animal ctor duck`).
(보충) 추상 클래스 vs 인터페이스를 고르는 기준(같은 계열의 공유 상태·코드 vs 능력의 약속)은 공식 문서의 규칙이 아니라 일반적인 설계 지침이다. default 메서드는 Java 8(JEP 126), private 메서드는 Java 9(JEP 213) 릴리스에 들어왔다. 그보다 앞서 인터페이스가 구현을 가질 수 없었다는 것은 이 문서들에서 직접 확인하지 못한 일반 지식이다(자세한 내용은 jo-09).
