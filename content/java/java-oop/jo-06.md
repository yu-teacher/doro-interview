**모범 답변 (30~60초)**
record는 값의 묶음을 나르는 불변 데이터 클래스를 짧게 선언하는 문법으로, Java 16에서 정식이 됐습니다. 헤더에 컴포넌트를 적으면 컴파일러가 private final 필드, 표준 생성자, 컴포넌트와 같은 이름의 public 접근자, 그리고 모든 컴포넌트를 기준으로 하는 equals, hashCode, toString을 만들어 줍니다. 암묵적으로 final이라 상속할 수 없고 Record를 이미 상속하므로 다른 클래스도 상속할 수 없지만, 인터페이스는 구현하고 static 멤버와 일반 메서드도 둘 수 있습니다. 헤더에 없는 인스턴스 필드는 선언할 수 없습니다. 다만 불변은 얕은 불변이라 컴포넌트가 가변 객체면 그 내용은 바뀔 수 있습니다.

(공식 문서) JLS 8.10은 record가 암묵적으로 final이고 직접 상위 클래스가 Record이며 extends 절이 없고, 본문에 비static 필드·인스턴스 초기화 블록·abstract 메서드를 둘 수 없다고 한다. 컴포넌트마다 private final 필드와 public 접근자가 생기고, equals·hashCode·toString이 컴포넌트 필드를 기준으로 암묵적으로 선언되며 기본형 컴포넌트는 래퍼 클래스의 compare로 비교한다(8.10.3). Record API 문서는 record를 얕게 불변인 투명한 운반체라고 부른다. 버전은 JEP 395에 따라 Java 14에서 프리뷰로 시작해 16에서 정식이 됐다.
(실험 확인) `record Point(int x, int y)`는 `Point[x=3, y=4]`로 출력되고 같은 값의 두 인스턴스가 `equals`·해시코드가 같았다. 리플렉션에서 `isRecord()`가 `true`, 상위 클래스가 `java.lang.Record`, 수정자가 `static final`, 필드가 `private final`이었다. record 본문에 `int y;`를 쓰면 `field declaration must be static`, `extends`를 쓰면 구문 오류로 컴파일되지 않았다. 인터페이스의 default 메서드는 record에서 그대로 호출됐다. 본문에 인스턴스 초기화 블록을 쓰면 `instance initializers not allowed in records`로 컴파일되지 않았고, `record R(double d)`에서 `NaN`끼리는 `equals`가 `true`(`==`는 `false`)이며 `0.0`과 `-0.0`은 `false`였다.
