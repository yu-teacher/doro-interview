**모범 답변 (30~60초)**
enum 상수는 암묵적인 static 필드로서 클래스가 초기화될 때 선언된 순서대로 가장 먼저 생성되고, 그 뒤에 나머지 static 필드 초기화와 static 블록이 소스 순서대로 실행됩니다. 그래서 상수의 생성자가 실행될 때는 아래쪽에 선언된 static 필드, 예를 들어 상수를 모아 두려는 Map이 아직 초기화되기 전입니다. 이런 실수를 막으려고 언어 규칙이 enum 생성자, 인스턴스 초기화 블록, 인스턴스 변수 초기화에서 상수 변수가 아닌 static 필드를 참조하는 것을 컴파일 오류로 정했습니다. 우회하려면 생성자에서 등록하지 말고 static 초기화 블록에서 values()를 돌며 Map에 넣으면 되고, 이 블록이 실행될 때는 이미 모든 상수가 만들어져 있습니다. 컴파일 타임 상수인 static final 기본형이나 문자열은 참조할 수 있습니다.

```java
enum Level {
    LOW(1), HIGH(10);
    private static final Map<Integer, Level> BY = new HashMap<>();
    static { for (Level l : values()) BY.put(l.w, l); }   // 상수가 모두 만들어진 뒤에 등록
    final int w;
    Level(int w) { this.w = w; /* BY.put(w, this); <- 컴파일 오류 */ }
    static Level of(int w) { return BY.get(w); }
}
```

(공식 문서) JLS 8.9.2는 enum 생성자·인스턴스 초기화 블록·인스턴스 변수 초기화에서 상수 변수가 아닌 static 필드를 참조하는 것이 컴파일 오류라고 밝힌다. 12.4.1은 static 초기화자와 클래스 변수 초기화자가 소스에 적힌 순서대로 실행된다고 하고, 8.9.1은 enum 본문에서 enum 상수 목록이 다른 선언보다 앞에 온다고 문법으로 정의한다.
(실험 확인) 위 `Level`을 처음 사용하는 시점에 상수 생성자가 선언 순서(`ctor 1`, `ctor 10`)대로 실행됐고 `of(10)`은 `HIGH`를 돌려줬다. 생성자에서 `Map`을 참조하면 `illegal reference to static field from initializer`, 상수가 아닌 `static int V`를 읽어도 같은 오류였고 `static final int K = 3`은 통과했다. `static final String T = new String("t")`처럼 `static final`이어도 상수 변수가 아니면 생성자에서 읽을 때 같은 오류였고, 인스턴스 초기화 블록에서 `V++`와 `L4.V`처럼 이름을 한정한 참조도 같은 오류였으며, `static final String K = "k"`와 `static final int N = 3`은 통과했다.
