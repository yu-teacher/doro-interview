**모범 답변 (30~60초)**
아닙니다. 런타임 객체를 기준으로 구현을 고르는 동적 선택은 인스턴스 메서드의 오버라이딩에만 적용됩니다. 하위 클래스가 상위 클래스와 같은 이름의 필드를 선언하면 오버라이딩이 아니라 숨김이라서, 필드 접근은 객체의 실제 클래스가 아니라 참조 변수의 선언 타입으로 정해지고, 객체 안에는 두 필드가 모두 존재해 super.name이나 캐스팅으로 구분해 접근합니다. static 메서드도 같은 시그니처로 다시 선언하면 숨김이라서, 인스턴스 참조로 호출해도 참조 타입의 static 메서드가 실행되고 참조가 null이어도 NullPointerException이 나지 않습니다. private 메서드는 상속되지 않아 오버라이딩 대상이 아니므로, 상위 클래스 메서드 안에서 부른 private 메서드는 항상 그 클래스의 것입니다.

```java
class S { String name = "S.field"; static String who() { return "S.static"; }
          String inst() { return "S.inst"; }
          private String priv() { return "S.priv"; }  String callPriv() { return priv(); } }
class T extends S { String name = "T.field"; static String who() { return "T.static"; }
          String inst() { return "T.inst"; }  String priv() { return "T.priv"; } }
S s = new T();
s.name;        // "S.field"   선언 타입 S 기준
((T) s).name;  // "T.field"
s.who();       // "S.static"  참조 타입 기준
s.inst();      // "T.inst"    런타임 클래스 기준(오버라이딩)
s.callPriv();  // "S.priv"    T.priv 는 오버라이딩이 아님
((S) null).who();   // "S.static", NPE 없음
```

(공식 문서) JLS 8.3은 필드 선언이 상위 타입의 같은 이름 필드를 숨기며(두 필드의 타입이 달라도 됨) 숨겨진 필드는 `super.`나 상위 타입으로의 캐스팅으로 접근한다고 한다. 8.4.8.2는 static 메서드가 상위의 메서드를 숨기며 숨겨진 static 메서드는 참조 타입으로 컴파일 때 정해진다고 하고 `Goodnight, Dick` 예제를 든다. 8.4.8.3은 private 메서드는 기술적 의미에서 오버라이드되거나 숨겨질 수 없고, 같은 시그니처의 하위 클래스 메서드는 반환 타입·throws와 무관하다고 한다. 15.11.1은 필드 접근이 선택자 식의 컴파일 타임 타입에서 필드를 찾는다고 하고, 15.12.4.1은 static 메서드 호출이면 대상 참조가 없고 선택자 식은 평가하되 결과를 버린다고 하며, 15.12.4.4는 private 메서드는 오버라이딩 없이 그 메서드가 호출된다고 한다. 12.5는 객체에 숨겨진 필드까지 모든 인스턴스 필드의 공간이 할당된다고 한다.
(실험 확인) 위 코드의 주석과 같은 결과가 나왔다. `null` 참조로 부른 static 메서드도 `S.static`을 돌려줬다. 하위 클래스가 `int` 필드를 `long` 필드로 숨기는 것도 컴파일됐고(`b.num`은 1, `d.num`은 2), `null` 변수로 읽은 static 필드도 NPE 없이 값을 돌려줬다.
