**모범 답변 (30~60초)**
자바는 객체를 만드는 중에도 오버라이드된 메서드를 하위 클래스 버전으로 호출합니다. 그래서 부모 생성자가 오버라이드 가능한 메서드를 부르면, 하위 클래스의 필드 초기화와 생성자 본문은 아직 실행되기 전이라 그 메서드가 필드의 기본값(null, 0)을 보게 됩니다. Java 24까지는(프리뷰 없이는) super()가 생성자의 첫 문장이어야 해서 피할 방법이 마땅치 않았지만, Java 25에서 정식이 된 유연한 생성자 본문(JEP 513)은 super() 앞에 문장을 쓸 수 있게 합니다. 이 구간에서 초기화자 없는 자기 필드에 값을 대입해 두면 부모 생성자가 부르는 메서드가 그 값을 보고, 인자 검증도 앞당길 수 있습니다. 다만 이 구간에서는 this를 읽거나 인스턴스 메서드를 부를 수 없고, 근본적으로는 생성자에서 오버라이드 가능한 메서드를 부르지 않는 것이 안전합니다.

```java
class Person {
    Person() { show(); }
    void show() { System.out.println("Person.show"); }
}
class Emp extends Person {
    String office = "A101";
    Emp() { super(); }                               // show() 시점에 office == null
    @Override void show() { System.out.println("office=" + office); }
}
class Emp2 extends Person {
    String office;
    Emp2(String o) { this.office = o; super(); }     // Java 25: super() 앞에서 자기 필드를 먼저 대입
    @Override void show() { System.out.println("office=" + office); }
}
```

(공식 문서) JLS 12.5는 오버라이드된 메서드가 객체 초기화 중에도 사용되며(C++과 달리 규칙이 바뀌지 않음), 생성자 본문의 prologue에서 필드를 대입하면 초기화되지 않은 상태의 노출을 피할 수 있다고 밝힌다. 8.8.7은 prologue(명시적 생성자 호출 앞의 문장)와 early construction context를 정의하고, 6.5.6.1은 그 문맥에서 인스턴스 필드를 쓸 수 있는 것은 초기화자 없는 필드에 대한 단순 대입뿐이라고 한다. JEP 513은 이 기능이 JDK 22(JEP 447), 23(JEP 482), 24(JEP 492)에서 프리뷰를 거쳐 25에서 변경 없이 정식이 됐고, prologue의 문장은 생성 중인 객체를 참조할 수 없지만 필드 초기화와 안전한 계산은 할 수 있다고 설명한다.
(실험 확인) JDK 25에서 `Emp`를 만들면 `Emp.show office=null n=0`이 출력돼 필드 초기화자(`"A101"`)가 아직 실행되기 전이었고, `super()` 앞에서 `this.office = o`를 한 `Emp2`는 `office=B7`을 봤다. `super()` 앞에서 `age < 18`이면 예외를 던지는 생성자(`Adult`)는 부모 생성자가 실행되기 전에 실패했다. prologue에서 `this.f`를 읽으면 `cannot reference this before supertype constructor has been called`, 인스턴스 메서드 `g()`를 부르면 `cannot reference g() before supertype constructor has been called`로 컴파일되지 않았다. 초기화자가 있는 필드(`n = 5`)는 `super()`가 끝난 뒤에야 5가 되어 부모 생성자가 부른 `show()`에는 `n=0`으로 보였다. prologue에서 초기화자가 있는 필드에 대입하면 `cannot assign initialized field 'f' before supertype constructor has been called`, 상위 클래스에서 상속한 필드에 대입하면 `cannot reference inh before supertype constructor has been called`, `Object o = this;`는 `cannot reference this before supertype constructor has been called`로 컴파일되지 않았다.
(보충) 이 질문의 결론(생성자에서 오버라이드 가능한 메서드를 부르지 말라)은 JLS의 경고 문장에서 이어지는 일반적인 설계 지침이다. 24까지는(프리뷰를 켜지 않으면) 생성자 호출이 첫 문장이어야 했다는 것은 JEP 513의 설명을 따른 것이며 이전 버전의 컴파일러로 확인하지 않았다.
