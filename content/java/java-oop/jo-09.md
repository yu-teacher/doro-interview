**모범 답변 (30~60초)**
default 메서드는 본문이 있는 인터페이스의 인스턴스 메서드로, 구현 클래스가 오버라이드하지 않으면 그 기본 구현을 물려받아서 기존 인터페이스에 메서드를 추가해도 구현 클래스가 깨지지 않게 해 줍니다. static 메서드는 인터페이스 이름으로만 호출하고 구현 클래스에 상속되지 않습니다. private 메서드는 Java 9부터 가능하고, default나 static 메서드의 중복 코드를 인터페이스 안에서만 공유할 때 씁니다. 서로 다른 인터페이스의 같은 시그니처 default 메서드를 한 클래스가 물려받으면 컴파일 오류이고, 그 클래스에서 메서드를 오버라이드한 뒤 A.super.hi()처럼 인터페이스를 지정해 호출해서 해결합니다. 슈퍼클래스의 구체 메서드가 있으면 그것이 default보다 우선합니다.

```java
interface A { default String hi() { return "A"; } }
interface B { default String hi() { return "B"; } }
class C implements A, B {
    public String hi() { return A.super.hi() + B.super.hi(); }   // "AB"
}
```

(공식 문서) JLS 9.4는 default 메서드가 구현 클래스에 기본 구현을 주는 인스턴스 메서드이고, private 인터페이스 메서드는 상속·오버라이드되지 않으며, 인터페이스는 static 메서드를 상속하지 않는다고 한다. 오버라이드된 default 메서드는 `인터페이스이름.super.메서드()`로 호출한다(9.4.1.1). 클래스가 override-equivalent한 default 메서드를 다른 상속 메서드와 함께 상속하면 컴파일 오류라는 것은 8.4.8.4에(인터페이스의 같은 규칙은 9.4.1.3, 새 메서드를 선언해 해결한다고 한다), 클래스가 상속한 구체 메서드가 default를 가려 그 상속을 막는다는 것과 클래스는 상위 인터페이스의 static 메서드를 상속하지 않는다는 것은 8.4.8에 있다. 9.4.1.2는 `Object`의 비private 메서드와 override-equivalent한 default 메서드를 선언할 수 없다고 한다. JEP 126(릴리스 8)은 가상 확장 메서드를 기존 인터페이스를 소스 호환되게 발전시키려는 기능으로 설명하고, JEP 213(릴리스 9)은 인터페이스에 private 메서드를 허용하는 변경이다.
(실험 확인) 위 `C`는 `AB`를 돌려줬고, `Base`(구체 `hi`)를 상속하며 `A`를 구현한 클래스는 `Base`를 돌려줬다. 충돌하는 두 default를 오버라이드 없이 구현하면 `types X and Y are incompatible`, `default boolean equals(Object)`는 `default method equals in interface Z overrides a member of java.lang.Object`, 구현 클래스 인스턴스로 인터페이스의 static 메서드를 부르면 `cannot find symbol`로 컴파일되지 않았다. 한 인터페이스가 다른 인터페이스를 상속하며 default를 재정의한 경우(`B extends A`, `implements A, B`)는 충돌이 아니라 더 구체적인 `B`의 것이 쓰였고, `X.super.hi()`에서 X가 직접 상위 인터페이스가 아니면 `not an enclosing class: X`, `private default`는 `illegal combination of modifiers`로 컴파일되지 않았다. private 인터페이스 메서드는 `javac --release 8`에서 `private interface methods are not supported in -source 8`로 거부되고 `--release 9`에서는 통과했다.
