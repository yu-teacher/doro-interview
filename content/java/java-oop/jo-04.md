**모범 답변 (30~60초)**
다형성은 상위 타입의 참조로 여러 하위 타입의 객체를 다루면서, 같은 메서드 호출이 객체의 실제 클래스에 따라 다르게 동작하는 성질입니다. 컴파일러는 참조 변수의 정적 타입을 보고 호출 가능한 메서드의 시그니처를 정하고, 인스턴스 메서드라면 실행할 때 객체의 런타임 클래스부터 거슬러 올라가며 오버라이딩된 구현을 찾는 동적 메서드 탐색을 합니다. 그래서 List<Shape>에 원과 사각형을 담고 area()를 부르면 각자의 구현이 실행됩니다. 상위 타입으로의 업캐스팅은 암묵적으로 되지만 다운캐스팅은 명시해야 하고 실제 타입이 아니면 ClassCastException이 나므로, 필요하면 instanceof로 먼저 확인합니다. 필드와 static 메서드에는 이런 동적 선택이 적용되지 않습니다.

(공식 문서) JLS 8.4.9가 컴파일 타임 시그니처 결정과 인스턴스 메서드의 런타임 동적 메서드 탐색을 설명하고, 15.12.4.4는 그 탐색이 대상 객체의 실제 런타임 클래스에서 시작해 오버라이딩하는 메서드를 찾을 때까지 상위 클래스로 올라간다고 하며 static 호출과 private 메서드에는 오버라이딩이 적용되지 않는다고 한다. 업캐스팅은 런타임 동작이 필요 없는 widening reference conversion(5.1.5)이라 대입 문맥에서 허용되고(5.2), 캐스트가 런타임에 허용되지 않으면 ClassCastException이 던져진다(15.16). 필드 숨김(8.3)과 static 메서드 숨김(8.4.8.2)은 동적 선택이 아니라는 내용은 jo-17에서 다룬다.
(실험 확인) `Shape`, `Circle`, `Sq`를 리스트에 담아 `area()`를 부르면 `3.0`, `4.0`, `0.0`처럼 각자의 구현이 실행됐고, `Sq` 객체를 `Circle`로 다운캐스팅하면 `ClassCastException`이 났으며, `instanceof Circle c` 패턴으로 확인한 뒤에는 `c.r()`을 안전하게 호출했다.
