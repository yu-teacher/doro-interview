**모범 답변 (30~60초)**
Java 16부터 obj instanceof String s처럼 타입 패턴을 쓰면 검사, 캐스팅, 변수 선언이 한 번에 되고, 패턴 변수는 매칭이 확실한 범위에서만 보이는 흐름 스코프를 가집니다. Java 21부터는 switch의 case에도 패턴과 when 가드를 쓸 수 있고 case null도 됩니다. 여러 case가 맞으면 위에서부터 먼저 맞는 것이 선택되고, 앞의 라벨이 뒤의 라벨을 가려 버리면 컴파일 오류입니다. 패턴을 쓰는 switch는 모든 입력을 다뤄야 하는 완전성 검사를 받아서, sealed 계층이면 하위 타입을 모두 적는 것으로 default를 대신할 수 있습니다. 기존 switch는 null을 주면 NullPointerException이지만 case null을 쓰면 직접 처리할 수 있습니다.

```java
static String d(Object o) {
    return switch (o) {
        case null                     -> "null!";
        case Integer i when i > 10    -> "big int " + i;   // 가드
        case Integer i                -> "int " + i;       // 가드 있는 라벨이 먼저
        case Pair(String x, Integer y) -> "pair " + x + y;  // 레코드 패턴(21)
        default                       -> "other";
    };
}
```

버전별 정리(Java 8에서는 `instanceof` 뒤에 캐스트를 따로 써야 했다):

| 기능 | 정식 버전 | 근거 |
|---|---|---|
| switch 표현식(화살표 case, yield) | 14 | JEP 361 |
| instanceof 패턴 | 16 | JEP 394 |
| switch 패턴 매칭, case null | 21 | JEP 441 |
| record 패턴(중첩 분해) | 21 | JEP 440 |
| 기본 타입 패턴(instanceof·switch) | 25에서는 프리뷰(3차) | JEP 507 |

(공식 문서) JEP 394는 패턴 변수가 매칭이 확실히 일어난 범위에서만 보이도록 하는 흐름 스코프를 설명한다. JEP 441은 먼저 나오는 맞는 라벨이 선택되고 앞 라벨이 뒤를 가리면 오류이며, 패턴·null 라벨을 쓰거나 선택자 타입이 레거시 타입이 아닌 switch는 완전해야 하고, sealed 계층의 permits 절로 완전성을 판단하며, 기존 switch는 null이면 NPE라고 설명한다. JLS 14.11.1.2는 선택자가 null이 아니면 적용되는 첫 번째 case 라벨을 고른다고 하고, 14.11.2는 Java 21에서 선택자 타입과 case null 제약이 완화됐으며 enhanced switch 문은 완전해야 한다고 밝힌다. 15.20.2는 instanceof의 패턴이 선택자 식의 타입에 적용 가능해야 한다고 하고(14.30.3: 타입에서 패턴 타입으로 검사 변환이 있으면 됨), 항상 성공하는 경우를 오류로 보는 규칙은 두지 않는다.
(실험 확인) 위 `d` 메서드는 `5`를 `int 5`, `50`을 `big int 50`, 레코드를 `pair k1`로 분기하고 `null`을 `null!`로 처리했다. `case CharSequence`가 `case String` 앞에 있으면 `this case label is dominated by a preceding case label`, 완전하지 않으면 `the switch expression does not cover all possible input values`로 컴파일되지 않았다. 레거시 형태의 `String` switch에 `null`을 주면 NPE였다. 패턴 변수는 `if (!(o instanceof String t)) return;` 뒤에서도 쓸 수 있었다. JEP 394는 16에서 `String` 타입 변수 `s`에 `s instanceof String t`처럼 항상 성공하는 패턴을 컴파일 오류로 정했다고 하는데, JDK 25에서는 그런 `instanceof`가 컴파일됐고 JLS 25의 15.20.2에도 그런 제한이 없다(바뀐 시점은 확인하지 않았다). `default`만 있고 `case null`이 없는 패턴 switch에 `null`을 주면 NPE였고(JEP 441: default는 null과 매치하지 않는다), 패턴이 있는 switch 문이 완전하지 않으면 `the switch statement does not cover all possible input values`로 컴파일되지 않았다. `case null, default`는 `case String s` 앞에 두면 dominated 오류였다.
