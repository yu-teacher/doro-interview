**모범 답변 (30~60초)**
오버로딩은 같은 이름에 매개변수 목록이 다른 메서드를 여러 개 두는 것이고, 어떤 메서드를 부를지는 인자의 컴파일 타임 타입을 보고 컴파일할 때 시그니처가 정해집니다. 오버라이딩은 하위 클래스가 상위 클래스의 인스턴스 메서드를 같은 시그니처로 다시 정의하는 것이고, 실제로 실행되는 구현은 객체의 런타임 클래스를 보고 실행 중에 찾습니다. 오버라이딩할 때 반환 타입을 하위 타입으로 좁히는 공변 반환은 되지만, 접근 범위를 좁히거나 더 많은 체크 예외를 던질 수는 없습니다. 실수로 오버로딩이 되는 것을 막으려고 @Override를 붙이고, static 메서드는 오버라이딩이 아니라 숨김입니다.

```java
class A { String f(Object o) { return "A.f(Object)"; } }
class B extends A {
    @Override String f(Object o) { return "B.f(Object)"; }   // 오버라이딩
    String f(String s) { return "B.f(String)"; }             // 오버로딩
}
A a = new B();  B b = new B();  Object o = "str";
a.f("s");   // B.f(Object)  정적 타입 A 에는 f(Object)뿐이므로 그 시그니처를 고르고, 실행은 B 의 구현
b.f("s");   // B.f(String)
b.f(o);     // B.f(Object)  인자의 정적 타입이 Object
```

(공식 문서) JLS 8.4.9는 메서드 호출 시 인자 개수와 컴파일 타임 타입으로 컴파일 때 시그니처를 정하고, 인스턴스 메서드면 실제 실행할 메서드는 런타임에 동적 메서드 탐색으로 정한다고 한다. 오버라이딩 규칙(8.4.8.1)과, 반환 타입은 return-type-substitutable이어야 하고 접근 범위가 같거나 넓어야 하며 상위 메서드보다 체크 예외를 더 많이 던질 수 없다는 요구(8.4.8.3)에 근거한다. 공변 반환은 Java SE 5.0부터 합법이라고 예제에 적혀 있다. static 메서드의 숨김은 8.4.8.2이고, `@Override`는 오버라이드하지 않는 메서드에 붙이면 컴파일 오류가 나게 해서 `equals(Foo)` 같은 의도치 않은 오버로딩을 잡는 용도라고 9.6.4.4가 설명한다.
(실험 확인) 위 코드의 출력이 주석과 같았다. `A.f`를 `public`에서 기본 접근으로 좁힌 하위 클래스는 `f() in Q cannot override f() in P`, 상위에 없는 `throws Exception`을 붙이면 `overridden method does not throw Exception`, 반환 타입을 `int`에서 `long`으로 바꾸면 `return type long is not compatible with int`, 상위에 없는 메서드에 `@Override`를 붙이면 `method does not override or implement a method from a supertype`, 인스턴스 메서드를 static으로 다시 선언하면 `overriding method is static`으로 컴파일되지 않았다.
