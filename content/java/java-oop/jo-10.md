**모범 답변 (30~60초)**
클래스 초기화는 인스턴스를 만들거나 static 메서드를 호출하거나 상수가 아닌 static 필드를 쓰는 것처럼 처음 능동적으로 쓰일 때 일어납니다. 이때 부모 클래스가 먼저 초기화되고, static 필드 초기화와 static 블록이 소스에 적힌 순서대로 실행됩니다. 객체를 만들 때는 먼저 모든 필드가 기본값으로 채워지고, 생성자가 부모 생성자 호출로 올라가서 부모부터 차례로, 각 클래스에서 super() 다음에 인스턴스 필드 초기화와 인스턴스 초기화 블록이 소스 순서로 실행되고 그 뒤에 생성자 본문이 실행됩니다. 결과적으로 부모 static, 자식 static, 부모 필드와 블록, 부모 생성자, 자식 필드와 블록, 자식 생성자 순서입니다.

```text
main start
Parent static            <- new Child() 로 Child 초기화 시작: 부모가 먼저
Child static
Parent field init        <- 객체 생성: 부모의 필드 초기화 -> 인스턴스 블록 -> 생성자
Parent instance block
Parent ctor
  Child.hook cf=0        <- 부모 생성자가 부른 오버라이드 메서드가 자식 필드의 기본값을 봄
Child field init
Child instance block
Child ctor
```

(공식 문서) JLS 12.4.1은 클래스가 초기화되는 조건(인스턴스 생성, 자신이 선언한 static 메서드 호출, static 필드 대입, 상수 변수가 아닌 static 필드 사용)과, 초기화 때 슈퍼클래스(그리고 default 메서드를 선언한 슈퍼인터페이스)가 먼저 초기화되며 static 필드 참조는 그 필드를 실제로 선언한 클래스만 초기화한다고 밝힌다. 12.4.2는 static 필드 초기화자와 static 초기화자를 소스 순서대로 한 블록처럼 실행한다고 한다. 12.5는 객체 생성 절차를 설명한다: 모든 필드를 기본값으로 채운 뒤, 생성자가 슈퍼클래스 생성자를 먼저 처리하고, 인스턴스 초기화자와 필드 초기화자를 소스 순서로 실행한 다음 생성자 본문의 나머지를 실행한다. Java 25판 JLS의 절차에는 super()/this() 앞의 prologue 단계가 포함돼 있다(jo-16).
(실험 확인) 위 출력이 그대로 나왔다(`Child.hook`이 부모 생성자 안에서 호출돼 `cf=0`을 본 줄 포함). `static final int CONST = 5`만 읽으면 `K init`이 출력되지 않았고, 자식 클래스 이름으로 부모의 static 변수를 읽으면 부모만 초기화됐다(`KSub init`은 출력되지 않았다). default 메서드가 있는 인터페이스 `I`와 없는 인터페이스 `J`를 구현한 클래스를 만들었을 때 `I init`만 출력됐다. `this(...)`로 다른 생성자에 위임하는 생성자를 거쳐 만들어도 인스턴스 초기화 블록은 한 번만 실행됐다.
