**모범 답변 (30~60초)**
orElse는 값을 인자로 받기 때문에 Optional에 값이 있어도 인자 표현식이 항상 먼저 평가됩니다. 그래서 대체값을 만드는 데 비용이나 부작용이 있다면 낭비가 되고, orElseGet은 Supplier를 받아 비어 있을 때만 호출하므로 이런 경우에 맞습니다. 이미 만들어 둔 상수라면 orElse로 충분합니다. 또 Optional.of(null)은 NullPointerException이고, null일 수 있는 값은 ofNullable로 감싸 빈 Optional로 만듭니다. map 함수가 null을 돌려주면 예외 없이 빈 Optional이 됩니다.

```java
static String sup() { System.out.println("fallback evaluated"); return "fb"; }
Optional.of("v").orElse(sup());        // 값이 있어도 "fallback evaluated" 출력
Optional.of("v").orElseGet(() -> sup());   // 출력 없음
Optional.of(null);                     // NullPointerException
Optional.of("a").map(x -> (String) null);  // Optional.empty
```

(공식 문서) Optional 문서가 orElse는 값이 없을 때 other를 돌려주고 orElseGet은 값이 없을 때 supplier의 결과를 돌려준다고 정의한다. of는 non-null 값만 받고 null이면 NullPointerException을 던지며, ofNullable은 null이면 빈 Optional을 돌려주고, map은 매핑 결과를 ofNullable처럼 감싸 null 결과면 빈 Optional을 돌려준다고 한다. 인자 표현식이 메서드 실행 전에 평가되는 것은 JLS 15.12.4가 메서드 호출의 두 번째 단계로 "인자 표현식 평가"를 규정한다(Run-Time Evaluation of Method Invocation).
(실험 확인) Java 25에서 위 네 줄의 동작(orElse에서만 `fallback evaluated` 출력, `of(null)`의 NPE, map의 null 결과가 `Optional.empty`)을 다시 확인했다. 비어 있는 Optional에서는 orElseGet도 supplier를 호출해 `fallback evaluated`를 출력했고, `flatMap`의 매퍼가 null을 돌려주면 NullPointerException이었다(Optional 문서의 flatMap Throws와 일치).
(보충) 이미 만들어 둔 값이면 orElse로 충분하다는 선택 기준은 공식 문서의 문장이 아니라 일반적인 판단이다.
