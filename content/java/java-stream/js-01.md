**모범 답변 (30~60초)**
함수형 인터페이스는 추상 메서드가 딱 하나인 인터페이스이고, 람다식과 메서드 참조는 그 인터페이스의 인스턴스를 간결하게 만드는 문법입니다. 람다식은 대입, 메서드 호출 인자, 캐스팅 문맥에서만 쓸 수 있고, 그 문맥이 요구하는 함수형 인터페이스가 대상 타입이 되어 추상 메서드의 시그니처에 맞춰 해석됩니다. default 메서드는 추상 메서드로 세지 않고, Object의 public 메서드를 다시 선언한 것도 세지 않습니다. @FunctionalInterface는 필수가 아니지만 붙여 두면 추상 메서드가 둘이 되는 순간 컴파일 오류로 알려 주는 안전장치가 됩니다.

```java
@FunctionalInterface
interface Calc {
    int apply(int a, int b);          // 유일한 추상 메서드
    boolean equals(Object o);         // Object 메서드 재선언: 개수에 포함되지 않음
    default Calc twice() { return (a, b) -> apply(apply(a, b), b); }
}
Calc add = (x, y) -> x + y;
add.twice().apply(1, 2);              // 5
```

(공식 문서) FunctionalInterface API 문서(Since 1.8)는 함수형 인터페이스가 개념적으로 추상 메서드를 정확히 하나 가지며, default 메서드와 Object의 public 메서드를 재선언한 추상 메서드는 개수에서 제외된다고 설명한다. 어노테이션이 없어도 정의를 만족하면 컴파일러가 함수형 인터페이스로 취급하고, 어노테이션이 붙었는데 조건을 어기면 컴파일러가 오류를 내야 한다고 한다. JLS 9.8은 정의(sealed로 선언되지 않은 인터페이스)와 Object 메서드 제외 이유를, JLS 15.27은 람다식이 대입·호출·캐스팅 문맥에서만 허용되는 poly expression이라는 점을, JLS 15.27.3은 대상 타입이 함수형 인터페이스여야 호환된다는 점을 밝힌다. 대표 인터페이스 모음은 java.util.function 패키지 문서에 있다.
(실험 확인) Java 25에서 위 코드가 컴파일·실행되어 `twice().apply(1, 2)`가 5였다. 추상 메서드가 둘인 인터페이스에 @FunctionalInterface를 붙이면 javac가 `Unexpected @FunctionalInterface annotation ... multiple non-overriding abstract methods`로 거부했고, 어노테이션 없이 추상 메서드가 하나뿐인 인터페이스는 람다로 대입됐다. sealed 인터페이스에 람다를 대입하면 `S is not a functional interface` 오류가 났다(JLS 9.8의 'sealed로 선언되지 않은'과 일치).
