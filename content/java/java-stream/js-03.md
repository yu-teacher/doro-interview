**모범 답변 (30~60초)**
자주 쓰는 형태는 네 가지입니다. Integer::parseInt처럼 static 메서드를 가리키는 것, pre::startsWith처럼 이미 정해진 객체의 인스턴스 메서드, String::equals처럼 타입 이름으로 쓰지만 첫 인자가 수신 객체가 되는 인스턴스 메서드, 그리고 ArrayList::new나 int[]::new 같은 생성자 참조입니다. 같은 `타입::이름` 모양이라도 static이면 인자가 전부 매개변수로, 인스턴스 메서드면 첫 인자가 수신 객체가 되어 매개변수가 하나 늘어난 람다로 풀립니다. 그래서 둘 다 해당하는 이름이면 컴파일러가 모호하다고 거부할 수 있습니다.

```java
Function<String,Integer>      f1 = Integer::parseInt;      // (s) -> Integer.parseInt(s)
BiFunction<String,String,Boolean> f2 = String::equals;     // (a, b) -> a.equals(b)
Supplier<List<String>>        f3 = ArrayList::new;         // () -> new ArrayList<>()
Function<Integer,int[]>       f4 = int[]::new;             // (n) -> new int[n]
String pre = "ab";
Predicate<String>             f5 = pre::startsWith;        // (s) -> pre.startsWith(s)
```

(공식 문서) JLS 15.13은 method reference의 문법 형태를 나열하고(위 네 가지 외에 super:: 형태도 있다), ReferenceType::Identifier 형태는 Identifier가 인스턴스 메서드를 가리키면 암묵 람다에 매개변수가 하나 더 있다고 설명한다. 한 타입이 두 종류의 적용 가능한 메서드를 모두 가질 수 있어 모호한 예(인스턴스 `size()`와 static `size(Object)`)도 직접 든다. 생성자 참조는 `ClassType::new`와 `ArrayType::new` 형태로 규정되어 있다.
(실험 확인) 위 다섯 줄이 컴파일되고 `f1.apply("12")`=12, `f2.apply("a","a")`=true, `f3.get()`=[], `f4.apply(3).length`=3, `f5.test("a")`=true, `f5.test("abc")`=false(`"ab".startsWith("abc")`)였다. JLS의 모호한 예를 그대로 컴파일하면 javac가 `reference to size is ambiguous`로 거부했다.
