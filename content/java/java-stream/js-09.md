**모범 답변 (30~60초)**
가장 큰 차이는 this입니다. 람다 본문에서 this와 super, 이름의 의미는 둘러싼 코드와 같아서 this가 바깥 클래스 인스턴스를 가리키지만, 익명 클래스 안의 this는 익명 클래스 자신입니다. 또 람다는 함수형 인터페이스 하나에만 쓸 수 있는 반면 익명 클래스는 추상 클래스나 메서드가 여럿인 인터페이스도 구현하고 필드를 가질 수 있습니다. 람다를 평가하면 새 인스턴스가 만들어질 수도, 기존 인스턴스가 재사용될 수도 있어서 ==나 synchronized 같은 identity 기반 연산에 기대면 안 됩니다.

```java
Runnable lam  = () -> System.out.println(this.getClass().getSimpleName());          // E1 (바깥 클래스)
Runnable anon = new Runnable() { public void run() { System.out.println(this.getClass().getName()); } }; // E1$1
```

(공식 문서) JLS 15.27.2는 람다 본문에서 이름과 this, super의 의미가 둘러싼 문맥과 같다고(익명 클래스 선언 안의 코드와 다르다고) 설명하고, JLS 15.8.3도 람다 본문의 this가 둘러싼 문맥의 this와 같다고 한다. JLS 15.27.3은 람다가 대상 타입이 함수형 인터페이스일 때만 호환된다고 하고, JLS 15.9.5는 익명 클래스가 지정한 슈퍼클래스나 슈퍼인터페이스를 기반으로 하며 클래스 본문에서 필드·메서드 등을 선언한다고 한다. JLS 15.27.4는 람다 평가 결과가 새 인스턴스일 수도 기존 인스턴스일 수도 있어 identity가 예측 불가하며 ==, 락, identityHashCode 결과가 구현마다, 심지어 같은 구현의 평가마다 다를 수 있다고 밝힌다.
(실험 확인) HotSpot(Corretto 25)에서 위 두 줄 구조는 각각 바깥 클래스 이름, `바깥클래스$1`을 출력했다. 같은 호출 위치에서 변수를 캡처하지 않는 람다는 매번 같은 인스턴스(`==`이 true)였고 지역 변수를 캡처하는 람다는 호출마다 다른 인스턴스(false)였으며, 람다 클래스는 isAnonymousClass()가 false이고 synthetic이었다. 필드(`cnt`)를 가진 추상 클래스의 익명 하위 클래스는 컴파일되고 `1 2`로 상태를 유지했다. 람다 identity 관련 관찰은 구현 동작이지 보장이 아니다.
