**모범 답변 (30~60초)**
reduce는 매 단계에서 새 값을 만들어 이전 값과 합치는 불변 값 중심의 접기이고, collect는 리스트나 StringBuilder 같은 가변 컨테이너 하나에 원소를 쌓는 가변 리듀스입니다. 문자열을 reduce로 이어 붙이면 단계마다 새 문자열을 복사해 문서가 말하듯 글자 수에 대해 제곱 시간이 걸릴 수 있습니다. collect는 컨테이너를 만드는 supplier, 원소를 넣는 accumulator, 병렬일 때 컨테이너를 합치는 combiner로 구성되고, 이를 묶어 재사용하게 만든 것이 Collector이며 joining 같은 것이 미리 만들어져 있습니다.

```java
Stream.of("a","b","c").collect(Collectors.joining(","));          // a,b,c
Stream.of("a","b").collect(StringBuilder::new, StringBuilder::append, StringBuilder::append); // ab
```

(공식 문서) 패키지 문서의 "Mutable reduction"이 가변 컨테이너(Collection, StringBuilder)에 누적하는 연산이며, reduce("", String::concat)는 동작하고 병렬도 되지만 문자열 복사가 많아 실행 시간이 글자 수에 대해 O(n^2)이라고 설명한다. collect의 세 함수(supplier, accumulator, combiner)와 이를 Collector로 묶는 이점(조합 가능성, Collectors의 미리 만들어진 팩토리)도 같은 절에 있다. Collector 문서는 supplier, accumulator, combiner에 선택적 finisher를 더한 네 함수로 지정된다고 한다. Collectors.joining은 입력 원소를 encounter order로 이어 붙이는 컬렉터다.
(실험 확인) 위 두 줄이 컴파일되고 각각 `a,b,c`, `ab`를 돌려줌을 다시 확인했다. `reduce("", String::concat)`도 `abc`로 동작했다. 성능 차이는 직접 측정하지 않았고 문서의 설명만 인용했다.
