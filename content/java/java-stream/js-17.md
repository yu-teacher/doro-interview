**모범 답변 (30~60초)**
항상 끝나지는 않습니다. 문서는 short-circuit 연산이 파이프라인에 있는 것이 무한 스트림 종료의 필요조건이지 충분조건이 아니라고 합니다. iterate나 generate에 limit을 붙이면 원하는 개수에서 끝나지만, sorted는 전체 입력을 봐야 결과를 낼 수 있어 뒤에 limit이 있어도 무한 스트림에서는 끝나지 않습니다. distinct 뒤의 limit은 서로 다른 값이 그 개수만큼 나올 때만 끝나고 값 종류가 모자라면 영원히 기다리며, filter 뒤 limit도 조건에 맞는 값이 모자라면 마찬가지입니다. 조건으로 끊으려면 Java 9의 takeWhile이나 hasNext 조건이 있는 iterate를 씁니다.

```java
Stream.iterate(1, x -> x * 2).limit(5).toList();                 // [1, 2, 4, 8, 16]
Stream.iterate(1, x -> x + 1).filter(x -> x % 7 == 0).limit(3).toList(); // [7, 14, 21]
Stream.iterate(1, x -> x < 100, x -> x * 3).toList();            // [1, 3, 9, 27, 81]  (Java 9)
Stream.iterate(1, x -> x + 1).takeWhile(x -> x < 4).toList();    // [1, 2, 3]          (Java 9)
Stream.iterate(1, x -> x + 1).sorted().limit(3).toList();        // 끝나지 않음
Stream.iterate(1, x -> x + 1).map(x -> x % 3).distinct().limit(5).toList(); // 끝나지 않음
Stream.iterate(1, x -> x + 1).map(x -> x % 5).distinct().limit(5).toList(); // [1, 2, 3, 4, 0] 끝남
```

(공식 문서) 패키지 문서의 "Stream operations and pipelines"가 short-circuit 연산이 있는 것은 무한 스트림이 유한 시간에 정상 종료하기 위한 필요조건이지만 충분조건은 아니라고 설명하고, 정렬은 모든 원소를 보기 전에는 결과를 낼 수 없다는 예를 든다. 상태 있는 연산(distinct, sorted)은 전체 입력을 처리해야 할 수도 있다고 쓰여 있다. takeWhile과 3인자 iterate는 Stream 문서의 Since 9이며, Java 8에는 없다.
(실험 확인) 위 처음 네 줄과 마지막 줄은 주석의 결과로 끝났다. `sorted().limit(3)`, 값이 3종류뿐인 `distinct().limit(5)`, 조건에 맞는 값이 없는 `filter(x -> x < 0).limit(1)`은 별도 데몬 스레드에서 실행해 1.5초 안에 끝나지 않았다. 반대로 `limit(5).sorted()`처럼 limit을 sorted 앞에 두면 끝났다. 이 확인은 영원히 끝나지 않음을 증명한 것은 아니며, 문서의 stateful 연산 설명과 필요조건 설명을 함께 근거로 한다.
