**모범 답변 (30~60초)**
ArrayList는 스레드 안전하지 않아서 여러 스레드가 동시에 add하면 데이터 레이스로 틀린 결과가 나옵니다. 실행해 보면 원소가 유실되거나 null이 끼어들거나 예외가 납니다. 문서도 이 코드를 부작용이 불필요한 예로 들어, 병렬로 돌리면 ArrayList의 스레드 비안전성 때문에 결과가 틀리고, 동기화를 넣으면 경합이 병렬의 이점을 없앤다고 설명합니다. 해법은 가변 공유 상태를 없애고 toList나 collect 같은 reduction으로 바꾸는 것입니다. 상태에 의존해 결과가 달라지는 stateful 람다도 같은 이유로 피해야 합니다.

```java
List<Integer> bad = new ArrayList<>();
IntStream.range(0, 100000).parallel().forEach(bad::add);
bad.size();   // 100000이 아님 (실험 환경에서 한 번 실행 시 15990, 매번 다름) 또는 예외

IntStream.range(0, 100000).parallel().boxed().toList().size();  // 100000
```

(공식 문서) 패키지 문서의 "Side-effects"가 forEach로 ArrayList에 add하는 예를 "불필요한 부작용"으로 지적하고, 병렬로 실행하면 ArrayList의 스레드 비안전성이 잘못된 결과를 낳고 필요한 동기화는 경합으로 병렬의 이점을 해친다며 toList로 바꾼 수정안을 보여 준다. "Stateless behaviors"에서는 stateful 람다의 결과가 비결정적일 수 있고, 공유 가변 상태는 동기화하지 않으면 데이터 레이스, 동기화하면 경합이라는 나쁜 선택지가 되므로 stateful 매개변수를 피하는 것이 최선이라고 한다. collect는 파티션마다 결과 컨테이너를 만들고 combiner로 합치는 방식이다(패키지 문서 "Mutable reduction").
(실험 확인) Java 25에서 위 코드를 40번 반복 실행했을 때 20번은 `size()`가 100000이 아니었고 19번은 ArrayIndexOutOfBoundsException이 발생했으며, 일부 실행에서는 리스트에 null 원소가 섞여 있었다(결과는 실행마다 다르다). `toList()`와 `collect(Collectors.toList())`로 바꾸면 20번 모두 100000이었다. 문서가 서술하는 것은 "잘못된 결과"이며 예외 종류는 구현 관찰이다.
