**모범 답변 (30~60초)**
안 됩니다. 스트림은 Iterator처럼 소스의 원소를 한 번만 지나가는 객체라서 종결 연산을 실행한 뒤 다시 연산을 붙이면 보통 IllegalStateException이 납니다. 종결 연산 뒤뿐 아니라 하나의 스트림에서 filter와 map을 갈라 붙이는 식의 포킹도 안 됩니다. 같은 데이터를 다시 순회해야 하면 소스에서 새 스트림을 만들면 되고, 반복해서 필요하면 Supplier로 스트림 생성을 감싸 둡니다. 다만 문서는 재사용을 항상 감지한다고는 약속하지 않으므로 예외가 안 나는 경우에 기대면 안 됩니다.

```java
Stream<String> r = list.stream();
r.count();
r.count();   // IllegalStateException: stream has already been operated upon or closed

Supplier<Stream<String>> s = () -> list.stream();
s.get().count(); s.get().toList();   // 매번 새 스트림
```

(공식 문서) Stream 인터페이스 문서가 스트림은 연산을 한 번만 해야 하며 같은 소스가 둘 이상의 파이프라인에 공급되는 "forked" 스트림이나 같은 스트림의 여러 번 순회는 허용되지 않는다고 하고, 재사용을 감지하면 IllegalStateException을 던질 수 있으나 일부 연산은 새 객체 대신 자기 자신을 반환하므로 모든 경우에 감지할 수는 없다고 설명한다. 닫힌(close) 스트림에 연산하면 IllegalStateException이라는 설명도 Stream 문서에 있다. 패키지 문서는 Iterator처럼 새 스트림을 만들어야 같은 원소를 다시 방문한다고 한다.
(실험 확인) Java 25에서 종결 연산 뒤 재호출, 같은 스트림에 중간 연산을 두 번 갈라 붙이기, close() 뒤 연산 모두 `stream has already been operated upon or closed` 메시지의 IllegalStateException이었다(메시지 문구는 구현 의존). 종결 연산을 끝낸 스트림에 `parallel()`을 호출하면 예외 없이 같은 객체가 반환됐고 그다음 연산에서야 예외가 났다.
(보충) Supplier로 스트림 생성을 감싸는 방식은 공식 문서의 문장이 아니라 "데이터 소스로 돌아가 새 스트림을 얻어야 한다"는 문서 설명을 적용한 일반적인 관용구다.
