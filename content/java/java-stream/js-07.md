**모범 답변 (30~60초)**
Stream.toList()는 Java 16에 추가됐고 수정할 수 없는 리스트를 돌려줘서 add하면 UnsupportedOperationException이 납니다. 반면 Collectors.toList()는 리스트의 타입, 가변성, 직렬화 가능 여부, 스레드 안전성을 문서가 전혀 보장하지 않습니다. 가변 리스트가 꼭 필요하면 toCollection으로 구현을 지정하는 것이 맞습니다. 그리고 forEach 안에서 외부 리스트에 add하는 방식은 부작용에 기대는 코드라, 병렬로 돌리면 스레드 안전하지 않은 ArrayList가 깨지기 때문에 문서도 toList나 reduction으로 바꾸라고 합니다.

```java
var t = Stream.of(1, 2).toList();
t.add(3);                                   // UnsupportedOperationException
var c = Stream.of(1, 2).collect(Collectors.toList());
c.add(3);                                   // HotSpot에서는 되지만 문서가 보장하지 않음
var m = Stream.of(1, 2).collect(Collectors.toCollection(ArrayList::new)); // 보장되는 가변 리스트
```

(공식 문서) Stream.toList는 Since 16이고, 반환 리스트는 수정할 수 없으며 mutator 호출은 항상 UnsupportedOperationException이라고 한다. 구현 타입과 직렬화 가능 여부의 보장이 없고 value-based일 수 있으며, 더 제어가 필요하면 Collectors.toCollection을 쓰라고 한다. Collectors.toList는 타입·가변성·직렬화·스레드 안전성 보장이 없어 더 제어하려면 toCollection을 쓰라고 한다. forEach로 ArrayList에 add하는 예를 "불필요한 부작용"으로 들어 병렬에서는 ArrayList의 스레드 비안전성 때문에 틀린 결과가 나오고 동기화는 경합을 낳는다고 하며 toList로 바꾼 수정안을 보여 주는 것은 java.util.stream 패키지 문서의 Side-effects 절이다.
(실험 확인) Java 25(Corretto)에서 `Stream.toList()` 결과는 add와 set 모두 UnsupportedOperationException이었고 `Stream.of(1, null).toList()`는 null을 허용했다. `Collectors.toList()` 결과는 이 JDK에서 `java.util.ArrayList`였으나 구현 의존이다.
