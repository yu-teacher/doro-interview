**모범 답변 (30~60초)**
키가 중복되면 수집하는 시점에 IllegalStateException이 던져집니다. 두 인자짜리 toMap은 중복을 허용하지 않기 때문입니다. 키가 겹칠 수 있다면 세 번째 인자로 merge 함수를 줘서 기존 값과 새 값을 어떻게 합칠지 정해야 하고, 맵 구현이나 순서가 필요하면 네 번째 인자로 LinkedHashMap 같은 mapFactory를 줍니다. 한 키에 값이 여러 개인 구조가 자연스러우면 groupingBy가 더 맞습니다. 참고로 값이 null이면 이 JDK에서는 NullPointerException이 났습니다.

```java
ps.stream().collect(Collectors.toMap(P::dept, P::name));
// IllegalStateException: Duplicate key dev (attempted merging values a and b)
ps.stream().collect(Collectors.toMap(P::dept, P::name, (x, y) -> x + "," + y));   // {ops=c, dev=a,b}
LinkedHashMap<String,Integer> lm = ps.stream()
    .collect(Collectors.toMap(P::dept, P::sal, Integer::sum, LinkedHashMap::new)); // {dev=30, ops=5}
```

(공식 문서) Collectors.toMap 문서가 매핑된 키가 중복되면(Object.equals 기준) 컬렉션 연산이 수행될 때 IllegalStateException이 던져진다고 하고, 중복 가능성이 있으면 BinaryOperator를 받는 toMap을 쓰라고 한다. 세 인자 형태에서는 같은 키의 값들이 merge 함수로 합쳐지며, 두 인자 형태는 무조건 던지는 merge 함수를 쓰는 것과 같다고 API Note에 적혀 있다. 반환 맵의 타입·가변성·직렬화·스레드 안전성은 보장하지 않고, 병렬에서는 toConcurrentMap이 나을 수 있다고 한다. 네 인자 toMap(Function, Function, BinaryOperator, Supplier)이 맵 공급자를 받는 형태다. null 값 처리는 toMap 문서에 규정이 없고 toUnmodifiableMap 문서만 null 키·값을 금지한다고 명시한다.
(실험 확인) 위 세 호출의 결과와 예외 메시지를 확인했다. 값이 null이면 두·세·네 인자 toMap 모두, 그리고 toUnmodifiableMap도 NullPointerException이었다. 반면 키가 null인 두 인자 toMap은 이 JDK에서 `{null=x}`로 통과했다. 이는 이 JDK에서의 관찰이며 toMap 문서에는 규정이 없다.
