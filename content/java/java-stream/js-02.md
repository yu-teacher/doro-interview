**모범 답변 (30~60초)**
java.util.function 패키지의 기본 모양 네 가지입니다. Function은 T를 받아 R을 돌려주는 변환이라 map에, Consumer는 값을 받기만 하고 돌려주지 않아 forEach에, Predicate는 boolean을 돌려주는 판정이라 filter에, Supplier는 인자 없이 값을 만들어 내서 지연 생성이나 orElseGet에 씁니다. 여기에 인자 두 개짜리 Bi 접두사가 있고, UnaryOperator는 Function을, BinaryOperator는 BiFunction을 상속합니다. IntFunction이나 ToIntFunction처럼 기본형에 특화된 변종은 박싱 없이 int 같은 기본형을 다루려고 씁니다.

```java
UnaryOperator<String> up = String::toUpperCase;
BinaryOperator<Integer> sum = Integer::sum;
Function<Integer, Integer> f =
    Function.<Integer>identity().andThen(x -> x + 1).compose((Integer x) -> x * 10);
f.apply(2);   // 21 : compose가 먼저(2*10), andThen이 나중(+1)
```

(공식 문서) java.util.function 패키지 문서가 기본 모양 네 가지(Function, Consumer, Predicate, Supplier), 인자 수를 바꾸는 Bi 접두사, 기본 모양을 확장한 UnaryOperator(Function 확장)와 BinaryOperator(BiFunction 확장), 기본형 특화 접두사(ToIntFunction, DoubleConsumer, ObjIntConsumer 등)의 명명 규칙을 설명한다. compose가 before를 먼저, andThen이 after를 나중에 적용한다는 것은 Function 문서에 있다. 각 인터페이스가 어느 메서드의 인자인지는 Stream(filter, map, forEach)과 Optional(orElseGet)의 시그니처에 근거한다.
(실험 확인) 위 코드를 Java 25에서 실행해 `f.apply(2)`가 21임을 확인했다. 리플렉션으로 UnaryOperator의 상위 인터페이스가 Function, BinaryOperator의 상위 인터페이스가 BiFunction임도 확인했다.
(보충) 기본형 특화 변종이 박싱 비용을 피하려는 것이라는 설명은 패키지 문서가 명시한 문장이 아니라 일반적인 설명이다. 문서는 명명 규칙만 서술한다.
