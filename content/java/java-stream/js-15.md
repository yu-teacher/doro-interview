**모범 답변 (30~60초)**
Optional은 '결과 없음'을 분명히 표현해야 하고 null을 쓰면 오류가 나기 쉬운 곳, 즉 메서드의 반환 타입으로 쓰라고 만든 것입니다. Optional 변수 자체가 null이면 안 됩니다. 쓸 때는 isPresent 후 get 대신 map, flatMap, filter로 이어 가다가 orElse, orElseGet, orElseThrow, ifPresentOrElse로 마무리합니다. 비어 있을 때 예외가 필요하면 Java 10부터 인자 없는 orElseThrow()가 있고, 문서는 get()의 권장 대체로 이것을 꼽습니다. Optional은 value-based 클래스라 동기화나 ==로 다루면 안 됩니다.

```java
Optional.of(3).filter(x -> x > 9).or(() -> Optional.of(0)).get();   // 0  (or: Java 9)
Optional.of(3).stream().toList();                                    // [3] (stream: Java 9)
Optional.of(Optional.of(1)).flatMap(x -> x);                         // Optional[1]
Optional.empty().get();           // NoSuchElementException: No value present
Optional.empty().orElseThrow();   // 같은 예외 (Java 10)
```

(공식 문서) Optional 클래스 문서의 API Note가 "주로 'no result'를 표현해야 하고 null을 쓰면 오류가 나기 쉬운 곳의 메서드 반환 타입용"이며 Optional 타입 변수는 절대 null이어서는 안 된다고 한다. get()의 API Note는 권장 대체가 orElseThrow()라고 하고, map 문서는 값 유무를 명시적으로 검사하지 않고 후처리하는 용도라고 설명한다. 클래스 설명은 Optional이 value-based이므로 동기화에 쓰면 안 되며 equal한 인스턴스는 교환 가능하게 다루라고 하고, Optional.empty() 문서는 empty()가 싱글턴이라는 보장이 없어 ==로 비교하지 말라고 한다. value-based 클래스의 정의는 Value-based Classes 문서에 있다. 메서드 도입 버전은 문서의 Since 표기로 확인했다(or·stream·ifPresentOrElse 9, orElseThrow() 10, isEmpty 11). Java 8에는 or·stream·ifPresentOrElse·인자 없는 orElseThrow()가 없다.
(실험 확인) 위 코드의 결과와 예외를 Java 25에서 다시 실행해 확인했다. `Optional.empty() == Optional.empty()`는 이 JDK에서 true였지만 `Optional.of(1) == Optional.of(1)`은 false여서 ==가 일관되지 않음을 보여 준다. `Stream<Optional<T>>`를 `flatMap(Optional::stream)`으로 펼치면 빈 것이 걸러져 `[1, 3]`이 됐다.
(보충) 필드, 메서드 매개변수, 컬렉션 원소에 Optional을 쓰지 말라는 것은 공식 문서가 아닌 일반적인 설계 지침이다. 문서는 "주로 반환 타입"이라고만 말한다.
