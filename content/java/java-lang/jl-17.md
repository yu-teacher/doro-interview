**모범 답변 (30~60초)**
복합 대입 연산자는 단순히 줄여 쓴 식이 아니라, 왼쪽 변수 타입 T로 형변환이 자동으로 들어간 식입니다. s += x는 s = (short)(s + x)와 같아서, 계산은 int로 승격되어 이루어지고 결과를 다시 short로 좁혀 담습니다. 그래서 컴파일 오류 없이 값이 잘려도 조용히 넘어갑니다. 반면 s = s + 1은 int 결과를 short에 대입하려다 손실 가능성 때문에 컴파일 오류가 납니다. byte에 += 300을 하거나 int에 += 3.9를 해도 마찬가지로 값이 조용히 변합니다.

```java
short s = 1;  s += 70000;      // 4465   ((short)(1 + 70000), 70001 - 65536 = 4465)
byte b = 10;  b += 300;        // 54
int  i = 5;   i += 3.9;        // 8      ((int)(5 + 3.9))
short c = a + b;               // error: possible lossy conversion from int to short (a, b가 short 변수일 때)
final short fa = 1, fb = 2;  short d = fa + fb;   // 컴파일됨: 상수 표현식이고 값이 short 범위
```

(공식 문서) JLS 15.26.2는 `E1 op= E2`가 `E1 = (T)((E1) op (E2))`와 같고(T는 E1의 타입, E1은 한 번만 평가), 예로 `short x = 3; x += 4.6;`이 x를 7로 만든다고 한다. JLS 5.1.3은 정수의 좁히는 변환이 하위 n비트만 남기고 버리며 부호가 달라질 수 있다고, 부동소수점에서 정수로는 0 방향으로 반올림한다고 한다. JLS 5.2는 대입 문맥에서 상수 표현식 값이 좁은 타입에 들어갈 수 있으면 좁히는 변환을 허용한다고 한다.
(실험 확인) 위 값들은 모두 주석과 같았고, 주석의 오류와 컴파일 성공도 javac 25로 확인했다.
