**모범 답변 (30~60초)**
String은 불변이라 연결할 때마다 새 객체가 만들어지고, StringBuilder는 내용을 직접 고치는 가변 문자열입니다. StringBuffer는 같은 API를 가지면서 스레드 안전하도록 동기화되는 쪽이고, StringBuilder는 동기화를 보장하지 않는 대신 한 스레드에서 쓸 때 대부분의 구현에서 더 빠르다며 문서가 우선 쓰기를 권합니다. 반복문 안에서 문자열을 계속 이어 붙이면 매번 새 String이 생기므로 StringBuilder를 쓰고, 한두 번 이어 붙이는 정도는 그냥 + 연산자로 충분합니다.

```java
String sum = "";
for (int k = 0; k < 3; k++) sum += k;   // 매번 새 String 생성
StringBuilder sb = new StringBuilder("a");
sb.append("b");                          // 같은 객체를 수정
```

(공식 문서) StringBuilder API는 "mutable sequence of characters"이며 StringBuffer와 호환되는 API에 동기화를 보장하지 않고, 단일 스레드에서 StringBuffer를 쓰던 자리에 대신 쓰도록 권장하며 대부분의 구현에서 더 빠르다고 한다. StringBuffer API는 thread-safe하며 메서드가 필요한 곳에서 동기화된다고 한다. JLS 15.18.1은 연결 결과가 상수 표현식이 아니면 새 String이 만들어지고, 구현은 중간 객체를 줄이기 위해 연결과 변환을 한 번에 할 수 있다고 한다. String API의 Implementation Note는 javac가 `+`를 JDK 버전에 따라 StringBuffer, StringBuilder, StringConcatFactory 중 하나로 구현할 수 있다고 한다.
(실험 확인) Corretto 25의 javac로 컴파일한 `"x"+a+b` 같은 연결은 `javap -c`에서 `StringBuilder` 호출이 아니라 `invokedynamic makeConcatWithConstants`로 나왔다. 같은 소스를 `--release 8`로 컴파일하면 `new StringBuilder`와 `append` 호출이, `--release 9`와 17로는 invokedynamic이 나왔다(javac 25의 대상 릴리스 옵션으로 확인한 것이며 JDK 8 자체를 돌려 본 것은 아니다).
(보충) 반복문 안의 `+=`는 매번 새 String을 만드니 StringBuilder를 쓰라는 권장과 한두 번 이으면 `+`로 충분하다는 기준은 널리 쓰이는 실무 지침이고, 문서가 횟수 기준을 정하지는 않는다.
