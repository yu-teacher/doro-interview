**모범 답변 (30~60초)**
오토박싱은 int 같은 기본 타입 값을 Integer 같은 래퍼 객체로, 언박싱은 반대로 컴파일러가 자동으로 변환해 주는 기능입니다. 함정은 래퍼가 null일 때 언박싱하면 NullPointerException이 난다는 점입니다. 예를 들어 맵에 없는 키를 get하면 null이 반환되는데 int 변수에 바로 받으면 NPE가 납니다. 또 List<Integer>의 remove는 int를 받는 인덱스 버전과 Object를 받는 값 버전이 있는데, 박싱 없이 적용되는 메서드를 먼저 고르므로 int 값을 넘기면 인덱스 삭제로 갑니다. 값을 지우려면 Integer.valueOf로 감싸야 합니다.

```java
Map<String,Integer> m = new HashMap<>();
int c = m.get("k");                 // NullPointerException
List<Integer> li = new ArrayList<>(List.of(10, 20, 30));
li.remove(1);                        // [10, 30]  (인덱스 1 삭제)
li.remove(Integer.valueOf(10));      // [30]      (값 10 삭제)
```

(공식 문서) JLS 5.1.7과 5.1.8은 박싱과 언박싱 변환을 정의하며, 언박싱할 참조가 null이면 NullPointerException을 던진다고 명시한다. JLS 5.2와 5.3은 대입 문맥과 호출 문맥에서 박싱 변환을 허용한다고 한다. Map.get API는 매핑이 없으면 null을 돌려준다고 하고, List API는 `remove(int index)`와 `remove(Object o)`를 따로 정의한다. JLS 15.12.2는 메서드 선택을 박싱·언박싱을 허용하지 않는 1단계로 먼저 하고, 적용되는 메서드가 없을 때만 박싱을 허용하는 2단계로 넘어간다고 한다.
(실험 확인) 위 코드를 실행하면 `Integer nul = null; int z = nul;`과 `int c = m.get("k")` 모두 NPE가 났고, 두 `remove` 호출의 결과는 주석과 같았다.
