**모범 답변 (30~60초)**
String은 한 번 만들어지면 내용을 바꿀 수 없다는 뜻입니다. toUpperCase나 replace 같은 메서드도 원본을 고치지 않고 결과를 String으로 돌려줍니다(바뀐 것이 없으면 같은 객체를 돌려줄 수도 있습니다). 클래스가 final이라 하위 클래스로 이 성질을 깨뜨릴 수도 없습니다. API 문서는 불변이기 때문에 String을 공유할 수 있다고 설명하고, 같은 내용의 리터럴이 하나의 인스턴스를 가리키는 것도 이 성질과 맞물려 있습니다. 값을 바꾸고 싶으면 StringBuilder처럼 가변 문자열 클래스를 써야 합니다.

```java
String t = "abc"; String u = t.toUpperCase();
System.out.println(t + " " + u);   // abc ABC
```

(공식 문서) String API 문서는 문자열이 상수이고 생성 후 값을 바꿀 수 없으며, 불변이라서 공유할 수 있다고 밝히고, 클래스는 `public final class String`으로 선언되어 있다. 같은 문서는 가변 문자열을 string buffer가 지원한다고 쓰고, StringBuilder API는 이를 mutable sequence of characters라고 소개한다. JLS 3.10.5는 문자열 리터럴이 항상 같은 String 인스턴스를 가리키며 상수 표현식의 값도 intern된다고 한다.
(실험 확인) 위 코드는 `abc ABC`를 출력해 원본이 바뀌지 않음을 확인했다. `String.class`의 modifier는 public final이었다. `"abc".replace('a','z')`는 새 문자열을 돌려줬지만 일치하는 문자가 없는 `replace('q','z')`는 원본과 같은 객체(`==` true)를 돌려줘서, 메서드가 항상 새 객체를 만든다고는 쓰지 않았다.
(보충) 불변이라서 내용 기반의 `hashCode`가 변하지 않으므로 해시 키로 쓰기에 안전하다는 점, 스레드 간에 동기화 없이 공유할 수 있다는 점, 리터럴 공유가 불변성 덕분에 안전하다는 점은 불변성에서 따라 나오는 일반적인 설명이고 문서가 직접 그렇게 서술하지는 않는다.
