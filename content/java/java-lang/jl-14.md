**모범 답변 (30~60초)**
finally 블록은 try 블록이나 catch 블록이 어떤 식으로 끝나든 그 뒤에 실행됩니다. 다만 System.exit으로 JVM이 종료되면 실행되지 않습니다. finally가 정상적으로 끝나면 try나 catch가 원래 가진 결과, 즉 return 값이나 던진 예외가 그대로 유지됩니다. 하지만 finally 안에서 return하거나 예외를 던지면 갑작스러운 종료의 이유가 finally 쪽으로 바뀌어, try에서 반환하려던 값이나 던져진 예외를 덮어씁니다. 그래서 finally에서 return을 쓰면 예외가 사라질 수 있어 피해야 합니다.

```java
static int f1() { try { return 1; } finally { System.out.print("[fin]"); } }   // [fin]1
static int f2() { try { return 1; } finally { return 2; } }                      // 2
static void f3() { try { throw new RuntimeException("try-ex"); }
                   finally { throw new IllegalStateException("finally-ex"); } }  // finally-ex 가 전파
```

(공식 문서) JLS 14.20은 finally 절이 try 블록과 실행될 수 있는 catch 블록 뒤에, 제어가 어떻게 벗어나든 실행됨을 보장한다고 하고, 14.20.2는 finally 블록이 정상 완료하면 try 문은 원래 이유로 완료하고, finally가 이유 S로 갑작스럽게 완료하면 try 문도 S로 완료하며 원래 이유나 던져진 값은 버려진다고 정의한다. 14.17은 return 전에 감싸는 try의 finally가 실행되고, finally의 갑작스러운 완료가 return의 제어 이동을 방해할 수 있다고 한다. Runtime API는 JVM이 종료되면 finally 절이 실행되지 않는다고 하고, `Runtime.exit`은 정상으로도 갑작스럽게도 완료하지 않는다고 한다.
(실험 확인) 위 세 메서드 결과는 `[fin]1`, `2`, `finally-ex`였다. javac 기본 설정에서는 f2·f3에 경고가 없었고 `-Xlint:finally`를 켜면 `finally clause cannot complete normally` 경고가 났다. `try { System.exit(0); } finally { print }`는 finally 출력 없이 종료 코드 0으로 끝났다(HotSpot).
