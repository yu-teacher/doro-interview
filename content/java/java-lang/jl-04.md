**모범 답변 (30~60초)**
==는 기본 타입에서는 값을 비교하고, 참조 타입에서는 두 변수가 같은 객체를 가리키는지, 즉 동일성을 비교합니다. equals는 Object에 정의된 메서드이고, 기본 구현은 같은 객체일 때만 true라서 ==와 똑같이 동작합니다. 그래서 값이 같은지, 즉 논리적 동등성을 보고 싶은 클래스는 equals를 재정의해야 하고, String이나 Integer 같은 표준 클래스는 이미 내용을 비교하도록 재정의되어 있습니다. 문자열이나 래퍼 객체를 ==로 비교하면 풀이나 캐시 때문에 우연히 맞기도 하니 equals로 비교해야 합니다.

```java
String s1 = "hello", s3 = new String("hello");
s1 == s3        // false
s1.equals(s3)   // true
int[] a1 = {1}, a2 = {1};
a1.equals(a2)   // false (배열은 Object.equals 그대로)
Arrays.equals(a1, a2)  // true
```

(공식 문서) JLS 15.21.3은 참조 타입 피연산자의 `==`가 두 값이 모두 null이거나 같은 객체나 배열을 가리킬 때 true라고 정의한다. Object.equals API는 기본 구현이 가장 차별적인 동등 관계, 즉 `x == y`일 때만 true라고 하고, 재정의할 때 지켜야 할 반사·대칭·추이·일관성 규칙을 적고 있다. String.equals는 인자가 null이 아니고 같은 문자 시퀀스를 나타내는 String이면 true를 돌려주고, Integer.equals는 같은 int 값을 담은 Integer 객체일 때만 true라고 한다. JLS 15.21.1은 숫자 피연산자의 `==`가 이항 숫자 승격 후 값을 비교한다고 한다.
(실험 확인) 위 비교의 결과는 주석과 같았다. 같은 변수들로 `s1.equals(null)`이나 `"a".equals(ns)`처럼 null이 오른쪽에 와도 NPE 없이 false였고, `Objects.equals(null, null)`은 true였다.
