**모범 답변 (30~60초)**
try 블록이 끝나면 리소스는 선언한 순서의 반대로 자동 close됩니다. 리소스 타입은 AutoCloseable을 구현해야 합니다. try 블록에서 예외가 났는데 close에서도 예외가 나면, try 블록의 예외가 주 예외로 던져지고 close의 예외는 suppressed 예외로 붙어서 getSuppressed로 꺼낼 수 있습니다. 주 예외가 없을 때 close에서 난 예외는 그대로 던져집니다. 한 리소스의 close가 실패해도 나머지 리소스는 계속 닫습니다.

```java
try (R r1 = new R("r1"); R r2 = new R("r2")) {   // close()마다 IllegalStateException
    throw new RuntimeException("body-ex");
} catch (Exception e) {
    e.getSuppressed();  // [close-r2, close-r1]
}
// open r1, open r2, body, close r2, close r1 순으로 출력, e.getMessage()는 body-ex
```

(공식 문서) JLS 14.20.3은 리소스를 왼쪽에서 오른쪽으로 초기화하고 초기화의 역순으로 닫으며, 한 리소스를 닫다 난 예외가 다른 리소스를 닫는 것을 막지 않고, 앞서 초기화·try 블록·다른 리소스 닫기에서 예외가 이미 던져졌다면 이 예외는 suppressed 처리된다고 한다. Throwable API는 addSuppressed와 getSuppressed가 Since 1.7이라고 하고 getSuppressed는 보통 try-with-resources가 억제한 예외를 돌려준다고 하며, AutoCloseable API는 close가 InterruptedException을 던지면 suppressed될 때 문제가 되니 던지지 말라고 권한다.
(실험 확인) 위 코드의 출력과 suppressed 배열이 주석과 같았다. try 블록이 정상일 때 `close-q1` 예외는 그대로 전파되었고 suppressed는 0개였다. 두 리소스가 모두 close에서 실패하고 본문은 정상이면 먼저 닫힌 `close-s2`가 던져지고 `close-s1`이 suppressed로 붙었다. 두 번째 리소스 초기화가 실패하면 첫 번째 리소스는 닫혔고, null 리소스는 close 없이 통과했다. 버전: `javac --release 8`에서 기존 변수를 `try (c) { }`로 쓰면 `variables in try-with-resources are not supported in -source 8` 오류였고 `--release 9`는 컴파일됐다(javac 25의 대상 릴리스 옵션으로 확인).
