**모범 답변 (30~60초)**
텍스트 블록은 큰따옴표 세 개로 여는 여러 줄 문자열 리터럴로, 줄바꿈과 큰따옴표를 이스케이프 없이 쓸 수 있고 Java 15에서 정식 기능이 되었습니다. 컴파일러가 줄바꿈을 통일하고, 모든 줄에 공통인 부수적인 들여쓰기와 줄 끝 공백을 제거한 뒤 이스케이프를 해석합니다. 공통 들여쓰기 기준에는 닫는 구분자가 있는 줄의 들여쓰기도 포함되어, 닫는 구분자를 왼쪽으로 옮기면 그만큼 들여쓰기가 남습니다. 줄 끝에 역슬래시를 쓰면 줄바꿈이 사라지고, \s는 공백 하나로 줄 끝 공백이 지워지는 것을 막습니다. 결과는 평범한 String입니다.

```java
String tb = """
    Hello,
      "World" \
    joined
    end\s
    """;
// "Hello,\n  \"World\" joined\nend \n"  (tb == 위 문자열 리터럴 -> true)
// 닫는 구분자 줄이 본문보다 왼쪽에 있으면 그 줄이 기준이 되어 본문에 들여쓰기가 남는다
```

(공식 문서) JLS 3.10.6은 텍스트 블록이 줄바꿈을 정규화하고, String.stripIndent와 같은 방식으로 부수적 공백을 제거하며, 마지막으로 String.translateEscapes와 같은 방식으로 이스케이프를 해석한다고 설명하고, 텍스트 블록 값도 상수 표현식처럼 intern되어 항상 같은 인스턴스를 가리킨다고 한다. String.stripIndent API는 마지막 줄의 선행 공백은 비어 있어도 최소 들여쓰기 계산에 포함한다고 하고, translateEscapes API는 `\s`를 공백 한 칸으로, 줄바꿈 앞의 `\`를 연속(삭제)으로 번역한다고 한다. JEP 378은 텍스트 블록이 Java 15에서 정식 기능으로 전달되었다고 한다.
(실험 확인) 위 블록의 값은 주석의 문자열과 `==`로 true였다. 본문이 12칸이고 닫는 구분자 줄이 8칸이면 각 줄 앞에 공백 4칸이 남았고, 닫는 구분자를 마지막 본문 줄 끝에 붙이면 끝 줄바꿈이 없었으며, 줄 끝 공백은 제거되고 `\s`로 쓴 것만 남았다.
버전: JEP 378에 따르면 텍스트 블록은 JDK 13(JEP 355)과 14(JEP 368)에서 프리뷰였고 15에서 정식 기능이 되었으므로, 8과 11에서는 쓸 수 없고 15부터 정식으로 쓸 수 있다. `javac --release 14`로 컴파일하면 `text blocks are not supported in -source 14` 오류가, `--release 15`는 성공이었다.
(실험 확인) 텍스트 블록(`"""`)은 Corretto 8과 11.0.33에서 `unclosed string literal`로 컴파일되지 않았고 Corretto 17.0.21에서는 동작했다. Corretto 17 javac의 `--release 14`는 `text blocks are not supported in -source 14`, `--release 15`는 컴파일됐다(15에서 정식이라는 설명과 일치).
