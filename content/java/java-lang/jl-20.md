**모범 답변 (30~60초)**
자바의 정수 연산은 오버플로가 나도 예외 없이 결과의 하위 비트만 남기고 넘어갑니다. 그래서 Integer.MAX_VALUE에 1을 더하면 MIN_VALUE가 됩니다. int의 음수 쪽은 양수 쪽보다 하나 더 많아서 MIN_VALUE의 부호를 바꾼 양수가 int로 표현되지 않고, Math.abs와 단항 마이너스가 그 값을 그대로 돌려줍니다. 오버플로를 감지해야 할 때는 Math.addExact나 Math.absExact처럼 예외를 던지는 Exact 메서드를 씁니다. int끼리 곱한 결과를 long에 담는 경우도 곱셈이 먼저 int로 끝나므로 피연산자 한쪽을 long으로 바꿔야 합니다.

```java
Integer.MAX_VALUE + 1 == Integer.MIN_VALUE   // true
Math.abs(Integer.MIN_VALUE)                    // -2147483648
-Integer.MIN_VALUE == Integer.MIN_VALUE         // true
long big = Integer.MAX_VALUE * 2;              // -2
long ok  = Integer.MAX_VALUE * 2L;             // 4294967294
Math.absExact(Integer.MIN_VALUE)               // ArithmeticException: Overflow to represent absolute value of Integer.MIN_VALUE
Math.addExact(Integer.MAX_VALUE, 1)            // ArithmeticException: integer overflow
```

(공식 문서) JLS 4.2.2는 정수 연산자가 오버플로나 언더플로를 어떤 식으로도 알리지 않는다고 하고, 15.17.1은 정수 곱셈이 오버플로하면 결과가 충분히 큰 2의 보수 형식으로 표현한 수학적 곱의 하위 비트라고 하고, 그래서 부호가 수학적 결과와 다를 수 있다고 한다. Math.abs(int) API는 인자가 Integer.MIN_VALUE이면 결과가 같은 음수 값이고, 대신 absExact는 이 값에 ArithmeticException을 던진다고 밝힌다. Math는 addExact 등 오버플로 시 예외를 던지는 메서드를 제공하고, JLS 15.15.4는 최소 음수의 단항 마이너스가 같은 값이 되며 예외 없이 오버플로한다고 한다.
(실험 확인) 위 값과 예외 메시지는 모두 주석과 같았다. `Math.abs(Long.MIN_VALUE)`도 같은 음수였다.
버전: API 문서에 따르면 `Math.absExact`는 Java 15에서 추가되었고(`addExact`는 1.8), `javac --release 11`에서는 `absExact`가 `cannot find symbol` 오류였다.
