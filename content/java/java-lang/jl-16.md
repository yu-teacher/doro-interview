**모범 답변 (30~60초)**
var는 지역 변수 선언에서 컴파일러가 초기화 식으로 타입을 추론하게 하는 Java 10의 기능입니다. 동적 타이핑이 아니라 컴파일 시점에 타입이 정해지는 정적 타입이라서, 한 번 정해진 타입은 바뀌지 않습니다. 그래서 초기화 식이 반드시 있어야 하고, null이나 람다처럼 타입을 정할 수 없는 식, 배열 초기화식, 한 줄에 여러 변수 선언은 쓸 수 없습니다. var는 키워드가 아니라 예약된 타입 이름이라 변수 이름으로는 쓸 수 있습니다. 필드와 메서드 매개변수, 반환 타입에는 쓸 수 없고 람다 매개변수에는 쓸 수 있습니다.

```java
var list = new ArrayList<String>();   // ArrayList<String>
var n = 10;                            // int
var x;                                 // error: cannot use 'var' on variable without initializer
var y = null;                          // error: variable initializer is 'null'
```

(공식 문서) JLS 14.4는 var 선언에서 변수 타입이 초기화 식을 독립 식으로 보고 추론한 타입의 상향 투영이며, 선언자가 여러 개이거나 브래킷이 붙거나 초기화가 없거나 배열 초기화식이거나 자기 자신을 참조하면 오류, 초기화식이 null 타입이면 오류, 람다·메서드 참조도 오류라고 한다. JLS 3.9는 var가 TypeIdentifier가 아니며 지역 변수 선언(LocalVariableType)과 람다 매개변수(LambdaParameterType)에서만 contextual keyword로 인식된다고 한다. JEP 286은 var가 키워드가 아니라 reserved type name이라서 변수·메서드·패키지 이름으로 쓴 코드는 영향이 없고 클래스·인터페이스 이름으로 쓴 코드만 영향을 받는다고 하며, Java 10에 전달되었다고 한다.
(실험 확인) 위 `var x;`와 `var y = null;`은 javac 25에서 주석의 오류를 냈고, `var anon = new Object(){ int hidden = 42; }`는 `anon.hidden`을 쓸 수 있었다(익명 클래스 타입으로 추론). `var var = 1;`은 컴파일됐고 `class var {}`는 `'var' not allowed here` 오류였다. 필드·메서드 매개변수·반환 타입에 쓰면 `'var' is not allowed here`, `var a = {1,2}`·`var f = () -> 1`·`var g = String::length`는 `cannot infer type for local variable`, `var a=1, b=2`는 `'var' is not allowed in a compound declaration` 오류였고, `(var x, var y) -> x + y` 람다와 `for (var i=0;...)`는 컴파일·실행됐다. 버전: `javac --release 8`과 9에서는 `var x = 1;`이 `cannot find symbol` 오류였고 `--release 10`부터 컴파일됐다.
