**모범 답변 (30~60초)**
타입 소거는 컴파일러가 파라미터화된 타입의 타입 인자를 지우는 것입니다. List<String>은 런타임에 그냥 List로 취급되고, 타입 변수는 가장 왼쪽 경계의 타입으로 바뀝니다. 그래서 런타임에 완전히 남아 있는 reifiable 타입이 필요한 곳에 제약이 생깁니다. new T[3]처럼 제네릭 배열은 만들 수 없고, 한 클래스 안에서 소거 후 시그니처가 같은 List<String>과 List<Integer> 인자의 오버로딩은 충돌합니다. 원시 타입으로 잘못 넣으면 꺼내는 시점에 ClassCastException이 납니다. instanceof는 Java 15까지 reifiable 타입만 허용했고 16부터 안전한 검사는 허용하지만 Object를 List<String>으로 확인하는 건 여전히 막힙니다.

```java
List<String> ls = new ArrayList<>(); List<Integer> li = new ArrayList<>();
ls.getClass() == li.getClass();   // true
List raw = ls; raw.add(42);       // 컴파일 경고만, 실행됨
String x = ls.get(0);             // ClassCastException (꺼내서 String으로 쓰는 지점)
```

(공식 문서) JLS 4.6은 소거를 파라미터화된 타입 G<T1,...,Tn>을 G로, 타입 변수를 가장 왼쪽 경계의 소거로 바꾸는 매핑으로 정의한다. 4.7은 런타임에 완전히 쓸 수 있는 reifiable 타입의 목록(비제네릭 타입, 모든 인자가 무제한 와일드카드인 타입, 원시 타입, 기본 타입 등)을 준다. JLS 15.10.1은 배열 생성 표현식의 요소 타입이 reifiable이 아니면 컴파일 오류라고 하고, 10.5는 요소 타입이 reifiable이 아니면 JVM이 배열 저장 검사를 할 수 없기 때문이라고 설명한다. 8.4.8.3은 제네릭이 소거로 구현되므로 같은 클래스에 선언된 같은 이름의 메서드는 소거가 달라야 한다고 한다. 15.20.2는 instanceof의 피연산자 타입이 reifiable이어야 한다는 요구가 Java SE 16 이전에 있었고 16에서 완화되었으며, 지금은 검사된 캐스트(checked cast)가 가능해야 한다고 한다. 4.12.2는 raw 타입 연산으로 heap pollution이 생길 수 있고 그 결과 나중에 ClassCastException이 날 수 있다고 한다. JVM 사양 4.7.9는 제네릭 선언의 타입 변수·파라미터화 타입 정보를 Signature 속성에 저장한다고 하여, 리플렉션으로 선언의 제네릭 정보를 읽을 수 있는 근거가 된다.
(실험 확인) 위 코드의 `==`는 true였고 ClassCastException은 `get(0)` 줄에서 났다(리스트 크기는 1). javac 25는 `new T[3]`에 `generic array creation`, `o instanceof List<String>`에 `Object cannot be safely cast to List<String>`, `f(List<String>)`/`f(List<Integer>)` 오버로딩에 `name clash ... have the same erasure` 오류를 냈다. 리플렉션으로 `g(List<String>)` 메서드의 `toGenericString()`을 보면 `List<java.lang.String>`이 나왔다. `javac --release 15`에서는 `List<Integer> x`의 `x instanceof ArrayList<Integer>`가 `reifiable types in instanceof are not supported in -source 15` 오류였고 `--release 16`과 25에서는 컴파일됐다. 25에서 `Object o`의 `o instanceof List<String>`은 여전히 오류였다.
