**모범 답변 (30~60초)**
삼항 연산자의 결과 타입은 두 피연산자의 타입으로 정해지는데, 한쪽이 기본 타입 int이고 다른 쪽이 Integer이면 조건식의 타입은 int가 됩니다. 그러면 Integer 쪽이 선택될 때 언박싱이 일어나고, 값이 null이면 이 언박싱 시점에서 NullPointerException이 납니다. 결과를 담는 변수가 Integer여도 소용이 없습니다. 두 피연산자의 타입이 모두 Integer로 같으면 조건식 타입이 그대로 Integer라 언박싱이 없어 null이 그대로 나오므로, Integer.valueOf(1)로 맞춰 주면 피할 수 있습니다. 비슷하게 true ? 1 : 2.0은 이항 숫자 승격으로 1.0이 됩니다.

```java
Integer nul = null; boolean f = false;
Integer r  = f ? 1 : nul;                      // NullPointerException (조건식 타입 int)
Integer r2 = f ? Integer.valueOf(1) : nul;     // null (둘 다 Integer)
Object o2 = true ? 1 : 2.0;                    // 1.0 (Double)
```

(공식 문서) JLS 15.25는 두 피연산자가 모두 숫자로 변환 가능한 타입(Integer 포함)의 식이면 숫자 조건식이라고 분류한다. 15.25.2는 두 피연산자의 타입이 같으면 그 타입이, 한쪽이 기본 타입 T이고 다른 쪽이 T를 박싱한 타입이면 T가, 그 밖에는 숫자 승격(언박싱 포함)을 적용한 타입이 조건식의 타입이라고 한다. 언박싱 대상이 null이면 NPE라는 것은 JLS 5.1.8이 밝힌다.
(실험 확인) 위 세 줄은 각각 NPE, `r2=null`, `1.0`이었다(두 번째는 `Integer r2`를 출력). 이어서 `Integer r3 = f ? 1 : null;`(null 리터럴)은 NPE 없이 null, `int x = f ? one : nul;`(둘 다 Integer 변수, 대입 대상이 int)은 NPE, `true ? Integer.valueOf(1) : Double.valueOf(2.0)`은 1.0(Double), `true ? 1 : "s"`는 1(Integer)이었다.
(보충) 피연산자가 상수 표현식이거나 byte/short/char끼리일 때의 세부 타입 결정은 표가 복잡해서 실무에서는 두 피연산자 타입을 일치시키는 편이 안전하다.
