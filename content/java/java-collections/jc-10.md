**모범 답변 (30~60초)**
Object 문서의 계약상 equals가 같은 두 객체는 반드시 hashCode도 같아야 하고, equals 비교에 쓰이는 정보가 바뀌지 않는 한 같은 객체의 hashCode는 여러 번 불러도 같은 값이어야 합니다. 반대로 서로 다른 객체가 같은 hashCode를 가져도 규칙 위반은 아니지만 해시 테이블 성능이 떨어집니다. 그래서 equals에 쓰는 필드만으로 hashCode를 만들고, 간단하게는 Objects.hash를 쓸 수 있습니다. 또 Map 문서는 equals 비교에 영향을 주는 값이 키로 들어 있는 동안 바뀌면 맵 동작이 규정되지 않는다고 하므로, 키는 불변 객체로 쓰는 게 안전합니다.

(공식 문서) Object.hashCode 문서의 일반 계약과 `Objects.hash`가 단순한 해시 코드를 만드는 데 쓸 수 있다는 API Note, Map 문서의 "mutable objects as map keys" 주의에 근거한다. equals는 반사·대칭·추이·일관성과 `x.equals(null)`이 false여야 하는 규칙을 가진다.
(실험 확인) `id` 필드로 equals·hashCode를 구현한 키를 맵에 넣은 뒤 `id`를 1에서 2로 바꾸니, 같은 객체로 `get`해도 null, 원래 값(id=1)인 새 객체로 `get`해도 null, `containsKey`는 false이고 size는 여전히 1이었다. 항목이 맵에 남아 있지만 찾을 수 없게 된 것이다.
(보충) 찾을 수 없게 되는 이유는 바뀐 hashCode가 다른 버킷을 가리키고, 원래 버킷에서는 바뀐 키가 equals로 맞지 않기 때문이라는 일반적인 설명이며, 문서는 "동작이 규정되지 않는다"까지만 말한다. 키를 불변 객체로 쓰라는 결론도 이 경고에서 끌어낸 일반적인 권고다.
