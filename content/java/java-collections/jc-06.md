**모범 답변 (30~60초)**
Arrays.asList는 배열을 감싼 고정 크기 리스트라서, set으로 값을 바꿀 수 있고 그 변경이 원본 배열에도 반영되지만 크기를 바꾸는 add나 remove는 UnsupportedOperationException입니다. List.of는 Java 9부터 있는 불변 리스트로 요소 변경이 전부 막히고 null 요소를 허용하지 않습니다. new ArrayList<>(컬렉션)은 요소를 복사한 별도의 가변 리스트라 자유롭게 추가·삭제할 수 있고 원본과 독립적입니다. 수정이 필요하면 ArrayList, 읽기 전용 상수 목록이면 List.of를 씁니다.

(공식 문서) Arrays.asList 문서는 배열과 리스트가 서로의 변경을 보며, 크기를 바꾸는 메서드는 UnsupportedOperationException이라고 한다. List 문서는 List.of와 copyOf의 리스트가 불변이고 null을 허용하지 않으며 value-based라고 한다. 버전 차이: Java 8에서는 List.of가 없어 JEP 269의 동기 설명처럼 컬렉션을 만든 뒤 `Collections.unmodifiableXxx`로 감싸야 했고, 9부터 List.of(JEP 269), 10부터 List.copyOf(List 문서 Since 10)가 있다.
(실험 확인) `asList`의 `set` 후 원본 배열 첫 요소가 바뀌었고(반대로 배열을 바꾸면 리스트에도 보였다), `add`·`clear`·존재하는 요소의 `remove`는 UnsupportedOperationException이었다. 리스트에 없는 요소의 `remove`는 크기가 안 바뀌어서인지 예외 없이 false였다. `List.of("a", null)`은 NullPointerException이었다. 질의도 달라서 `List.of(...).contains(null)`은 NullPointerException, `Arrays.asList(...).contains(null)`은 정상 처리됐다(List 문서가 구현에 따라 예외일 수도 있다고 허용한다).
(실험 확인) Corretto 8(1.8.0_512)에서 `List.of("a")`는 `cannot find symbol ... method of(String)`로 컴파일되지 않았다. Corretto 11.0.33에서는 `List.of`와 `List.copyOf`가 동작했고(`[a]`), 같은 11의 `--release 9`에서 `List.of`는 컴파일됐지만 `List.copyOf`는 `cannot find symbol ... method copyOf(List<String>)`였다(10부터라는 설명과 일치).
