**모범 답변 (30~60초)**
HashMap은 해시 테이블 기반이라 get과 put이 해시가 잘 퍼지면 상수 시간이지만, 순회 순서는 보장하지 않고 시간이 지나며 바뀔 수도 있습니다. LinkedHashMap은 같은 해시 구조에 이중 연결 리스트를 더해 보통 삽입 순서대로 순회하고, 비용 증가는 조금입니다. TreeMap은 레드-블랙 트리라 키 정렬 순서로 순회하며 containsKey, get, put, remove가 log(n)으로 보장됩니다. EnumMap은 enum 키 전용으로 배열로 구현되어 enum 상수 선언 순서로 순회하고 기본 연산이 상수 시간입니다.

(공식 문서) HashMap은 순서 보장이 없고 null을 허용하며, LinkedHashMap은 이미 있는 키를 다시 put해도 순서가 바뀌지 않는다고 문서가 밝힌다(접근 순서 모드는 별도). TreeMap은 자연 순서나 Comparator로 정렬하고, EnumMap은 enum 하나의 상수만 키로 받으며 null 키는 불가이고 기본 연산이 상수 시간이다.
(실험 확인) `banana, apple, cherry` 순으로 넣고 `banana`를 다시 put한 뒤 LinkedHashMap은 `[banana, apple, cherry]`, TreeMap은 `[apple, banana, cherry]` 순이었다. EnumMap에 WED, MON 순으로 넣어도 `{MON=m, WED=w}`로 출력됐고, `put(null, ...)`은 NullPointerException, `containsKey(null)`은 false였다.
