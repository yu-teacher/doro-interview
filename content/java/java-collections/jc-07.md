**모범 답변 (30~60초)**
Queue는 처리 전 요소를 담는 컬렉션으로 대개 FIFO이며, 삽입·삭제·조회마다 실패하면 예외를 던지는 add, remove, element와 null이나 false를 돌려주는 offer, poll, peek 두 벌을 제공합니다. Deque는 양쪽 끝에서 넣고 뺄 수 있어서 큐로도 스택으로도 쓸 수 있습니다. 구현체로는 ArrayDeque를 먼저 고려합니다. 문서가 스택으로는 Stack보다, 큐로는 LinkedList보다 빠를 가능성이 높다고 하고, 레거시 Stack 대신 Deque를 쓰라고 권합니다. 단 ArrayDeque는 null 요소를 넣을 수 없습니다.

(공식 문서) Queue 문서의 표는 add·remove·element가 예외, offer·poll·peek가 특수 값(null/false)이라고 정리한다. Deque 문서는 큐로 쓸 때 add=addLast, offer=offerLast, remove=removeFirst, poll=pollFirst이고, 스택으로 쓸 때 push=addFirst, pop=removeFirst, peek=peekFirst이며 "legacy Stack class"보다 Deque를 쓰라고 한다. ArrayDeque 문서는 null 요소를 금지하고 스레드 안전하지 않다고 한다.
(실험 확인) `push(1); push(2); addLast(3)` 뒤 deque는 `[2, 1, 3]`, `pop()`은 2, `pollLast()`는 3이었다. 빈 LinkedList 큐에서 `poll()`은 null, `remove()`와 `element()`는 NoSuchElementException이었고, `ArrayDeque.add(null)`은 NullPointerException이었다.
