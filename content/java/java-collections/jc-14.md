**모범 답변 (30~60초)**
Java 21의 JEP 431이 정의된 순서(encounter order)를 갖는 컬렉션을 위해 SequencedCollection, SequencedSet, SequencedMap 인터페이스를 추가했습니다. 처음과 끝 요소를 getFirst, getLast, addFirst, removeLast 같은 통일된 이름의 메서드로 다루고, reversed()로 역순 뷰를 얻는 통일된 API가 핵심입니다. List, Deque, LinkedHashSet, LinkedHashMap, SortedSet 같은 순서 있는 타입이 구현하고, 순서가 없는 HashSet과 HashMap은 구현하지 않습니다. Java 17 이하에서는 리스트 마지막 요소를 list.get(list.size() - 1)로 꺼냈고 LinkedHashSet은 끝 요소를 얻으려면 전부 순회해야 했습니다.

| 대상 | 첫 요소(17 이하) | 마지막 요소(17 이하) | 21 이상 |
|---|---|---|---|
| List | `list.get(0)` | `list.get(list.size() - 1)` | `getFirst()` / `getLast()` |
| Deque | `getFirst()` | `getLast()` | 동일 |
| SortedSet | `first()` | `last()` | `getFirst()` / `getLast()` |
| LinkedHashSet | `iterator().next()` | 없음(전체 순회) | `getFirst()` / `getLast()` |

(공식 문서) SequencedCollection 문서는 Since 21이며 양 끝 추가·조회·삭제와 reversed()를 제공하고, reversed()는 첫 요소와 마지막 요소 개념이 뒤바뀐 뷰라고 한다. 위 표의 기존 방식 열은 JEP 431의 동기 설명에 근거한다. SequencedMap은 keySet·values·entrySet 뷰도 맵의 encounter order를 따른다고 한다. LinkedHashMap 문서는 putFirst, putLast로 기존 엔트리의 위치를 바꿀 수 있다고 한다.
(실험 확인) `[1,2,3]`에서 `getFirst()`=1, `getLast()`=3, `reversed()`=`[3, 2, 1]`이었고 `reversed()`에 `add(0)`을 하면 원본 리스트 앞에 0이 들어갔다(뷰). 빈 리스트의 `getFirst()`는 NoSuchElementException이었다. `instanceof SequencedCollection`은 HashSet false, TreeSet·ArrayDeque true였고 `instanceof SequencedMap`은 HashMap false, TreeMap true였으며, TreeSet의 `addFirst`는 UnsupportedOperationException이었다. `LinkedHashMap.putFirst("z", 0)` 후 `{z=0, a=1, b=2}`였다.
