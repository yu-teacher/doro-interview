**모범 답변 (30~60초)**
HashMap은 null 키 하나와 null 값을 허용하고, LinkedHashMap, ArrayList, LinkedList도 null을 허용합니다. 반면 ConcurrentHashMap과 Hashtable은 null 키와 값 모두 허용하지 않고, Map.of와 List.of 같은 불변 팩토리, ArrayDeque, PriorityQueue도 null을 허용하지 않습니다. TreeMap과 TreeSet은 자연 순서를 쓸 때 null 비교에서 NullPointerException이 납니다. 조회도 구현마다 달라서 List.of(...).contains(null)은 NPE인데 Arrays.asList(...).contains(null)은 false입니다. HashMap에서 get이 null이면 키 없음인지 값이 null인지 containsKey로 구분해야 합니다.

(공식 문서) HashMap·LinkedHashMap·ArrayList·LinkedList 문서는 null 허용을, ConcurrentHashMap 문서는 "does not allow null to be used as a key or value"를, Hashtable 문서는 non-null만 가능하다는 점을, Map·List 문서는 팩토리 불변 컬렉션의 null 금지를, ArrayDeque와 PriorityQueue 문서는 null 요소 금지를 근거로 한다. Comparable 문서는 `e.compareTo(null)`이 NullPointerException을 던져야 한다고 하고, TreeMap의 put·get 문서는 키가 null이고 자연 순서이거나 비교자가 null을 허용하지 않으면 NullPointerException이라고 한다. Map 문서는 부적격 요소의 조회가 예외일 수도 false일 수도 있고 구현에 따른다고 한다.
(실험 확인) HashMap에서 `put(null, 1)`과 `put("k", null)`이 되고 `get("k")`는 null인데 `containsKey("k")`는 true였다. ConcurrentHashMap의 null 키·값 `put`과 `get(null)`, Hashtable의 null 값 `put`, `Map.of("a", null)`, `TreeMap.put(null, 1)`, `PriorityQueue.add(null)`, `ArrayDeque.add(null)`은 모두 NullPointerException이었다(Corretto 25.0.3). 반면 `Comparator.nullsFirst`를 준 TreeMap은 null 키를 받았다.
