**모범 답변 (30~60초)**
List는 순서가 있고 인덱스로 접근하며 중복을 허용하는 컬렉션이고, Set은 equals 기준으로 중복이 없는 컬렉션이며, Map은 키 하나에 값 하나를 대응시키는 구조로 같은 키를 두 번 가질 수 없습니다. Queue는 처리를 기다리는 요소를 담는 용도로 보통 FIFO이고, Deque는 양쪽 끝에서 넣고 뺄 수 있습니다. 순서대로 보관하고 인덱스로 읽으면 ArrayList, 중복 제거나 포함 여부 확인이 목적이면 HashSet, 키로 조회하면 HashMap, 정렬이 필요하면 TreeSet이나 TreeMap, 큐나 스택이면 ArrayDeque를 먼저 고려합니다.

(공식 문서) List 문서는 정수 인덱스 접근과 중복 허용(`e1.equals(e2)`인 쌍도 보통 허용)을, Set 문서는 `e1.equals(e2)`인 쌍이 없고 null은 최대 하나라는 점을, Map 문서는 중복 키 불가·키당 값 하나를 설명한다. Queue 문서는 요소를 "처리 전에 담아 두는" 용도이며 대개 FIFO이지만 우선순위 큐나 LIFO 큐 같은 예외가 있다고 하고, Deque 문서는 양 끝 삽입·삭제를 지원한다고 한다.
(실험 확인) `Collection.class.isAssignableFrom(Map.class)`는 false, Set은 true였다. 즉 Map은 Collection의 하위 타입이 아니라 별도 계층이다. LinkedList는 List이면서 Queue이고 Deque였다(Corretto 25.0.3).
(보충) 구현체 선택 요령(ArrayList 기본, 중복 제거는 HashSet, 정렬은 Tree 계열 등)은 일반적인 실무 가이드이며 문서가 순위를 매긴 것은 아니다.
