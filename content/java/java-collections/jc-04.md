**모범 답변 (30~60초)**
HashSet은 내부적으로 HashMap을 쓰는 해시 테이블 기반 Set이라, 요소의 hashCode로 버킷을 고르고 같은 버킷 안에서 equals로 동등 여부를 판단합니다. Object 문서의 계약상 equals가 같은 두 객체는 hashCode도 같아야 하는데, equals만 재정의하면 이 계약이 깨져서 논리적으로 같은 객체가 서로 다른 버킷에 들어가 중복으로 저장될 수 있습니다. 그래서 equals와 hashCode는 함께 재정의하는 것이 원칙이고, 이 둘을 직접 쓰기 번거로우면 record를 쓰는 방법도 있습니다.

(공식 문서) HashSet 문서는 "backed by a hash table (actually a HashMap instance)"라고 밝히고 순회 순서를 보장하지 않는다고 한다. Object 문서는 equals가 같으면 hashCode도 같아야 하며, equals를 재정의하면 일반적으로 hashCode도 재정의해야 한다고 한다. Map 문서는 구현체가 해시 코드를 먼저 비교해 equals 호출을 건너뛸 수 있다고 한다. JLS 8.10.3은 record가 컴포넌트 기준의 equals와 hashCode를 암묵적으로 갖는다고 정의한다.
(실험 확인) equals만 재정의한 클래스를 HashSet에 같은 값으로 두 번 넣으니 size가 2였고(1,000번 반복해도 모두 2), equals와 hashCode를 함께 재정의하면 1, record도 1이었다. hashCode를 상수로 고정하고 equals가 다른 값 둘을 넣으면 둘 다 들어갔다. 기본 hashCode는 객체마다 다른 값이 나오는 경향이라 결과가 이렇게 나오지만, 서로 다른 객체가 우연히 같은 해시를 가질 수도 있으므로 "항상 2"가 보장되는 것은 아니다.
(보충) 해시로 버킷을 고른 뒤 같은 버킷 안에서 equals로 비교한다는 흐름은 HashMap 문서의 버킷·해시 설명과 Map 문서의 equals 규정을 합친 일반적인 설명이며, 문서가 HashSet의 내부 절차를 단계별로 적은 것은 아니다.
