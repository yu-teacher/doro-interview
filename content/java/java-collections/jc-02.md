**모범 답변 (30~60초)**
ArrayList는 크기가 조절되는 배열 기반이라 get과 set 같은 인덱스 접근이 상수 시간이고, 끝에 추가하는 것도 분할 상환 상수 시간입니다. 중간에 넣거나 빼면 뒤쪽 요소를 옮겨야 해서 선형 시간입니다. LinkedList는 이중 연결 리스트라 인덱스로 접근하려면 앞이나 뒤에서 가까운 쪽부터 노드를 따라가야 합니다. 문서도 ArrayList의 상수 계수가 LinkedList보다 낮다고 하므로 특별한 이유가 없으면 ArrayList를 기본으로 쓰고, 양 끝 삽입·삭제가 핵심인 큐나 스택은 ArrayDeque를 먼저 고려합니다.

(공식 문서) ArrayList 문서는 size, get, set 등이 상수 시간, add는 분할 상환 상수 시간, 나머지는 대략 선형 시간이며 상수 계수가 LinkedList보다 낮다고 한다. LinkedList 문서는 인덱스 연산이 처음이나 끝 중 가까운 쪽부터 순회한다고 한다. List 문서는 구현을 모르면 인덱스로 훑기보다 이터레이터로 순회하라고 권한다. ArrayDeque 문서는 큐로는 LinkedList보다 빠를 가능성이 높다고 한다.
(실험 확인) 요소 50,000개에서 인덱스로 전부 읽기는 ArrayList 0.2~1.2ms, LinkedList 약 0.93~0.95초였고(이터레이터로 순회하면 LinkedList도 0.2~0.7ms), 맨 앞 50,000회 삽입은 ArrayList 65~75ms, LinkedList 0.4~1.7ms, ArrayDeque.addFirst 0.4~2.5ms였다. 노트북 한 대에서 3회 반복한 값이라 절대 수치는 의미 없고 경향만 본다(HotSpot, Corretto 25.0.3). `RandomAccess`는 ArrayList가 구현하고 LinkedList는 구현하지 않았다.
(보충) LinkedList의 중간 삽입이 O(1)이라는 설명은 이미 그 노드를 가리키는 이터레이터가 있을 때만 맞고, 위치를 찾는 데는 선형 시간이 든다. 또 노드 객체마다 참조 두 개가 붙어 메모리 부담이 크다는 점은 일반적인 설명이며 이번에 문서로 확인하지 않았다.
