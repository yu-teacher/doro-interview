**모범 답변 (30~60초)**
CopyOnWriteArrayList는 add나 set 같은 변경 때마다 내부 배열을 통째로 새로 복사하고, 이터레이터는 만들어진 시점의 배열을 참조하는 스냅샷 방식입니다. 그 배열은 이터레이터 수명 동안 바뀌지 않으므로 간섭이 없어 ConcurrentModificationException이 발생하지 않습니다. 대신 이터레이터는 이후의 추가·삭제·변경을 반영하지 않고, 이터레이터의 remove, set, add는 UnsupportedOperationException입니다. 변경마다 복사 비용이 들어서 쓰기가 잦으면 비효율적이므로 순회가 변경보다 훨씬 많을 때 쓸 만합니다.

(공식 문서) CopyOnWriteArrayList 문서는 모든 변경 연산이 새 배열 복사로 구현되고, 순회가 변경보다 훨씬 많을 때 대안보다 효율적일 수 있으며, 스냅샷 이터레이터는 CME를 던지지 않고 이후의 변경을 반영하지 않으며 remove·set·add는 UnsupportedOperationException이라고 한다. ConcurrentHashMap의 반복자도 CME는 없지만 "생성 시점 또는 그 이후"의 상태를 반영한다는 점에서 스냅샷과 구별된다.
(실험 확인) 요소 3개 리스트에서 이터레이터를 만든 뒤 4번째 요소를 add하고 순회하니 3개만 나왔고 리스트 size는 4였다. `Iterator.remove()`는 UnsupportedOperationException이었고, for-each 안에서 `cow.remove(i)`를 호출해도 예외 없이 끝나 리스트가 비었다(순회는 원래 스냅샷 기준). 이터레이터를 만든 뒤 `clear()`해도 그 이터레이터는 3개를 모두 돌려줬다. 요소 50,000개 add는 CopyOnWriteArrayList 145~219ms, ArrayList 0~1ms였다(노트북 한 대에서 2회, 경향만).
