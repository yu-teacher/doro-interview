**모범 답변 (30~60초)**
구조적 동시성은 여러 하위 작업을 한 블록 안에서 시작하고 그 블록을 벗어나기 전에 모두 끝나거나 취소되게 묶는 방식입니다. Java 25에서 StructuredTaskScope는 JEP 505로 다섯 번째 프리뷰이고 정식이 아니라서, 컴파일과 실행에 --enable-preview가 필요하며 API가 바뀔 수 있습니다. 25에서는 생성자 대신 open 팩토리 메서드로 열고, 기본 정책은 하나라도 실패하면 나머지를 취소하며, Joiner로 첫 성공 결과만 받는 등 완료 정책을 고릅니다. 반면 ScopedValue는 JEP 506으로 25에서 정식이 되어 프리뷰 옵션 없이 씁니다.

(공식 문서) JEP 505는 Release 25, Structured Concurrency (Fifth Preview)이고, `StructuredTaskScope`가 public 생성자 대신 정적 팩토리로 열리며 `--enable-preview`로 컴파일·실행해야 한다고 한다. JEP 525는 Release 26의 여섯 번째 프리뷰(Structured Concurrency (Sixth Preview))이고 일곱 번째 프리뷰로 JEP 533이 표시되어 있다. JEP 505의 History는 21(JEP 453)부터 프리뷰였다고 한다. Java SE 25 API 문서는 `StructuredTaskScope`를 프리뷰 API로 표시하고 프리뷰를 켜야만 쓸 수 있다고 한다. JEP 506은 Scoped Values(Release 25, 정식)이고 21(JEP 446)에서 프리뷰로 제안됐다고 하며 `ScopedValue` 문서는 Since 25이다.
(실험 확인) `--enable-preview` 없이 `StructuredTaskScope`를 쓰면 컴파일이 "is a preview API and is disabled by default" 오류로 실패했다. `--enable-preview`로는 `ScopedValue.where(...).run`으로 바인딩한 값을 `fork`한 하위 작업이 읽었고, 두 하위 작업 중 하나가 실패하자 1ms 안에 `join()`이 FailedException(원인 IllegalStateException)을 던지고 3초 걸리는 다른 작업은 기다리지 않았으며, `Joiner.anySuccessfulResultOrThrow()`는 빠른 결과 `fast`를 돌려줬다. `ScopedValue`만 쓰는 코드는 프리뷰 옵션 없이 실행됐다. Java 21(Temurin 21.0.12.1)과 Java 24(Corretto 24.0.2)에서는 `ScopedValue`와 `StructuredTaskScope` 모두 프리뷰 옵션 없이는 "is a preview API and is disabled by default" 오류로 컴파일되지 않았고, 21 형태의 `new StructuredTaskScope.ShutdownOnFailure()`는 21에서 `--enable-preview`로 컴파일·실행됐지만 25에서는 `ShutdownOnFailure` 클래스를 찾을 수 없었다(25는 `Joiner` 방식으로 바뀌었다).
(실험 확인) Corretto 8, 11.0.33, 17.0.21에서 `java.util.concurrent.StructuredTaskScope`와 `ScopedValue`는 `cannot find symbol ... class StructuredTaskScope`, `class ScopedValue`로 컴파일되지 않아 둘 다 없었다.
(보충) 26 이후 API는 JEP 525와 JEP 533의 제목과 상태만 확인했다.
