**모범 답변 (30~60초)**
Thread.State는 여섯 가지입니다. NEW는 만들었지만 start 전, RUNNABLE은 JVM 안에서 실행 중이거나 실행 가능한 상태, TERMINATED는 끝난 상태입니다. BLOCKED는 모니터 락, 즉 synchronized 진입을 기다리는 상태입니다. WAITING은 시간 제한 없이 다른 스레드의 동작을 기다리는 상태로 timeout 없는 Object.wait, join, LockSupport.park가 원인이고, TIMED_WAITING은 sleep이나 timeout을 준 wait, join처럼 대기 시간이 정해진 경우입니다. 이 상태는 JVM이 보는 상태이지 OS 스레드 상태가 아니고, 한 시점에는 하나의 상태만 가집니다.

(공식 문서) Thread.State 문서에 여섯 상태와 각 원인 메서드 목록이 있고, 이 상태가 OS 스레드 상태를 반영하지 않는 가상 머신 상태라고 밝힌다.
(실험 확인) `Thread.join()`을 기다리는 스레드는 WAITING, `join(5000)`은 TIMED_WAITING, `LockSupport.park()`는 WAITING, `parkNanos`는 TIMED_WAITING이었다. `getState()`로 NEW, `sleep` 중 TIMED_WAITING, `wait()` 중 WAITING, 다른 스레드가 쥔 `synchronized` 진입 대기 중 BLOCKED, `wait(5000)` 중 TIMED_WAITING, 바쁜 루프 중 RUNNABLE, 종료 후 TERMINATED를 각각 확인했다. 또 `ReentrantLock.lock()`을 기다리는 스레드는 BLOCKED가 아니라 WAITING이었다(문서의 BLOCKED는 모니터 락 대기에 한정되고, WAITING 원인 목록에는 `LockSupport.park`가 있다).
