**모범 답변 (30~60초)**
synchronized는 객체에 붙은 모니터를 잡는 문법입니다. 인스턴스 메서드는 호출된 객체 this의 모니터를, static 메서드는 그 클래스의 Class 객체 모니터를 잡고, 블록은 괄호에 쓴 객체의 모니터를 잡습니다. 그래서 같은 객체에 대한 두 synchronized 인스턴스 메서드는 서로 배제되지만, 서로 다른 인스턴스이거나 인스턴스 메서드와 static 메서드 사이에서는 락이 달라 동시에 실행됩니다. 같은 스레드는 이미 가진 모니터를 다시 잡을 수 있는 재진입이 되고, 잡은 횟수만큼 풀어야 완전히 해제됩니다. 락을 풀 때 쓴 값이 다음에 같은 락을 잡는 스레드에게 보이는 것도 보장됩니다.

(공식 문서) JLS 8.4.3.6이 synchronized 메서드는 실행 전에 모니터를 얻고 static이면 Class 객체, 인스턴스면 this의 모니터를 쓴다고 한다. JLS 17.1은 synchronized 문이 괄호 안 식이 가리키는 객체의 모니터를 잠근다고 하고, 한 스레드가 같은 모니터를 여러 번 잠글 수 있으며 unlock이 lock 한 번을 되돌린다고 하며, 17.4.5는 모니터 unlock이 이후의 같은 모니터 lock보다 먼저 일어난다(happens-before)고 한다.
(실험 확인) 각각 0.5초 걸리는 두 작업의 총 소요 시간이, static 메서드 대 인스턴스 메서드는 약 505ms(병렬), 서로 다른 두 인스턴스는 약 505ms(병렬), 같은 인스턴스는 약 1010ms(직렬), static 메서드 대 `synchronized (E04.class)` 블록은 약 1010ms(직렬)였다(재실행 값이며 실행마다 조금 다르다).
