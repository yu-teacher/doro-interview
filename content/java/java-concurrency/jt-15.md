**모범 답변 (30~60초)**
가상 스레드는 OS 스레드에 묶이지 않고 JVM이 소수의 플랫폼 스레드(캐리어) 위에 올렸다 내렸다 하며 실행하는 경량 스레드입니다. 블로킹 I/O 같은 대기에 들어가면 캐리어에서 내려와 그 캐리어를 다른 가상 스레드가 쓰므로, 대기 시간이 긴 작업을 수만 개 동시에 돌려도 부담이 적습니다. 공식 문서도 더 빠른 스레드가 아니라 더 높은 처리량을 위한 것이라고 하고, CPU 바운드 작업에는 맞지 않습니다. 요청 하나에 가상 스레드 하나를 만들고 풀로 재사용하지 않으며, 동시 실행 수를 제한해야 하면 Semaphore를 씁니다. Java 21에서 정식으로 확정됐습니다.

(공식 문서) Java 25 가이드의 가상 스레드 장이 위 개념, "not faster threads ... scale (higher throughput), not speed", 풀링하지 말고 Semaphore로 제한하라는 지침을 담고 있다. JEP 444는 21에서 최종 확정이고 19(JEP 425)와 20(JEP 436)에서 프리뷰였다고 하며, `Thread.ofVirtual()`은 Since 21로 표시되어 있다. `Executors.newVirtualThreadPerTaskExecutor()`는 작업마다 새 가상 스레드를 만든다.
(실험 확인) 1초 자는 작업 10,000개를 가상 스레드 실행기에 제출하자 약 1043ms에 끝났고, 200개 플랫폼 스레드 풀은 약 50187ms가 걸렸다. 가상 스레드는 `isVirtual()` true, daemon이고 `setDaemon(false)`는 IllegalArgumentException이었으며 이름은 빈 문자열이었다. CPU 바운드 작업(코어 15개, 작업 60개)은 가상 스레드 약 392ms, 코어 수 풀 약 377ms로 차이가 없었다. 가상 스레드에서도 `ThreadLocal`이 동작했다. Java 21(Temurin 21.0.12.1)에서도 `Thread.ofVirtual()`이 프리뷰 옵션 없이 동작했다.
(실험 확인) Corretto 8, 11.0.33, 17.0.21에서 `Thread.ofVirtual()`은 `cannot find symbol ... method ofVirtual()`, `Executors.newVirtualThreadPerTaskExecutor()`는 `method newVirtualThreadPerTaskExecutor()`를 찾을 수 없어 컴파일되지 않았고, Corretto 21.0.13에서는 프리뷰 옵션 없이 컴파일·실행됐다.
(보충) 19·20이 프리뷰였다는 것은 JEP 444의 이력 설명을 따른 것이며, 19·20 JDK가 실험 환경에 없어 직접 확인하지 못했다.
