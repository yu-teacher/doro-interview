**모범 답변 (30~60초)**
AtomicInteger 같은 원자 클래스는 값을 volatile 접근 의미로 다루면서 compareAndSet 같은 읽기-수정-쓰기 연산을 제공합니다. compareAndSet은 현재 값이 기대한 값일 때만 새 값으로 바꾸고 성공 여부를 돌려주므로, 실패하면 다시 읽고 계산해 재시도하는 낙관적 루프를 돕니다. 락을 잡고 기다리지 않아서 락 프리 프로그래밍에 쓰입니다. 한계는 첫째, 단일 변수에만 원자적이라 두 변수의 불변식은 못 지키고 둘째, 경합이 심하면 재시도가 늘며 합계를 모으는 통계 용도라면 LongAdder가 낫고 셋째, 값이 A에서 B를 거쳐 다시 A가 되어도 성공해 버리는 ABA 문제가 있습니다.

(공식 문서) atomic 패키지 문서는 단일 변수에 대한 락 프리 스레드 안전 프로그래밍 도구 모음이라 소개하고 `compareAndSet`과 `getAndUpdate`를 설명한다. `LongAdder` 문서는 통계처럼 여러 스레드가 공통 합계를 갱신하는 용도에서 보통 `AtomicLong`보다 낫고(세밀한 동기화 제어용은 아니다) 경합이 높으면 처리량이 크게 높은 대신 공간을 더 쓴다고 하고, `AtomicInteger`의 `get`은 `VarHandle.getVolatile`, `compareAndSet`은 `VarHandle.compareAndSet`의 메모리 효과를 따르며 VarHandle 문서는 후자를 `setVolatile`의 메모리 의미라고 한다. `AtomicStampedReference`는 참조와 정수 스탬프를 함께 원자적으로 갱신한다고 한다.
(실험 확인) 4스레드가 각 250000번 증가시키자 일반 `int`는 605763(처음 실행에서는 394500), `AtomicInteger`와 `LongAdder`는 1000000이었다. `AtomicReference`는 A→B→A로 바뀐 뒤에도 `compareAndSet(A, C)`가 성공했지만, `AtomicStampedReference`는 오래된 스탬프로 시도하면 실패했다.
(보충) CAS가 CPU의 원자 명령으로 구현된다는 설명과 ABA 문제라는 이름은 문서가 아니라 일반 설명이다.
