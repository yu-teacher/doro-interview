**모범 답변 (30~60초)**
happens-before는 한 동작의 결과가 다른 동작에 보이고 그보다 앞서 정렬된다는 보장입니다. 두 스레드의 충돌하는 접근 사이에 이 관계가 없으면 데이터 레이스이고, 어떤 값을 볼지 보장되지 않습니다. 성립하는 대표 경우는 같은 스레드의 프로그램 순서, 모니터 unlock에서 이후 같은 모니터 lock, volatile 쓰기에서 이후 같은 필드 읽기, Thread.start 호출에서 시작된 스레드의 동작, 스레드의 모든 동작에서 그 스레드를 join으로 받은 쪽입니다. 이 관계는 이행적이라 연결할 수 있습니다. 다만 실제 실행 순서를 강제하는 것은 아니고, 결과가 합법적이면 재배치는 허용됩니다.

(공식 문서) JLS 17.4.5가 happens-before의 정의와 위 규칙들, 데이터 레이스의 정의, 그리고 happens-before가 실제 실행 순서를 의미하지는 않는다는 설명을 담고 있다. `java.util.concurrent` 패키지 문서는 이를 확장해 동시성 컬렉션에 넣기 전 동작이 꺼낸 뒤 동작보다 앞서고, `Executor`에 제출하기 전 동작이 실행 시작보다 앞선다고 정리한다.
(실험 확인) volatile 플래그로 일반 필드 값을 넘기는 시나리오를 20000번 반복해 오래된 값을 읽은 경우는 0번이었다. `join()` 뒤, `start()` 뒤, `synchronized` unlock에서 lock으로 넘어간 뒤에 기대한 값이 보였다. 오래된 값이 관찰되지 않았다는 것이 보장의 증명은 아니다.
