**모범 답변 (30~60초)**
자바에서 스레드 중단은 강제가 아니라 협력입니다. interrupt()는 대상 스레드의 인터럽트 상태를 세우거나, 그 스레드가 sleep, join, wait 같은 곳에서 블로킹 중이면 상태를 지우고 InterruptedException을 던지게 할 뿐입니다. 그래서 작업 코드가 주기적으로 isInterrupted()를 보거나 InterruptedException을 잡아 스스로 정리하고 끝내야 합니다. 예외를 잡으면 상태가 지워지므로, 호출자가 알 수 있게 예외를 다시 던지거나 Thread.currentThread().interrupt()로 상태를 복원해야 합니다. 스레드를 강제로 죽이던 stop()은 제거 예정으로 표시되어 있고, Java 25 문서 기준으로 호출하면 항상 UnsupportedOperationException이 납니다.

(공식 문서) Thread 문서의 `interrupt()` 설명이 위 동작(블로킹 메서드에서는 상태 해제와 InterruptedException, 그 외에는 상태 설정)을 정의하고, `interrupted()`는 상태를 읽고 지우며 `isInterrupted()`는 지우지 않는다고 한다. `stop()`은 "Deprecated, for removal"로 표시되어 있고 Java 25 문서에는 UnsupportedOperationException을 항상 던진다고 적혀 있으며, 대신 중단 신호용 변수를 두고 대기 중이면 `interrupt`를 쓰라고 안내한다.
(실험 확인) 바쁜 루프는 `isInterrupted()`가 true가 되어 끝났고(종료 시점에도 상태는 true), `sleep` 중 인터럽트되면 catch 안에서 상태가 false였다. `interrupt()`로 복원하면 true가 되고, `Thread.interrupted()`는 한 번 true를 돌려주고 두 번째는 false였다. start 전의 스레드를 인터럽트해도 상태가 true로 기록됐고(문서의 JDK 구현 노트와 일치), 인터럽트를 확인하지 않는 작업은 그대로 끝까지 실행됐다.
(보충) 예외를 잡았다면 다시 던지거나 `Thread.currentThread().interrupt()`로 상태를 복원하라는 처리 요령은 문서의 규정이 아니라 일반적인 관행이다.
