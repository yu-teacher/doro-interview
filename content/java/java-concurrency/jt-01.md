**모범 답변 (30~60초)**
프로세스는 운영체제가 자원과 주소 공간을 따로 배정해 주는 실행 단위이고, 스레드는 한 프로세스 안에서 실행 흐름을 나눈 단위라서 같은 프로세스의 스레드끼리는 메모리를 공유합니다. 자바에서는 JVM 하나가 보통 프로세스 하나이고 그 안에서 여러 스레드가 돕니다. JVM 사양상 pc 레지스터와 JVM 스택은 스레드마다 따로 만들어지고, 힙과 메서드 영역은 모든 스레드가 공유합니다. 그래서 지역 변수는 스레드끼리 간섭하지 않지만, 힙에 있는 객체를 여러 스레드가 함께 바꾸면 동기화가 필요해집니다. 프로세스 간 통신보다 스레드 간 공유가 쉬운 대신 경쟁 상태를 직접 책임져야 한다는 점이 핵심 차이입니다.

(공식 문서) JVM 사양 2.5.1~2.5.2절은 JVM 스레드마다 자기 pc 레지스터와 JVM 스택이 있다고 하고, 2.5.3~2.5.4절은 힙과 메서드 영역을 모든 JVM 스레드가 공유한다고 한다. JLS 17장 도입부는 스레드가 공유 주 메모리에 있는 값과 객체에 대해 독립적으로 코드를 실행한다고 설명하고, 17.4.1절은 필드와 배열 원소는 힙(공유) 메모리에 있고 지역 변수·메서드 매개변수는 스레드 사이에 공유되지 않는다고 한다.
(실험 확인) 별도 스레드가 쓴 배열 원소와 static 필드 값을, 그 스레드를 `join()`한 main 스레드가 읽어 확인했다(스레드 이름은 `main`과 `Thread-0`).
(보충) 프로세스가 자원과 주소 공간을 따로 배정받는 단위라는 설명, 그리고 JVM 하나가 보통 프로세스 하나로 실행된다는 설명은 자바 문서가 아니라 운영체제 일반 개념이다.
