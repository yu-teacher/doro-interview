**모범 답변 (30~60초)**
가장 기본은 Runnable을 Thread 생성자에 넘기는 것이고, Thread를 상속해 run을 오버라이드할 수도 있습니다. Java 21부터는 Thread.ofPlatform()과 Thread.ofVirtual() 빌더로 플랫폼 스레드와 가상 스레드를 이름 같은 속성과 함께 만들 수 있습니다. start()는 스레드를 스케줄링해 새 실행 흐름에서 run이 실행되게 하지만, run()을 직접 부르면 그냥 현재 스레드에서 메서드 하나가 호출될 뿐입니다. start()는 한 번만 호출할 수 있고, 이미 시작했거나 끝난 스레드에 다시 부르면 IllegalThreadStateException이 납니다.

(공식 문서) Thread 클래스 문서가 `start()`는 스레드를 스케줄링해 독립적으로 실행하게 하며 한 번만 시작할 수 있고 재시작은 불가능하다고 밝힌다. 플랫폼 스레드는 daemon 여부를 갖고(생성자나 빌더로 만든 플랫폼 스레드는 설정하지 않으면 부모 스레드의 daemon 상태를 물려받는다) 가상 스레드는 항상 daemon이며, 시작된 non-daemon 스레드가 모두 끝나야 JVM 종료 절차가 시작된다고 한다. `Thread.ofPlatform()`과 `Thread.ofVirtual()`은 Since 21로 표시되어 있다.
(실험 확인) `run()` 직접 호출은 `main` 스레드에서, `start()`는 `worker`에서 실행됐다. 두 번째 `start()`는 IllegalThreadStateException이었다. 빌더로 만든 플랫폼 스레드는 이름 `w-0`, 가상 스레드는 `v-0`이었고, 가상 스레드는 daemon, 플랫폼 스레드는 non-daemon이었다(부모인 `main`이 non-daemon이라 물려받은 값이다).
(실험 확인) Corretto 8, 11.0.33, 17.0.21에서 `Thread.ofPlatform()`과 `Thread.ofVirtual()`을 쓰면 `cannot find symbol ... method ofPlatform()`, `method ofVirtual()`로 컴파일되지 않았고, Corretto 21.0.13에서는 컴파일·실행됐다(이름 `w-0`, 가상 스레드 `isVirtual()` true). Corretto 8과 17에서 `new Thread(Runnable, name)`와 `ThreadFactory`로 만든 스레드는 정상 실행됐고(`w-0`, `f-0`), 끝난 스레드에 다시 `start()`하면 IllegalThreadStateException이었다.
