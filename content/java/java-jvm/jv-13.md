**모범 답변 (30~60초)**
상세 메시지로 어느 영역이 모자란지 구분합니다. Java heap space는 힙에 객체를 만들지 못한 경우로, 힙(-Xmx)이 작거나 참조 누수 때문입니다. GC overhead limit exceeded는 GC가 시간의 약 98%를 쓰면서 힙의 2%도 못 건지는 일이 연속될 때 나는데, java 문서는 Parallel GC가 던진다고 적습니다. Metaspace는 클래스 메타데이터가 MaxMetaspaceSize를 넘은 경우이고, Requested array size exceeds VM limit는 힙 여유와 상관없이 VM 한계를 넘는 배열을 요청한 경우입니다. 진단은 -XX:+HeapDumpOnOutOfMemoryError로 힙 덤프를 남기고 GC 로그와 라이브 셋 추이를 보며, 네이티브 메모리 부족이면 OS 도구와 NMT를 씁니다.

(공식 문서) 문제 해결 가이드의 OutOfMemoryError 절에 근거한다. 이 절은 상세 메시지를 Java heap space, GC overhead limit exceeded, Requested array size exceeds VM limit, Metaspace, Compressed class space, "request size bytes for reason. Out of swap space?", native method 메시지로 나누고 각 원인과 조치를 설명한다. Java heap space의 원인으로 설정 부족, 의도치 않은 참조 유지, 과도한 finalizer 사용(finalizer 스레드가 큐를 못 따라가는 경우)을 든다. GC overhead는 98%·2%·연속 5번 GC가 기준이며 `-XX:-UseGCOverheadLimit`로 끌 수 있다. `java` 도구 문서의 `-XX:+UseGCOverheadLimit` 항목은 이 정책으로 OutOfMemoryError를 던지는 것을 parallel GC라고 적는다.
(공식 문서) 네이티브 메모리 문제는 같은 장이 NMT(`-XX:NativeMemoryTracking=summary|detail`과 jcmd)로 JVM 내부 네이티브 할당을 추적하라고 하며, JNI 등 JVM 밖 할당은 추적하지 못하고 켜면 5~10% 정도 성능이 떨어질 수 있다고 한다.
(공식 문서) `java` 도구 문서에 따르면 `-XX:+HeapDumpOnOutOfMemoryError`는 기본이 꺼져 있고, 힙 고갈로 JVM이 던진 OutOfMemoryError에만 적용되며 Java 코드가 직접 던진 경우나 네이티브 스레드 생성 실패 같은 다른 자원 고갈에는 적용되지 않는다. 덤프 경로는 `-XX:HeapDumpPath`, 기본은 현재 디렉터리의 `java_pid<pid>.hprof`다.
(실험 확인) `-Xmx16m -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=...`로 힙을 채우자 `Dumping heap to ...x.hprof`와 `Heap dump file created [21359690 bytes ...]`가 찍혔고 파일이 만들어졌다. jv-07 실험에서 `Java heap space`, `Requested array size exceeds VM limit`, `Metaspace` 메시지를 재현했다.
(실험 확인) `GC overhead limit exceeded`는 힙(`-Xmx20m`)을 라이브 데이터 14MB로 거의 채운 뒤 HashMap에 계속 `put`하는 프로그램으로 확인했다(HotSpot, Corretto 25.0.3).

```text
-XX:+UseParallelGC                       -> GC overhead limit exceeded   (2/2회)
-XX:+UseParallelGC -XX:-UseGCOverheadLimit -> Java heap space
-XX:+UseG1GC (기본)                       -> Java heap space
-XX:+UseSerialGC  (-Xmx20m)               -> Java heap space
```

같은 프로그램이 G1과 Serial에서는 이 메시지가 나지 않았고, `-Xmx15m`·`-Xmx16m`에서는 Parallel도 `Java heap space`였다. 네이티브 메모리 부족 메시지는 재현하지 않았다.
