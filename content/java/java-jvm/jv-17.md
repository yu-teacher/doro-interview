**모범 답변 (30~60초)**
Class.forName(name)은 이 메서드를 호출한 클래스의 정의 로더로 클래스를 로드하고, 초기화까지 수행합니다. 사양상 forName(name)은 forName(name, true, 로더)와 같아서 static 초기화 블록이 그 자리에서 실행됩니다. Class.forName(name, false, loader)는 로더를 직접 지정하고 초기화를 하지 않습니다. ClassLoader.loadClass(name)는 클래스를 찾아 로딩만 하고 초기화는 처음 실제로 쓸 때까지 미룹니다. 못 찾으면 둘 다 ClassNotFoundException이고, forName은 초기화 중 예외가 나면 ExceptionInInitializerError도 던질 수 있습니다.

(공식 문서) Class API 문서는 `forName(String)`이 `Class.forName(className, true, currentLoader)`와 동등하다고 하고, `forName(name, initialize, loader)`는 `initialize`가 true이고 아직 초기화되지 않았을 때만 초기화하며 `loader`가 `null`이면 부트스트랩 로더를 쓴다고 한다. 던질 수 있는 예외로 LinkageError, ExceptionInInitializerError, ClassNotFoundException을 적는다.
(실험 확인) 같은 클래스 `Lazy`(static 초기화 블록에서 메시지 출력)로 확인했다(Corretto 25.0.3).

```text
loader.loadClass("Init$Lazy")                       -> 초기화 메시지 없음
Class.forName("Init$Lazy", false, loader)           -> 초기화 메시지 없음
Class.forName("Init$Lazy")                          -> "Lazy init" 출력
존재하지 않는 이름: 두 방식 모두 ClassNotFoundException
```

JLS 12.4.1절은 초기화가 일어나는 경우를 닫힌 목록으로 정하고 Class와 java.lang.reflect의 일부 리플렉션 메서드 호출을 그중 하나로 꼽는다. ClassLoader.loadClass 문서는 로딩 순서만 적고 초기화는 언급하지 않으며, 위 목록에도 loadClass는 없다.
(공식 문서) DriverManager API 문서는 초기화 때 `jdbc.drivers` 속성과 서비스 제공자 로딩 방식으로 사용 가능한 드라이버를 찾는다고 하고, 새로 로딩된 드라이버 클래스가 `registerDriver`를 호출해 스스로를 등록해야 한다고 적는다.
(보충) JDBC 드라이버 등록을 `Class.forName("...Driver")`로 하던 관행이 이 초기화 효과로 드라이버의 static 초기화를 실행시키려던 것이라는 연결은 위 문서가 직접 말하지 않는 일반적인 설명이다.
