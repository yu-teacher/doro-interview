**모범 답변 (30~60초)**
JLS 12.4.1에 따르면 클래스는 그 인스턴스를 만들 때, 그 클래스가 선언한 static 메서드를 호출할 때, 그 클래스가 선언한 static 필드에 대입하거나 상수 변수가 아닌 static 필드를 사용할 때 직전에 초기화됩니다. 그 밖의 경우에는 초기화되지 않습니다. 컴파일 타임 상수인 static final 값은 읽어도 초기화가 일어나지 않고, 서브클래스 이름으로 부모의 static 필드를 읽으면 필드를 선언한 부모만 초기화됩니다. 클래스가 초기화되면 부모 클래스가 먼저 초기화되고, Class.forName 같은 리플렉션 호출도 초기화를 유발합니다.

(공식 문서) JLS 12.4.1절에 근거한다. 이 절은 클래스를 초기화할 때 부모 클래스와 default 메서드를 선언한 상위 인터페이스가 먼저 초기화되고, 인터페이스 초기화가 상위 인터페이스를 초기화하지는 않는다고 한다. JVM 사양 5.5절은 초기화 중 예외가 나면 그 클래스가 오류 상태가 되고 이후 초기화 시도가 NoClassDefFoundError를 던진다고 한다.
(실험 확인) Java 25(Corretto 25.0.3)에서 다음을 확인했다. 각 줄에서 초기화 메시지가 찍혔는지가 결과다.

| 동작 | 초기화 발생 |
|---|---|
| `Child.pv`(부모가 선언한 static int, 자식 이름으로 접근) | 부모만 |
| `Consts.C`(`static final int`), `Consts.S`(`static final String`) | 안 함 |
| `Consts.BOXED`(`static final Integer`, 상수 변수가 아님) | 함 |
| `K.NC`(`static final int NC = Integer.parseInt("5")`, 상수 변수가 아님) | 함 |
| `Q.B`(`static final int B = A + 2`, A는 `static final int A = 1`, 상수식) | 안 함 |
| `C.sm()`(부모 P가 선언한 static 메서드를 자식 이름으로 호출) | 부모만 |
| 이미 부모가 초기화된 뒤의 `new C()` | 자식만 |
| `new Arr[1]`, `Arr.class` | 안 함 |
| `new Impl2()`(default 메서드 없는 인터페이스 구현) | 구현 클래스만 |
| `new Impl()`(default 메서드 있는 인터페이스 구현) | 인터페이스 먼저, 구현 클래스 나중 |
| `loadClass("...Lazy")`, `Class.forName("...Lazy", false, loader)` | 안 함 |
| `Class.forName("...Lazy")` | 함 |

(실험 확인) 정적 초기화에서 0으로 나누기가 나는 클래스를 두 번 접근하자 첫 번째는 ExceptionInInitializerError(원인 ArithmeticException), 두 번째는 NoClassDefFoundError(원인 ExceptionInInitializerError)였다.
(공식 문서) 버전. JLS 8판 12.4.1절에는 초기화 조건에 "최상위 클래스 안의 assert 문이 실행될 때"가 하나 더 있었고, JLS 9·11·17·21·25판에는 이 항목이 없다. 나머지 조건과 "그 밖에는 초기화되지 않는다"는 문장은 위 판들에서 같게 읽혔다(사양 문서를 비교한 것이며 각 버전 JVM에서 실행해 본 것은 아니다).
