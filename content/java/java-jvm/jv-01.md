**모범 답변 (30~60초)**
JVM 사양은 런타임 데이터 영역을 JVM 시작 때 만들어져 종료 때까지 가는 것과 스레드가 만들어질 때 함께 생기는 것으로 나눕니다. 스레드마다 따로 갖는 것은 실행 중인 명령의 주소를 가리키는 pc 레지스터, 메서드 호출 프레임을 쌓는 JVM 스택, 네이티브 메서드를 위한 네이티브 메서드 스택(이를 제공하는 구현에서)입니다. 모든 스레드가 공유하는 것은 객체와 배열이 할당되는 힙과, 클래스별 구조와 메서드 코드를 담는 메서드 영역이며, 클래스마다 있는 런타임 상수 풀은 이 메서드 영역에서 할당됩니다.

| 영역 | 범위 | 사양이 적은 용량 부족 예외 |
|---|---|---|
| pc 레지스터 | 스레드별 | 없음 |
| JVM 스택 | 스레드별 | StackOverflowError, 확장 실패 시 OutOfMemoryError |
| 네이티브 메서드 스택 | 스레드별(제공하는 구현만) | StackOverflowError, OutOfMemoryError |
| 힙 | 전체 공유 | OutOfMemoryError |
| 메서드 영역 | 전체 공유 | OutOfMemoryError |

(공식 문서) JVM 사양 2장 2.5절(Run-Time Data Areas)에 근거한다. 사양은 힙의 저장소를 가비지 컬렉터가 회수하고 객체를 명시적으로 해제하지 않는다고 하고, 힙·메서드 영역·스택이 고정 크기이거나 늘고 줄 수 있다고 하면서 구체적인 배치와 정책은 구현에 맡긴다. 메서드 영역은 논리적으로 힙의 일부이지만 단순한 구현은 이 영역을 회수하거나 압축하지 않아도 된다고 적는다.
(공식 문서) 2.5.1절은 현재 메서드가 네이티브면 pc 레지스터 값이 정의되지 않는다고 하고, 2.5.6절은 네이티브 메서드를 올리지 못하고 일반 스택에도 의존하지 않는 구현은 네이티브 메서드 스택을 제공하지 않아도 된다고 한다.
(공식 문서) 이 질문은 JVM 사양 Java SE 25판 기준이다. HotSpot이 메서드 영역을 실제로 어떻게 구현하는지(8의 PermGen에서 Metaspace로의 변화)는 jv-11에서 다룬다.
