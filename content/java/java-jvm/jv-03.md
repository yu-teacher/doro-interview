**모범 답변 (30~60초)**
크게 로딩, 링킹, 초기화 순서입니다. 로딩은 클래스 로더가 클래스 파일의 바이트를 찾아 Class를 만드는 단계입니다. 링킹은 세 부분으로 검증, 준비, 해석입니다. 검증은 바이트코드가 구조적으로 올바른지 확인하고, 준비는 static 필드를 만들고 기본값으로 채우며, 해석은 상수 풀의 기호 참조를 실제 참조로 바꿉니다. 마지막 초기화에서 static 필드 초기식과 static 블록이 실행됩니다. 사양은 해석 시점을 구현에 맡기지만 초기화 전에 검증과 준비가 끝나야 한다고 정합니다.

(공식 문서) JVM 사양 5장에 근거한다. 5.3절 로딩, 5.4절 링킹(검증 5.4.1, 준비 5.4.2, 해석 5.4.3), 5.5절 초기화다. 5.4절은 클래스가 완전히 로딩된 뒤에 링크되고, 완전히 검증·준비된 뒤에 초기화된다는 속성을 유지하는 한 링크 시점은 구현이 정할 수 있다고 한다(필요할 때 하나씩 해석하는 lazy, 한꺼번에 해석하는 eager 모두 허용). 5.4.2절은 준비가 JVM 코드를 실행하지 않으며 static 필드의 명시적 초기식은 초기화 때 실행된다고 한다.
(공식 문서) 5.5절 초기화 절차의 첫 단계는 ConstantValue 속성이 있는 static 필드에 그 값을 대입하는 것이고, 그다음 `<clinit>`을 실행한다.
(공식 문서) 5.3절에 따르면 클래스 파일을 못 찾으면 로더가 ClassNotFoundException을 던지고 로딩 과정은 이를 원인으로 하는 NoClassDefFoundError로 실패한다. 검증 실패는 VerifyError다.
(실험 확인) 준비 단계에서 기본값이 먼저 들어간다는 것을 선언 순서를 거꾸로 한 static 초기식으로 확인했다.

```java
static class P {
    static int v = read();   // w 보다 앞에서 초기화
    static int w = 5;
    static int read() { return w; }
}
// P.v == 0, P.w == 5
```

`v`를 초기화하는 시점에 `w`는 준비 단계의 기본값 0이라 `v`가 0이 됐다.
