**모범 답변 (30~60초)**
메서드를 호출할 때마다 호출한 스레드의 JVM 스택에 프레임이 하나 만들어지고, 프레임 안에는 지역 변수 배열과 피연산자 스택이 있습니다. 메서드가 정상이든 예외든 끝나면 그 프레임은 사라집니다. 객체와 배열은 모든 스레드가 공유하는 힙에 할당되고 가비지 컬렉터가 회수합니다. 지역 변수에는 기본형 값이나 힙 객체를 가리키는 참조가 들어가므로, 참조 변수는 스택에 있어도 객체 자체는 힙에 있습니다. 스택이 허용 크기를 넘으면 StackOverflowError, 힙이 모자라면 OutOfMemoryError가 납니다.

(공식 문서) JVM 사양 2.6절은 프레임이 메서드 호출 때 만들어지고 완료되면 파괴되며, 각 프레임이 지역 변수 배열·피연산자 스택·런타임 상수 풀 참조를 갖는다고 한다. 2.6.1절은 지역 변수 하나가 int, float, reference, returnAddress 값을 담을 수 있다고 하고, 2.5.3절은 클래스 인스턴스와 배열의 메모리가 힙에서 할당된다고 한다.
(실험 확인) 종료 조건 없는 재귀를 `-Xss` 값만 바꿔 실행하고 StackOverflowError를 잡아 깊이를 셌다(HotSpot, macOS, Corretto 25.0.3의 한 번 실행 값이다. 같은 `-Xss4m`이 앞선 실행에서는 98466이 나왔을 만큼 JIT 컴파일 여부에 따라 실행마다 크게 달라진다).

```text
-Xss256k : depth=1465
-Xss1m   : depth=20171
(기본값)  : depth=50125   (실험 환경는 macOS/Aarch64라 기본 2048k)
-Xss4m   : depth=197217
```

스택 크기를 키울수록 깊이가 늘었고, 오류를 잡은 뒤에도 JVM은 계속 동작해 힙에 `new int[10]`을 정상 할당했다. 스택은 스레드별이라 이 오류는 해당 스레드의 문제다.
(공식 문서) `java` 도구 문서는 `-Xss`가 스레드 스택 크기이고 기본값이 플랫폼마다 다르다고 한다(예: Linux/x64 1024 KB, macOS/Aarch64 2048 KB).
