**모범 답변 (30~60초)**
평소 쓰는 참조가 강한 참조이고, 이것으로 닿는 객체는 회수되지 않습니다. SoftReference는 메모리 요구에 따라 GC가 재량으로 지우며, OutOfMemoryError를 던지기 전에 softly reachable 객체를 가리키는 soft 참조가 모두 지워진다고 보장돼서 메모리에 민감한 캐시에 씁니다. WeakReference는 GC가 약한 참조로만 닿는다고 판단하면 지우므로 키를 붙잡지 않는 매핑에 씁니다. PhantomReference는 get이 항상 null이고, 객체가 회수 대상이 된 뒤 ReferenceQueue로 통지를 받아 사후 정리를 할 때 씁니다. 참조 객체 자체가 도달 불가능해지면 큐에 들어오지 않으니 직접 붙잡고 있어야 합니다.

(공식 문서) java.lang.ref 패키지 문서가 강함에서 약함 순으로 strongly, softly, weakly, phantom reachable을 정의하고, 마지막에 어느 쪽으로도 닿지 않으면 회수 대상이라고 한다. SoftReference 문서는 최근에 만들어졌거나 쓰인 soft 참조를 덜 지우도록 구현에 권장하지만 지우는 시점과 순서에는 제약이 없다고 한다. WeakReference는 GC가 weakly reachable임을 판단하면 그 객체를 가리키는 weak 참조를 모두 원자적으로 지우고 객체를 finalizable로 만든다. Phantom 참조의 `get`은 항상 `null`이고 `refersTo`로 referent 여부를 검사할 수 있다.
(실험 확인) 아래를 `-Xmx64m`로 확인했다(HotSpot G1, `System.gc()` 사용).

```text
System.gc() 뒤: 강하게도 참조 중인 객체의 weak 참조 -> 유지
                  weak 참조만 있는 객체 -> get() == null
                  soft 참조만 있는 객체 -> get() != null (메모리 여유가 있어서 유지)
phantom.get() == null, 큐에 들어옴(poll 성공)
20MB를 soft 참조로 들고 있다가 힙을 꽉 채워 OutOfMemoryError가 던져진 시점 -> 살아 있는 soft 참조 0개
```

(보충) 캐시에 SoftReference를 쓰는 것이 실무에서 항상 좋은 선택은 아니다. 회수 시점이 GC 구현과 메모리 압박에 달려 있어 캐시 적중률을 예측하기 어렵다는 점은 문서에 없는 일반적인 설명이다.
