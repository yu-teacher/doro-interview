**모범 답변 (30~60초)**
StackOverflowError는 한 스레드의 계산이 허용된 JVM 스택보다 큰 스택을 요구할 때 나고, 흔한 원인은 종료 조건이 없는 깊은 재귀입니다. 스택은 스레드마다 따로라서 그 스레드에서 나는 문제입니다. OutOfMemoryError는 객체를 할당해야 하는데 가비지 컬렉터가 공간을 더 만들어 주지 못하고 힙도 더 늘릴 수 없을 때가 대표적입니다. 사양상으로는 메서드 영역이 모자랄 때나 스택을 확장하지 못할 때도 나며, 라이브러리 네이티브 코드의 할당 실패로도 납니다. OOM은 상세 메시지로 힙인지 Metaspace인지 구분합니다.

(공식 문서) JVM 사양 2.5절이 두 오류의 발생 조건을 영역별로 정리한다. 스택은 요구가 허용보다 크면 StackOverflowError, 확장하거나 새 스레드의 초기 스택을 만들 메모리가 없으면 OutOfMemoryError이고, 힙과 메서드 영역은 부족하면 OutOfMemoryError다. OutOfMemoryError API 문서는 객체를 할당할 수 없고 GC가 더 확보하지 못한 경우라고 하며, 문제 해결 가이드는 네이티브 라이브러리 코드의 할당 실패로도 이 오류가 던져질 수 있다고 한다.
(실험 확인) 아래 세 가지를 직접 일으켜 메시지를 확인했다(HotSpot, Corretto 25.0.3).

```text
-Xmx32m  : long[100_000] 배열을 계속 보관     -> OutOfMemoryError: Java heap space
-Xmx32m  : new int[Integer.MAX_VALUE]          -> OutOfMemoryError: Requested array size exceeds VM limit
-XX:MaxMetaspaceSize=16m : 로더마다 프록시 클래스 생성 -> OutOfMemoryError: Metaspace
```

(실험 확인) 같은 방식으로 `new int[n]`의 n을 바꿔 보니(`-Xmx32m`, HotSpot) `Integer.MAX_VALUE`와 `MAX_VALUE-1`은 `Requested array size exceeds VM limit`, `MAX_VALUE-2` 이하는 `Java heap space`였다. 이 경계는 HotSpot 구현의 값이라 사양이나 문서가 정한 수치가 아니다.

StackOverflowError는 잡은 뒤에도 JVM이 계속 동작하는 것을 jv-02 실험에서 확인했다. 상세 메시지별 의미는 jv-13에서 다룬다.
