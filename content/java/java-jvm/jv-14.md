**모범 답변 (30~60초)**
HotSpot은 기본이 혼합 모드라서, 처음에는 바이트코드를 인터프리터로 실행하다가 자주 실행되는 핫 메서드만 JIT 컴파일러가 네이티브 코드로 컴파일합니다. JVM은 실행 중에 메서드별로 바이트코드가 몇 번 실행됐는지, 어떤 타입의 객체가 오는지 같은 프로파일을 모으고, 이것을 근거로 최적화합니다. 자주 일어나는 경로를 가정해 최적화했다가 가정이 깨지면 인터프리터 실행으로 되돌릴 수도 있습니다. 그래서 시작 직후에는 느리다가 워밍업 뒤에 빨라집니다. Java 24의 AOT 캐시에 25부터 실행 프로파일 저장이 더해져 이 워밍업을 줄일 수 있습니다.

(공식 문서) `java` 도구 문서는 `-Xmixed`(기본)가 핫 메서드만 네이티브 코드로 컴파일하고 나머지는 인터프리터로 실행한다고 하고, `-Xint`는 컴파일을 끄고 전부 인터프리터로 실행한다고 한다. JEP 483(Java 24)은 AOT 캐시로 클래스를 로드·링크된 상태로 저장해 시작 시간을 줄이는 기능이다. JEP 515는 HotSpot이 JDK 1.2부터 메서드별 프로파일을 모아 왔고, 워밍업 동안 프로파일을 모으며 느리게 돈다고 하며, 훈련 실행의 프로파일을 저장해 시작 때 JIT가 바로 쓰게 하는 기능(Java 25)을 도입한다. JEP 483은 JVM이 관찰한 동작에 근거해 투기적으로 최적화하고 가정이 깨지면 바이트코드 해석으로 되돌릴 수 있다고 설명한다.
(실험 확인) 같은 루프(약 3억 번 반복)를 `-Xmixed`와 `-Xint`로 실행해 시간을 쟀다(Corretto 25.0.3, macOS, 재실행 한 번의 값이며 앞선 실행에서도 각각 약 140ms와 1.1~1.2초였다).

```text
-Xmixed : 139 ms
-Xint   : 1158 ms
```

`-XX:+PrintCompilation`에서는 같은 `work` 메서드가 레벨 3으로 먼저, 이어서 레벨 4로 컴파일됐다고 출력됐다.
(보충) 레벨 3과 4가 C1과 C2 컴파일러에 해당하고 여러 단계를 거치는 티어드 컴파일이라는 설명은 일반적인 설명이다. 위 `java` 문서에는 C1·C2와 `-XX:TieredStopAtLevel` 같은 티어드 옵션의 이름만 나오고 단계 정의는 없다.
