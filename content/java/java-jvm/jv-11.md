**모범 답변 (30~60초)**
Java 8에서 HotSpot의 영구 세대(PermGen)가 제거됐습니다. 이전에는 클래스 메타데이터, intern된 문자열, 클래스의 static 변수가 모두 영구 세대에 있어 크기를 -XX:MaxPermSize로 맞춰야 했습니다. 이후 클래스 메타데이터는 네이티브 메모리의 Metaspace로, intern 문자열과 static 변수는 Java 힙으로 옮겨졌습니다. Metaspace는 크기를 따로 정해 두지 않으면 상한이 없고 -XX:MaxMetaspaceSize로 제한할 수 있으며, 넘으면 OutOfMemoryError: Metaspace가 납니다. 메타데이터는 클래스 로더별 블록에 할당되어 로더가 해제될 때 반환됩니다.

(공식 문서) JEP 122(Java 8)가 영구 세대 제거 목적과 방식을 설명한다. 클래스 메타데이터는 네이티브 메모리에 로더별 블록으로 할당하고 로더가 죽으면 블록을 해제하며, intern 문자열과 클래스 static 변수는 Java 힙으로 옮긴다고 한다. JEP 387(Java 16)은 Metaspace가 JEP 122 이후 오프힙 메모리를 많이 쓰는 것으로 다소 악명이 높았다고 하며, 사용하지 않는 메타스페이스 메모리를 OS에 더 빨리 돌려주도록 개선한다. `java` 도구 문서는 `-XX:MaxMetaspaceSize`의 기본값이 제한 없음이라고 한다.
(공식 문서) 문제 해결 가이드는 상한(MaxMetaspaceSize)을 넘기면 `OutOfMemoryError: Metaspace`가 나고, 64비트에서 클래스 포인터 압축을 쓰면 별도로 `Compressed class space` 부족 메시지도 날 수 있다고 한다.
(실험 확인) `-XX:MaxMetaspaceSize=16m`로 실행하며 새 클래스 로더마다 프록시 클래스를 만들어 붙들자 `java.lang.OutOfMemoryError: Metaspace`가 났다(HotSpot, Corretto 25.0.3).
(보충) JVM 사양의 메서드 영역(jv-01)을 HotSpot이 Metaspace 등으로 구현한다고 대응해 설명하는 것은 일반적인 설명이고, 위 JEP 문서가 그 대응을 한 문장으로 못박지는 않는다.
