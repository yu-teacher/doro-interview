**모범 답변 (30~60초)**
WeakHashMap은 키를 약한 참조로 들고 있어서 키가 다른 곳에서 더는 쓰이지 않으면 GC 뒤에 항목이 사라집니다. 하지만 값은 맵이 일반 강한 참조로 들고 있기 때문에 값이 키를 직접 또는 간접적으로 참조하면 키가 강하게 도달 가능해져서, 약한 참조가 지워지지 않고 항목이 계속 남습니다. 문서는 값을 WeakReference로 감싸는 방법을 제시합니다. 또 사라지는 시점이 GC에 달려서 size가 줄거나 get이 갑자기 null을 주는 식으로 동작하고, 키는 동일성 비교 객체에 어울립니다. String처럼 다시 만들 수 있는 키는 혼란스럽습니다.

(공식 문서) WeakHashMap API 문서의 구현 노트에 근거한다. 값은 일반 강한 참조로 들고 있으므로 값이 자신의 키를 직접 또는 간접적으로(맵을 통해 다른 키의 값이 이 키를 참조하는 경우 포함) 강하게 참조하면 키가 폐기되지 못한다고 하고, 값이 맵의 강한 참조에 의존하지 않으면 `m.put(key, new WeakReference(value))`로 감싸고 `get` 때 꺼내라고 한다. 문서는 GC가 언제든 키를 버릴 수 있어서 보이지 않는 스레드가 항목을 지우는 것처럼 보일 수 있고, 그래서 `size`, `isEmpty`, `containsKey`, `get`의 결과가 시간에 따라 바뀔 수 있다고 한다.
(실험 확인) 키 1000개를 맵에 넣고 지역 참조를 버린 뒤 `System.gc()`를 반복했다(HotSpot, `-Xmx64m`).

```text
값이 키를 참조하지 않음(byte[10])  : GC 뒤 size = 0
값이 키를 참조함(ValueRefsKey)      : GC 뒤 size = 1000
```

값이 키를 참조하는 항목 1000개가 모두 남았다. 같은 값을 `new WeakReference<>(값)`으로 감싸 넣으면(값을 다른 곳에서 강하게 잡지 않는 경우) `System.gc()` 몇 번 뒤 `size = 0`이었다(HotSpot, `-Xmx64m`).
