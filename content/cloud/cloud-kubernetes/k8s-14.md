**모범 답변 (30~60초)**
HPA는 Deployment나 StatefulSet 같은 대상의 replicas를 메트릭에 맞춰 자동으로 조정하는 컨트롤 루프이고, 기본 15초마다 메트릭을 조회합니다. 개수는 현재 replicas에 현재 메트릭 값을 목표값으로 나눈 비율을 곱해 올림해서 계산하고, 비율이 1에 가까우면 기본 허용 오차 0.1 안에서는 조정하지 않습니다. CPU 사용률은 사용량이 Pod의 CPU `requests` 대비 몇 퍼센트인지로 계산하므로 `requests`가 꼭 있어야 하고, 리소스 메트릭 API(`metrics.k8s.io`, 보통 metrics-server)가 필요합니다. 플래핑을 막으려 축소에는 기본 300초 안정화 창이 적용되고, HPA를 쓰면 매니페스트의 `spec.replicas`는 지우는 것이 권장됩니다.

(공식 문서) Horizontal Pod Autoscaling 페이지는 HPA가 API 리소스와 컨트롤러로 구현되고 kube-controller-manager의 `--horizontal-pod-autoscaler-sync-period` 기본값이 15초이며, 리소스 메트릭 API는 보통 별도로 띄우는 Metrics Server 애드온이 제공한다고 설명한다. 알고리즘은 `desiredReplicas = ceil[currentReplicas * (currentMetricValue / desiredMetricValue)]`이고 비율이 1.0에 충분히 가까우면(기본 허용 오차 0.1) 조정을 건너뛴다. 사용률은 현재 사용량을 Pod의 리소스 request 대비 비율로 구하므로 request 지정이 필요하다고 하고, 컨테이너별 지표(ContainerResource)도 지원한다. scaleDown 안정화 창 기본값은 300초이고 scaleUp은 0초이다. HPA 사용 시 Deployment 매니페스트의 `spec.replicas`를 제거하길 권장하는데, 남기면 `kubectl apply` 때마다 그 값으로 되돌려 플래핑이 생길 수 있다고 한다. 클러스터가 없어 실험하지 않았다. (2026-10-27 원문 확인)
