**모범 답변 (30~60초)**
쿠버네티스는 컨테이너화된 워크로드와 서비스를 관리하는 오픈 소스 플랫폼입니다. 컨테이너만 직접 띄우면 하나가 죽었을 때 다시 띄우고, 부하에 맞춰 늘리고, 새 버전으로 무중단 교체하는 일을 사람이 해야 합니다. 쿠버네티스는 죽은 컨테이너를 재시작하거나 교체하는 자가 치유, 롤아웃과 롤백, 서비스 디스커버리와 로드 밸런싱, 설정과 시크릿 관리 같은 기능을 제공합니다. 동작 방식은 절차를 순서대로 실행하는 것이 아니라, 원하는 상태를 선언하면 컨트롤러들이 현재 상태를 그쪽으로 계속 수렴시키는 것입니다.

(공식 문서) Overview 페이지는 쿠버네티스를 컨테이너화된 워크로드와 서비스를 관리하는 이식 가능하고 확장 가능한 오픈 소스 플랫폼이라고 소개하고, 제공 기능으로 서비스 디스커버리와 로드 밸런싱, 스토리지 오케스트레이션, 자동 롤아웃·롤백, 자동 bin packing, 자가 치유, 시크릿·설정 관리, 배치 실행, 수평 확장을 나열한다. 같은 페이지는 쿠버네티스가 단순한 오케스트레이션(A 다음 B 다음 C 식의 정해진 워크플로 실행)이 아니라 현재 상태를 원하는 상태로 계속 몰아가는 독립적인 제어 프로세스의 집합이라고 설명하고, 전통적인 올인원 PaaS가 아니며 소스 코드를 배포하거나 애플리케이션을 빌드하지 않는다고 밝힌다. Controllers 페이지는 컨트롤러를 클러스터 상태를 지켜보다가 현재 상태를 원하는 상태에 가깝게 만드는 제어 루프로 정의한다. 클러스터가 없어 실험하지 않았다. (2026-10-27 Kubernetes 1.37 문서 원문 확인)
