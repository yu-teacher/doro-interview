**모범 답변 (30~60초)**
세 프로브는 목적이 다릅니다. `livenessProbe`는 컨테이너가 살아 있는지 보고, 실패 임계를 넘으면 kubelet이 컨테이너를 재시작합니다. 교착 상태처럼 재시작해야 풀리는 문제에 쓰는 용도입니다. `readinessProbe`는 트래픽을 받을 준비가 됐는지 보고, 실패하면 재시작하지 않고 Service 트래픽 대상에서만 빠지며 컨테이너 수명 내내 계속 실행됩니다. `startupProbe`는 앱이 시작을 마쳤는지 보며, 설정하면 성공할 때까지 다른 두 프로브가 실행되지 않아 시작이 느린 앱이 liveness에 죽는 것을 막습니다. HTTP 프로브는 200 이상 400 미만이 성공입니다.

(공식 문서) Configure Liveness, Readiness and Startup Probes 페이지는 liveness 실패 시 kubelet이 컨테이너를 죽이고 재시작하고, readiness 실패 시 Pod가 Service로 트래픽을 받지 않으며 readiness 프로브는 컨테이너의 전체 수명 동안 실행된다고 설명한다. startup 프로브는 `failureThreshold * periodSeconds`로 최악의 시작 시간을 덮고, 한 번 성공하면 liveness가 이어받으며 끝내 성공하지 못하면 컨테이너가 죽고 재시작 정책을 따른다고 한다. liveness와 readiness가 서로의 성공에 의존하지 않으므로 기다리려면 `initialDelaySeconds`나 startupProbe를 쓰라고 한다. HTTP는 200 이상 400 미만이 성공이다. Pod Lifecycle 페이지는 startup 프로브가 설정되면 성공 전까지 liveness와 readiness가 실행되지 않고, readiness 실패 시 EndpointSlice 컨트롤러가 Pod IP를 매칭되는 모든 Service의 EndpointSlice에서 제거한다고 한다. (2026-10-27 원문 확인)
(실험 확인) Kubernetes 1.36.1 클러스터(Docker Desktop)에서 nginx가 경로별로 응답 코드를 돌려주게 하고 readiness 프로브를 걸자 200, 301, 399는 `1/1`(성공), 400과 500은 `0/1`이고 이벤트는 `Readiness probe failed: HTTP probe failed with statuscode: 400`이었으며 재시작은 0이었다. readiness가 도중에 성공에서 실패로 바뀌는 Pod에서는 `2/2`가 `1/2`로 떨어졌고 `RESTARTS`는 0이었다. 이때 EndpointSlice에서 Pod IP가 지워진 것이 아니라 `ready: false`(`serving: false`)로 남았고(`Endpoints`에서는 `notReadyAddresses`), Service로의 요청은 `Connection refused`였다. liveness를 400 응답 경로로 걸면 이벤트에 `Liveness probe failed: HTTP probe failed with statuscode: 400`과 `Container nginx failed liveness probe, will be restarted`가 나고 재시작이 쌓이다 `CrashLoopBackOff`가 됐다. startup 프로브가 있는 컨테이너에서 startup 프로브는 주기마다 돌다 성공한 직후부터 liveness·readiness 프로브가 돌기 시작했다(각 프로브가 남긴 로그의 시각 순서). startup 프로브가 계속 실패하는 컨테이너(`failureThreshold: 3`, `periodSeconds: 2`)는 `Container c failed startup probe, will be restarted`와 함께 죽고 재시작됐다. 종료 코드는 프로세스가 SIGTERM을 어떻게 처리하느냐에 달려, SIGTERM을 무시하는 `sleep`은 유예 시간(30초) 뒤 SIGKILL로 137이었고 같은 설정의 nginx는 0(`Completed`)이었다. 199 응답은 nginx가 올바른 HTTP 응답을 만들지 못해(`malformed HTTP response`) 하한 경계를 확인하지 못했다.
