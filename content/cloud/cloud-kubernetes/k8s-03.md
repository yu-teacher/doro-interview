**모범 답변 (30~60초)**
Pod는 쿠버네티스에서 만들고 관리하는 가장 작은 배포 단위로, 네트워크와 스토리지를 공유하는 컨테이너 한 개 이상의 묶음입니다. 한 Pod의 컨테이너는 같은 IP와 포트 공간을 쓰기 때문에 `localhost`로 서로 통신하고, 같은 볼륨을 마운트할 수 있으며, 항상 같은 노드에서 함께 실행됩니다. 대부분은 Pod당 컨테이너가 하나이고, 로깅·모니터링 같은 부가 기능으로 메인 앱을 보조하는 컨테이너를 사이드카로 함께 둡니다. 사이드카는 `restartPolicy: Always`를 준 init 컨테이너로 선언하며, 메인 컨테이너보다 먼저 시작해 Pod 수명 동안 실행되고 종료는 메인 컨테이너가 끝난 뒤에 이뤄집니다.

(공식 문서) Pods 페이지는 Pod를 저장소와 네트워크를 공유하는 컨테이너 묶음으로 정의하고, 한 Pod의 컨테이너가 네트워크 네임스페이스(IP, 포트)를 공유하며 서로 localhost로 통신하고, 같은 곳에 스케줄링되어 함께 실행된다고 설명한다. 복제는 한 Pod에 컨테이너를 여럿 넣는 것이 아니라 Pod를 여러 개 두는 것이고, Pod를 직접 만드는 일은 드물며 Deployment 같은 워크로드 리소스로 만든다고 한다. Sidecar Containers 페이지는 사이드카가 init 컨테이너의 특수한 경우이고 `restartPolicy: Always`로 선언하며, 종료 시 kubelet이 메인 컨테이너가 완전히 멈출 때까지 사이드카 종료를 미루고 선언의 역순으로 내린다고 한다. 사이드카를 로깅·모니터링·보안·데이터 동기화 같은 부가 기능을 주는 용도로 소개한다. 이 기능은 1.29부터 기본 활성이고 1.33에서 stable이다. (2026-10-27 원문 확인)
(실험 확인) Kubernetes 1.36.1(Docker Desktop 단일 노드)에서 `initContainers`에 `restartPolicy: Always`인 nginx 사이드카(startupProbe 포함), 일반 init 컨테이너, busybox 메인 컨테이너를 한 Pod에 두고 `restartPolicy: Never`로 실행했다. 사이드카가 먼저 시작해 공유 `emptyDir`에 쓴 파일을 일반 init 컨테이너가 읽을 수 있었고(사이드카가 계속 실행 중인 채로 다음 단계로 넘어갔다), 메인 컨테이너는 그 뒤에 시작했다. 메인 컨테이너에서 `wget http://localhost:80`이 사이드카 nginx의 응답을 받았고 `hostname -i`가 `status.podIP`와 같았다. 메인이 끝나자 사이드카도 약 1초 뒤 종료 코드 0으로 내려가 Pod가 `Completed`가 됐다. 선언 역순 종료와 노드 공동 배치는 확인하지 않았다(단일 노드).
