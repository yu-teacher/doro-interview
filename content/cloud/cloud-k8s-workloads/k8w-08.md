**모범 답변 (30~60초)**
스케줄러는 노드가 아직 배정되지 않은 새 Pod를 대상으로 두 단계로 노드를 고릅니다. 먼저 필터링에서 Pod의 요구를 만족하지 못하는 노드를 걸러 냅니다. 요청한 자원이 남아 있는지, `nodeSelector`나 어피니티, taint와 toleration이 맞는지를 보는 단계입니다. 남은 실행 가능 노드가 여럿이면 스코어링으로 점수를 매겨 가장 높은 노드를 고르고, 동점이면 그중 무작위로 하나를 택합니다. 이 결정을 API 서버에 알리는 과정이 바인딩입니다. 필터링 뒤에 노드가 하나도 안 남으면 Pod는 Pending으로 남고, 낮은 우선순위 Pod를 내보내 자리를 만드는 선점이 시도될 수 있습니다.

(공식 문서) Kubernetes Scheduler 페이지는 kube-scheduler가 새로 만들어졌거나 아직 스케줄되지 않은 Pod를 위해 필터링과 스코어링 두 단계로 노드를 고른다고 설명한다. 필터링은 Pod의 요구를 못 채우는 노드를 거르고(자원 요청이 맞는지 보는 필터가 예시), 목록이 비면 Pod는 아직 스케줄할 수 없다. 스코어링은 남은 노드에 점수를 매겨 최고점 노드를 고르고 동점이면 무작위로 하나를 택하며, 결정을 API 서버에 알리는 과정이 바인딩이다. Scheduling Framework 페이지는 Filter 뒤에 실행 가능한 노드가 없을 때만 PostFilter가 호출되고 대표 구현이 선점이라고 한다. Assigning Pods to Nodes 페이지는 `preferred` 어피니티의 가중치가 다른 점수에 더해지고 `required` 규칙은 노드 필터링 단계에서 적용된다고 한다. taint는 Taints and Tolerations 페이지가 매칭 toleration이 없으면 `NoSchedule` 노드에 스케줄하지 않는다고 한다.
(실험 확인) Kubernetes v1.36.1 단일 노드에서 노드를 탈락시키는 필터 사유가 이벤트에 `0/1 nodes are available: 1 Insufficient cpu.` 형태로 나왔고(필터링 실패), 같은 이벤트 뒤에 `preemption: 0/1 nodes are available: 1 Preemption is not helpful for scheduling.`이 이어져 필터링 실패 뒤에 선점 단계(PostFilter)가 시도됨을 볼 수 있었다. 맞는 노드가 없는 `preferred` 어피니티 Pod는 점수에서만 불리할 뿐 노드에 배치됐다. 노드가 하나라 점수 비교로 노드가 갈리는 과정과 동점 무작위 선택은 확인하지 못했고 공식 문서 근거만 쓴다.
