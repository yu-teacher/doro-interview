**모범 답변 (30~60초)**
`requests.cpu`나 `limits.memory`처럼 컴퓨트 자원에 쿼터가 걸린 네임스페이스에서는 쿼터가 걸린 항목마다 Pod가 값을 명시해야 하고, 빠지면 API 서버가 생성을 403 Forbidden으로 거부합니다. 예를 들어 `requests.cpu`와 `limits.memory` 쿼터가 있으면 requests만 쓴 Pod는 `limits.memory`가 없다고 거부됩니다. 쿼터를 넘기는 요청도 같은 403이고 메시지에 요청량과 사용량, 한도가 나옵니다. 매번 쓰기 번거로우면 같은 네임스페이스에 `LimitRange`로 기본값을 두면 값이 자동으로 채워집니다. 쿼터는 종료되지 않은 Pod들의 합계로 계산하며, Deployment 같은 상위 오브젝트는 만들어져도 Pod가 거부될 수 있어 `kubectl describe`로 확인해야 합니다.

(공식 문서) Resource Quotas 페이지는 위반하는 생성·수정 요청이 403 Forbidden으로 거부되고 메시지에 위반 내용이 담기며, `cpu`·`memory`에 쿼터가 있으면 새 Pod마다 requests나 limits를 지정해야 하고 아니면 거부될 수 있다고 한다. `LimitRange`로 기본값을 강제하면 이 문제를 피할 수 있다고 하며, `limits.cpu` 같은 컴퓨트 쿼터는 종료되지 않은 상태의 Pod들의 합계에 적용된다. Deployment 같은 상위 오브젝트는 생성에 성공해도 Pod가 모두 만들어지지 못할 수 있어 `kubectl describe`로 확인하라고 한다.
(실험 확인) Kubernetes v1.36.1에서 쿼터(`requests.cpu: 1`, `limits.memory: 512Mi`, `pods: 3`)가 있는 네임스페이스에 자원 값 없는 Pod를 만들자 `failed quota: q: must specify limits.memory for: nores; requests.cpu for: nores`(Forbidden)로 거부됐다. 반례로, CPU·메모리 `limits`만 쓴 Pod는 requests가 limits와 같은 값으로 채워져 통과했고, requests(CPU·메모리)만 쓴 Pod는 `must specify limits.memory`, 메모리 limits만 쓴 Pod는 `must specify requests.cpu`로 거부됐다(쿼터가 걸린 항목마다 값이 있어야 한다). 기본값을 넣는 LimitRange(`default` cpu 300m·memory 128Mi, `defaultRequest` cpu 100m·memory 64Mi)를 만든 뒤 값 없는 Pod는 성공했고 requests 100m·64Mi, limits 300m·128Mi가 들어갔으며 annotation `LimitRanger plugin set: ...`이 붙었다. 쿼터 사용량은 집계됐고(`limits.memory` 228Mi, `requests.cpu` 700m, `pods` 2), `pods: 3`이 찬 상태에서 새 Pod는 `exceeded quota ... requested: pods=1, used: pods=3, limited: pods=3`으로 거부됐다.
