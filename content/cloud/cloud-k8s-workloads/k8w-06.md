**모범 답변 (30~60초)**
둘 다 네임스페이스에 거는 정책이지만 대상이 다릅니다. `ResourceQuota`는 네임스페이스 전체의 합계를 제한해서, 예를 들어 `requests.cpu` 합계나 Pod 개수가 상한을 넘으면 새 오브젝트 생성을 막습니다. `LimitRange`는 개별 컨테이너나 Pod 하나에 대해 최소·최대 값과 requests 대비 limits 비율을 강제하고, requests와 limits를 안 쓴 컨테이너에는 기본값을 넣어 줍니다. 둘 다 위반하면 API 서버가 403 Forbidden으로 거부합니다. 그래서 총량은 쿼터로, 개별 크기와 기본값은 LimitRange로 함께 씁니다.

(공식 문서) Resource Quotas 페이지는 네임스페이스에서 만들 수 있는 리소스의 총량(컴퓨트 자원 합계, 특정 종류 오브젝트 개수 등)을 제한하며, 위반하면 요청이 HTTP 403 Forbidden으로 거부된다고 설명한다. Limit Ranges 페이지는 LimitRange가 네임스페이스 안에서 Pod나 컨테이너별 최소·최대, 요청 대비 limit 비율을 강제하고 기본 request/limit를 주입한다고 하며, 위반 시 403으로 거부된다고 한다.
(실험 확인) Kubernetes v1.36.1에서 `requests.cpu: 1`, `limits.memory: 512Mi`, `pods: 3` 쿼터가 있는 네임스페이스에 `requests.cpu: 600m` Pod를 만든 뒤 같은 크기 Pod를 하나 더 만들자 `exceeded quota: q, requested: requests.cpu=600m, used: requests.cpu=600m, limited: requests.cpu=1`로 거부됐다. 컨테이너 메모리 최대 256Mi인 LimitRange가 있을 때 limit 300Mi Pod는 `maximum memory usage per Container is 256Mi, but limit is 300Mi`로 거부됐다. 이 LimitRange에 `default`·`defaultRequest`가 있으면 값이 없는 Pod에 기본값이 들어갔다(`k8w-10`, `k8w-11` 실험).
