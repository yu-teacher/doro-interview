**모범 답변 (30~60초)**
`<unknown>`은 HPA가 현재 메트릭 값을 구하지 못했다는 뜻입니다. CPU 사용률은 리소스 메트릭 API(`metrics.k8s.io`)가 제공해야 하고 보통 metrics-server 애드온을 따로 설치해야 하는데, 없으면 HPA는 `ScalingActive`가 False가 되고 아무 조정도 하지 않습니다. 컨테이너에 CPU requests가 없어도 사용률이 정의되지 않아 조정하지 않습니다. 또 HPA를 쓰면 Deployment 매니페스트에서 `spec.replicas`를 빼라고 권장합니다. 남겨 두면 `kubectl apply`를 할 때마다 그 값으로 되돌려져 HPA와 충돌하고 개수가 출렁일 수 있기 때문입니다.

(공식 문서) Horizontal Pod Autoscaling 페이지는 리소스 메트릭 API(`metrics.k8s.io`)를 보통 Metrics Server가 제공하며 클러스터 애드온으로 띄울 수 있다고 한다. 사용률은 컨테이너의 resource request 대비 비율이며 일부 컨테이너에 해당 request가 없으면 그 메트릭에 대해 오토스케일러가 아무 조치도 하지 않는다고 한다. 마이그레이션 절은 HPA를 켤 때 매니페스트의 `spec.replicas`를 제거하길 권하고, 남기면 `kubectl apply -f`로 변경이 적용될 때마다 그 값으로 스케일되어 HPA와 충돌(thrashing)할 수 있으며, 제거하면 기본값 1로 일시적으로 줄어들 수 있다고 한다.
(실험 확인) Kubernetes v1.36.1 Docker Desktop 클러스터에는 metrics-server가 없어 `kubectl top nodes`가 `Metrics API not available`이었다. `kubectl autoscale deploy app --cpu=50% --min=2 --max=6`을 만들자 60초 넘게 `cpu: <unknown>/50%`로 남았고, 조건은 `ScalingActive=False`, 이유 `FailedGetResourceMetric`, 메시지에 `unable to fetch metrics from resource metrics API: the server could not find the requested resource (get pods.metrics.k8s.io)`가 들어 있었으며 replicas는 3으로 유지됐다. 별도로 HPA 없이 `kubectl scale`로 replicas를 5로 늘린 뒤 `replicas: 3`이 적힌 매니페스트를 `kubectl apply`하자 3으로 되돌아갔다. `kubectl apply`로 `replicas`가 있던 매니페스트에서 `replicas`를 뺀 매니페스트를 처음 적용하면 replicas가 1로 줄었고, 다시 5로 늘린 뒤 같은 매니페스트를 적용하면 5가 유지됐다. requests가 없을 때의 증상은 실험하지 않았다(그 전 단계인 메트릭 API 조회에서 실패했다). 이 부분은 공식 문서 근거만 쓴다.
