**모범 답변 (30~60초)**
`emptyDir`는 Pod가 노드에 배정될 때 빈 디렉터리로 만들어지고 Pod가 그 노드에서 사라지면 함께 지워지는 임시 볼륨입니다. 컨테이너가 죽어 재시작되는 것만으로는 데이터가 지워지지 않지만 Pod가 교체되면 사라지므로 캐시나 컨테이너 간 파일 공유에 씁니다. `hostPath`는 노드의 파일시스템 경로를 그대로 마운트하는데, 노드마다 내용이 달라질 수 있고 노드의 민감한 파일에 접근할 수 있어서 문서도 가능하면 피하라고 합니다. Pod와 별개로 데이터를 보존해야 하면 PersistentVolumeClaim 볼륨으로 PV에 저장합니다.

```yaml
volumes:
- name: scratch
  emptyDir: {}
- name: data
  persistentVolumeClaim: {claimName: data}
```

(공식 문서) Volumes 페이지는 모든 종류의 볼륨에서 컨테이너가 재시작해도 데이터가 유지된다고 하고, 임시(ephemeral) 볼륨의 수명은 Pod에 묶여 있지만 영구 볼륨은 Pod 수명을 넘어 존재하며 쿠버네티스가 지우지 않는다고 한다. `emptyDir`는 Pod가 노드에 배정될 때 만들어져 처음엔 비어 있고, 모든 컨테이너가 같은 파일을 읽고 쓸 수 있으며, Pod가 어떤 이유로든 노드에서 제거되면 영구 삭제되고 컨테이너 크래시는 Pod를 제거하지 않으므로 데이터가 안전하다고 한다. 용도로는 임시 작업 공간, 장시간 계산의 체크포인트, 콘텐츠를 받아 오는 컨테이너와 웹서버 컨테이너의 파일 공유를 든다. `hostPath`는 호스트 노드의 파일이나 디렉터리를 마운트하는 것으로, 많은 보안 위험이 있어 피할 수 있으면 피하고 예를 들어 로컬 PersistentVolume을 대신 쓰라고 한다. 노드의 파일시스템 접근이 kubelet 자격 증명이나 컨테이너 런타임 소켓 같은 것을 노출할 수 있고, 같은 구성의 Pod가 노드마다 다르게 동작할 수 있다고도 경고한다.
(실험 확인) Kubernetes v1.36.1 Docker Desktop 단일 노드 클러스터(kubeadm, 컨텍스트 docker-desktop)에서 재실행했다. 컨테이너가 매번 `exit 1`로 종료되는 Pod에서 `emptyDir`에 파일을 하나씩 만들자 세 번째 실행에서 파일 수가 3으로 세어져 컨테이너 재시작 후에도 데이터가 남았다. 같은 Pod가 PVC의 `/data/log.txt`에 한 줄씩 쓰게 한 뒤 Pod를 지우고 다시 만들자 새 Pod의 `emptyDir` 파일 수는 1부터 다시 세어졌고(재시작 한 번 뒤 2) PVC의 `log.txt`는 이전 줄에 이어져 5줄이 됐다. `hostPath`에 존재하지 않는 경로와 `type: Directory`를 주자 Pod는 `ContainerCreating`에 머물고 `hostPath type check failed: /exp-configv-nonexistent is not a directory` 이벤트가 났다. 같은 경로 방식에 `type: DirectoryOrCreate`를 주면 Pod가 `Running`이 됐다.
