**모범 답변 (30~60초)**
Deployment 생성은 거부되지 않습니다. enforce 모드는 워크로드 리소스에는 적용되지 않고 최종적으로 만들어지는 Pod에만 적용되며, audit과 warn 모드만 Deployment 같은 워크로드에도 적용되어 빨리 경고해 줍니다. 그래서 위반하는 Deployment는 만들어지지만 ReplicaSet이 Pod를 만들지 못해 `READY 0/1`에서 멈추고, 원인은 ReplicaSet 이벤트의 `FailedCreate`에 남습니다. 이미 실행 중인 Pod는 enforce 레이블을 달 때 경고만 나오고 계속 실행됩니다. 적용 전에 `--dry-run=server`로 기존 Pod에 미칠 영향을 미리 볼 수 있습니다.

```bash
kubectl label --dry-run=server --overwrite ns exp-configv pod-security.kubernetes.io/enforce=restricted
```

(공식 문서) Pod Security Admission 페이지는 Pod가 보통 Deployment나 Job 같은 워크로드로 간접 생성되며, 위반을 일찍 잡기 위해 audit과 warn 모드는 워크로드 리소스에도 적용되지만 enforce 모드는 워크로드 리소스에 적용되지 않고 만들어진 Pod에만 적용된다고 설명한다. Enforce Pod Security Standards with Namespace Labels 페이지는 enforce 레이블을 달거나 바꾸면 네임스페이스의 각 Pod를 새 정책에 대해 검사해 위반을 경고로 돌려주고, `--dry-run=server`로 정책을 실제로 바꾸지 않고 영향을 볼 수 있다고 한다.
(실험 확인) Kubernetes v1.36.1 Docker Desktop 단일 노드 클러스터(kubeadm, 컨텍스트 docker-desktop)에서 재실행했다. `warn=restricted` 네임스페이스에서 `kubectl create deployment`는 `Warning: would violate PodSecurity "restricted:latest"`와 함께 만들어졌다. `enforce=restricted`를 단 네임스페이스에서는 `kubectl create deployment`가 `created`였지만 `READY 0/1`(`UP-TO-DATE 0`)로 멈췄고 ReplicaSet은 `DESIRED 1 CURRENT 0`이었으며 이벤트에 `FailedCreate ... is forbidden: violates PodSecurity "restricted:latest"`가 반복됐다. 이미 Pod가 있는 네임스페이스에 enforce 레이블을 달 때 `existing pods in namespace ... violate the new PodSecurity enforce level` 경고가 나왔지만 이미 있던 Pod는 그대로 `Running`이었다. enforce 레이블을 뗀 뒤 `kubectl label --dry-run=server --overwrite ns ... enforce=restricted`를 실행하자 같은 경고와 함께 `labeled (server dry run)`이 출력됐고 실제 레이블은 바뀌지 않았다.
