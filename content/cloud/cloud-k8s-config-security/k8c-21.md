**모범 답변 (30~60초)**
`kubectl apply`는 적용한 매니페스트를 객체의 `kubectl.kubernetes.io/last-applied-configuration` 어노테이션에 저장해 다음 적용 때 비교 기준으로 씁니다. 그래서 `stringData`로 평문을 적어 apply하면 서버가 값을 `data`로 바꿔 저장하더라도 어노테이션에는 평문 매니페스트가 그대로 남았습니다. 이 어노테이션은 Secret을 읽을 수 있는 사람이 `kubectl get -o yaml`로 볼 수 있습니다. 매니페스트에 적는 값은 base64여도 그대로 노출되는 셈이라 파일을 저장소에 올리지 말아야 하고, `kubectl create secret`처럼 apply가 아닌 방법으로 만든 Secret에는 이 어노테이션이 붙지 않았습니다.

```bash
kubectl -n exp-configv get secret sd -o jsonpath='{.metadata.annotations}'
# {"kubectl.kubernetes.io/last-applied-configuration":"{...\"stringData\":{\"user\":\"admin\"}}\n"}
```

(공식 문서) Declarative Management of Kubernetes Objects Using Configuration Files 페이지는 `kubectl apply`가 객체에 `kubectl.kubernetes.io/last-applied-configuration` 어노테이션을 설정하고 그 내용이 객체를 만드는 데 쓴 구성 파일의 내용이라고 하며, 이후 적용 때 이 값과 비교해 변경분을 계산한다고 설명한다. Well-Known Labels, Annotations and Taints 페이지는 이 어노테이션을 kubectl이 변경 추적에 쓰는 레거시 방식이고 서버 측 적용이 대체했다고 한다. Good practices for Kubernetes Secrets 페이지는 base64로 인코딩한 Secret 매니페스트를 공유하거나 저장소에 넣으면 읽을 수 있는 모두에게 값이 노출되며 base64는 암호화 방법이 아니라고 경고한다. Secrets 페이지와 Managing Secrets using Configuration File 페이지는 `stringData`가 서버 측 적용과 잘 맞지 않는다고만 적는다. Secrets, Good practices for Secrets, Managing Secrets using Configuration File, Managing Secrets using kubectl, Managing Secrets using Kustomize 페이지와 kubectl apply 레퍼런스에서 Secret의 `last-applied-configuration` 어노테이션에 `stringData` 평문이 남는다는 명시적 설명은 찾지 못했고, 위 구성 파일 내용 설명에서 추론되는 결과를 실험으로 확인했다.
(실험 확인) Kubernetes v1.36.1 Docker Desktop 단일 노드 클러스터(kubeadm, 컨텍스트 docker-desktop)에서 재실행했다. `stringData: {user: admin}`로 `kubectl apply`한 Secret의 `.data`는 `{"user":"YWRtaW4="}`였고 `.stringData`는 비어 있었지만, `.metadata.annotations`의 `last-applied-configuration`에는 `"stringData":{"user":"admin"}` 평문이 들어 있었고 `kubectl apply view-last-applied`로도 보였다. `data` 필드(base64)로 apply한 경우에는 어노테이션에 base64 값이 그대로 들어갔다. `kubectl create secret generic --from-literal`, 같은 매니페스트의 `kubectl create -f`, `kubectl apply --server-side`로 만든 Secret에는 어노테이션이 붙지 않았다. `secrets`의 `list`만 허용한 계정도 `kubectl get secrets -o jsonpath`로 이 어노테이션을 읽었다. 어노테이션을 지운 뒤 값을 바꿔 다시 `apply`하면 어노테이션이 새 평문으로 다시 생겼다.
