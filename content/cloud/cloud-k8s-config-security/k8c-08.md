**모범 답변 (30~60초)**
StorageClass는 어떤 provisioner가 어떤 파라미터로 볼륨을 만들지, reclaimPolicy와 바인딩 시점을 어떻게 할지 적어 둔 클러스터 범위 객체입니다. PVC가 만들어지면 provisioner가 그에 맞는 PV를 그 자리에서 만들어 바인딩하므로 관리자가 PV를 미리 만들 필요가 없습니다. PVC에 `storageClassName`을 쓰지 않으면 기본 StorageClass가 적용되고, 빈 문자열 `""`로 쓰면 기본 클래스를 쓰지 않고 미리 만들어 둔 PV 중에서만 찾습니다. 바인딩 모드의 기본은 `Immediate`이고, `WaitForFirstConsumer`는 그 PVC를 쓰는 Pod가 만들어질 때까지 바인딩과 프로비저닝을 미룹니다.

```bash
kubectl get sc
# NAME                 PROVISIONER          RECLAIMPOLICY   VOLUMEBINDINGMODE
# hostpath (default)   docker.io/hostpath   Delete          Immediate
```

(공식 문서) Dynamic Volume Provisioning 페이지는 관리자가 StorageClass를 미리 만들어 두면 PVC 생성 시 스토리지가 자동으로 프로비저닝되어 PV를 수동으로 만들 필요가 없다고 설명한다. Storage Classes 페이지는 StorageClass가 `provisioner`, `parameters`, `reclaimPolicy`를 담고 PV를 동적으로 만들 때 쓰인다고 하며, PVC에 `storageClassName`이 없으면 기본 StorageClass가 쓰이고, 기본 클래스가 없어도 PVC는 만들어지며 나중에 기본이 생기면 값이 비어 있거나 키가 없는 PVC에 채워진다고 한다. 기존 PVC의 `storageClassName`이 `""`이면 갱신되지 않으므로, 기본 클래스가 있어도 `""`인 PV에 계속 붙으려면 PVC에도 `""`를 써야 한다고 하고, Persistent Volumes 페이지도 `""`인 PVC는 클래스가 `""`인 PV에만 바인딩된다고 한다. `volumeBindingMode`는 비워 두면 `Immediate`이고, `WaitForFirstConsumer`는 그 PVC를 쓰는 Pod가 만들어질 때까지 바인딩과 프로비저닝을 미루며 Pod의 스케줄링 제약에 맞는 PV를 고른다고 한다. Namespaces 페이지는 StorageClass를 네임스페이스에 속하지 않는 클러스터 범위 객체의 예로 든다.
(실험 확인) Kubernetes v1.36.1 Docker Desktop 단일 노드 클러스터(kubeadm, 컨텍스트 docker-desktop)에서 재실행했다. 기본 StorageClass는 `hostpath (default)`(provisioner `docker.io/hostpath`, reclaim `Delete`, 바인딩 `Immediate`)였고 `kubectl api-resources`에서 `storageclasses`의 NAMESPACED는 `false`였다. `storageClassName` 없이 만든 10Mi PVC는 몇 초 안에 `hostpath` 클래스로 바인딩되어 PV가 자동 생성됐다. `storageClassName: ""`인 PVC는 `Pending`이었고 이벤트는 `no persistent volumes available for this claim and no storage class is set`이었다. 클래스가 `""`이고 20Mi인 정적 PV(hostPath, `Retain`)를 만든 뒤 새로 만든 `""` PVC는 그 PV에 바로 바인딩됐다. 존재하지 않는 클래스 이름을 쓴 PVC는 `Pending`과 `storageclass ... "nosuchclass" not found` 이벤트였다. 같은 provisioner에 `volumeBindingMode: WaitForFirstConsumer`를 준 StorageClass의 PVC는 Pod를 만들기 전까지 `Pending`(`waiting for first consumer to be created before binding`)이었고 Pod를 만들자 `Bound`가 됐다.
