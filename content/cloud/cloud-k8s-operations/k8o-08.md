**모범 답변 (30~60초)**
파드의 `restartPolicy`가 기본값 `Always`가 아니라 `Never`이거나, `OnFailure`인데 성공(종료 코드 0)으로 끝나면 컨테이너가 재시작되지 않고 파드는 종료 상태로 남습니다. 모든 컨테이너가 성공하면 phase가 `Succeeded`, 하나라도 실패하면 `Failed`이고, `kubectl get`은 종료 코드 0이면 `Completed`, 아니면 `Error`로 보여 줍니다. Job이 만드는 파드가 전형적이며 일회성 작업이 끝났다는 정상 신호입니다. 로그도 남아 `kubectl logs`로 볼 수 있습니다. 반대로 Deployment의 파드 템플릿은 `Always`만 허용되어, 정상 종료하는 프로그램을 띄우면 계속 재시작되며 `CrashLoopBackOff`가 됩니다.

(공식 문서) Pod Lifecycle 페이지는 phase `Succeeded`를 모든 컨테이너가 성공적으로 종료되어 재시작되지 않는 상태, `Failed`를 모든 컨테이너가 종료됐고 하나 이상이 실패한(0이 아닌 종료 상태 또는 시스템에 의한 종료) 상태로 정의한다. `restartPolicy`는 Always(기본), OnFailure, Never이고, 비교 표는 종료 코드 0이면 Always만 재시작하고 0이 아닌 종료는 Always와 OnFailure가 재시작하며 Never는 재시작하지 않는다고 보여 준다. Deployment 페이지는 `.spec.template.spec.restartPolicy`로 `Always`만 허용된다고 한다. 표시 문구 `Completed`·`Error`는 Job 문서 계열의 `kubectl get pods` 출력 예시(병렬 처리 예제, Pod failure policy 예제)에 나온다. (2026-10-27 원문 확인)
(실험 확인) Docker Desktop 단일 노드 클러스터(Kubernetes v1.36.1, 런타임 docker 29.6.1)에서 `restartPolicy: Never`로 `echo hi`만 하고 끝나는 파드는 phase `Succeeded`, 컨테이너 terminated reason `Completed`, exit code 0이었고 `kubectl get`의 STATUS도 `Completed`였으며 `kubectl logs`로 `hi`가 보였다. `exit 1`로 끝나는 파드는 phase `Failed`, reason `Error`, exit code 1, STATUS `Error`였다. `restartPolicy: OnFailure`로 `echo hi`만 하는 파드는 `Completed`로 남았다. `restartPolicy`를 적지 않은(기본 `Always`) 파드와 Deployment의 파드가 `echo hi`만 하고 끝나면 `Completed`가 잠깐 보인 뒤 RESTARTS가 늘며 `CrashLoopBackOff`가 되었다. Deployment 템플릿에 `restartPolicy: Never`나 `OnFailure`를 쓰면 API 서버가 `Unsupported value: "Never": supported values: "Always"`로 거부했다. Job의 파드는 `Completed`였고 Job은 `Complete 1/1`이었다.
