**모범 답변 (30~60초)**
삭제 요청을 받은 파드가 지워지지 않는 대표 원인은 파드에 `finalizer`가 남아 있어 컨트롤 플레인이 오브젝트를 제거하지 못하는 경우입니다. 문서는 finalizer가 있는데 파드 UPDATE를 막는 어드미션 웹훅이 있어 finalizer가 제거되지 못하는 상황을 흔한 예로 듭니다. 또 컨테이너가 SIGTERM에 반응하지 않으면 유예 시간이 끝날 때까지 `Terminating`으로 보입니다. `kubectl get pod -o yaml`로 `deletionTimestamp`와 `finalizers`를 확인하고, finalizer를 지워야 할 주체(웹훅이나 컨트롤러)를 고치는 것이 정석입니다. `--grace-period=0 --force`는 kubelet 확인을 건너뛸 뿐 finalizer는 못 지우고, 실제 프로세스가 남을 수 있어 주의합니다.

(공식 문서) Debug Pods 페이지의 My pod stays terminating 절은 삭제가 요청됐는데 컨트롤 플레인이 파드 오브젝트를 지우지 못하는 상태이고, 보통 파드에 finalizer가 있는데 클러스터에 설치된 어드미션 웹훅이 finalizer 제거를 막아서 생긴다고 설명한다. 확인 방법으로 파드 `UPDATE`를 대상으로 하는 ValidatingWebhookConfiguration·MutatingWebhookConfiguration을 보라고 한다. Finalizers 페이지는 finalizer가 있는 오브젝트를 삭제하면 `deletionTimestamp`가 채워지고 오브젝트가 terminating 상태로 남으며, `metadata.finalizers`가 비면 삭제가 완료된 것으로 본다고 설명한다. Pod Lifecycle 페이지는 종료 때 기본 유예 시간 후 KILL을 보낸다고 하고, v1.27부터 kubelet이 삭제되는 파드를 API 서버에서 지우기 전에 종료 phase(`Failed` 또는 `Succeeded`)로 바꾼다고 한다. Forced Pod termination 절은 `--grace-period=0 --force` 삭제가 kubelet의 종료 확인을 기다리지 않고 API 서버에서 즉시 파드를 지워 같은 이름의 새 파드를 만들 수 있게 하지만 실행 중인 자원이 계속 돌 수 있어 위험하다고 경고한다. (2026-10-27 원문 확인)
(실험 확인) Docker Desktop 단일 노드 클러스터(Kubernetes v1.36.1, 런타임 docker 29.6.1)에서 파드에 임의의 finalizer(`exp-opsv/hold`)를 달고 `kubectl delete pod`를 하자 컨테이너가 종료된 뒤에도 파드 오브젝트가 남았고 `deletionTimestamp`가 찍혀 있었다. 컨테이너가 아직 정리 중일 때는 STATUS가 `Terminating`이었지만 컨테이너 종료 후에는 phase가 `Failed`라 `kubectl get`의 STATUS가 `Error`로 표시되었다(`Terminating` 문구만 찾으면 놓칠 수 있다). 이 상태에서 `kubectl delete pod --grace-period=0 --force`를 해도 파드는 지워지지 않고 명령이 대기했다(finalizer가 남아 있어서). `kubectl patch`로 finalizers를 비우자 파드가 즉시 사라졌다. SIGTERM을 무시하는 `sleep` 컨테이너(유예 40초)는 삭제 요청 뒤 22초가 지나도 `Terminating`이었다. 어드미션 웹훅 시나리오는 실행하지 않았다.
