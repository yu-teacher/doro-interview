**모범 답변 (30~60초)**
`kubectl exec`는 대상 컨테이너 안에서 명령을 실행하므로 셸이나 도구가 없는 최소 이미지(distroless 등)나 이미 죽은 컨테이너에는 쓸 수 없습니다. 이때는 `kubectl debug <파드> -it --image=busybox --target=<컨테이너>`로 실행 중인 파드에 임시 컨테이너를 붙입니다. 임시 컨테이너는 자원 보장도 재시작도 없고 포트나 프로브를 가질 수 없으며, 한 번 추가하면 수정하거나 지울 수 없어 디버깅 전용입니다. `--target`을 주면 대상 컨테이너와 프로세스 네임스페이스를 공유해 `ps`로 대상의 프로세스가 보입니다(런타임이 지원해야 합니다). 파드를 복사해 명령이나 이미지를 바꿔 띄우는 `--copy-to` 방식도 있어, 시작하자마자 죽는 앱을 셸로 열어 볼 때 씁니다.

```bash
kubectl debug <파드> -it --image=busybox:1.36 --target=<컨테이너> --profile=general
kubectl debug <파드> -it --copy-to=<파드>-debug --container=<컨테이너> -- sh
```

(공식 문서) Ephemeral Containers 페이지는 임시 컨테이너가 자원이나 실행 보장이 없고 자동 재시작되지 않으며, 포트·livenessProbe·readinessProbe·resources 같은 필드는 허용되지 않고, `kubectl edit`로는 추가할 수 없으며 한 번 추가하면 바꾸거나 지울 수 없다고 설명한다. distroless처럼 셸이 없는 이미지를 `kubectl exec`만으로 디버깅하기 어려울 때 쓴다고 한다. Debug Running Pods 페이지는 임시 컨테이너가 v1.25부터 Stable이고, `--target`은 컨테이너 런타임이 지원해야 하며 지원하지 않으면 프로세스가 보이지 않을 수 있다고 하고, `--copy-to`로 파드를 복사하면서 새 컨테이너를 추가하거나 명령(`--container` 지정)·이미지(`--set-image`)를 바꾸는 방법과 `--profile`(general, baseline, restricted, netadmin, sysadmin, legacy)을 설명한다. (2026-10-27 원문 확인)
(실험 확인) Docker Desktop 단일 노드 클러스터(Kubernetes v1.36.1, 런타임 docker 29.6.1)에서 nginx 파드에 `kubectl debug <파드> --image=busybox:1.36 --target=web --profile=general --container=dbg1 -- sh -c 'ps; wget -qO- localhost | head -4; sleep 3'`를 실행하자 임시 컨테이너가 붙었고 로그에 nginx master 프로세스가 PID 1로, worker들이 함께 보였으며 `wget -qO- localhost`로 nginx 응답 HTML을 받았다(`--profile=general`은 `SYS_PTRACE` 권한을 붙였다). `kubectl describe pod`에는 `Ephemeral Containers:` 절이 생겼고 끝난 임시 컨테이너는 `Completed`, 재시작 0이었다. `--target` 없이 붙인 임시 컨테이너는 `ps`에 자기 프로세스만 보였다. API로 임시 컨테이너에 `ports`·`livenessProbe`·`resources`를 넣으면 `Forbidden: cannot be set for an Ephemeral Container`였고, 이미 붙은 임시 컨테이너를 지우거나 바꾸면 `existing ephemeral containers "dbg1" may not be removed`/`may not be changed`, 일반 파드 patch로 추가하는 것도 거부되었다. 계속 죽는(`CrashLoopBackOff`) 파드에 `kubectl debug <파드> --copy-to=<사본> --container=c -- sh -c '...; sleep 600'`를 하자 사본 파드가 `Running`으로 떠 명령이 실행되었고 원본은 그대로 죽는 상태였다. `--image=busybox:1.36 --share-processes --copy-to=...`로 만든 사본에서는 `ps`에 nginx master가 보였고 `--set-image=web=busybox:1.36` 사본의 이미지가 바뀌었다. 반면 이 로컬 클러스터에서는 `kubectl exec` 자체가 `Internal error occurred: error sending request: ... http: server gave HTTP response to HTTPS client`로 실패해서 exec로 들어가는 동작은 확인하지 못했다(환경 문제로 보이며 원인은 조사하지 않았다). 그래서 `-it` 대화형 접속 대신 명령을 지정하고 로그로 확인했다.
