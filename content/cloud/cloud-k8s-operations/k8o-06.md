**모범 답변 (30~60초)**
죽은 이유는 `kubectl describe pod`의 `Last State: Terminated`에 reason과 exit code로 남습니다. 앱이 직접 `exit 3`으로 끝났다면 3과 `Error`, 존재하지 않는 실행 파일을 지정했다면 시작조차 못 해 `ContainerCannotRun`과 127(이 로컬 클러스터 기준), 메모리 한도를 넘었다면 `OOMKilled`와 137이 기록됩니다. 로그는 `kubectl logs`로 보고, 컨테이너가 재시작돼 현재 인스턴스가 새로 떠 있다면 `--previous`로 직전 인스턴스의 로그를 봅니다. 앱이 `terminationMessagePath`(기본 `/dev/termination-log`)에 쓴 마지막 메시지도 상태에 노출됩니다. 137은 시그널 9라는 리눅스 관례라 reason도 함께 봅니다.

(공식 문서) Debug Running Pods 페이지는 이전에 죽은 컨테이너의 로그를 `kubectl logs ${POD_NAME} -c ${CONTAINER_NAME} --previous`로 본다고 하고, describe 예시에서 크래시 중인 컨테이너가 `Last State: Terminated`, `Reason: Error`, `Exit Code: 1`을 보인다고 보여 준다. kubectl logs 레퍼런스는 `-p, --previous`가 파드 안 컨테이너의 이전 인스턴스 로그를 출력한다고 한다. Determine the Reason for Pod Failure 페이지는 컨테이너가 `terminationMessagePath`(기본 `/dev/termination-log`)에 쓴 짧은 메시지가 `lastState.terminated.message`에 담기며 4096바이트를 넘으면 잘린다고 설명한다. Manage Resources 페이지의 예시는 `Last State: Terminated`, `Reason: OOMKilled`, `Exit Code: 137`을 보여 준다. (2026-10-27 원문 확인)
(실험 확인) Docker Desktop 단일 노드 클러스터(Kubernetes v1.36.1, 런타임 docker 29.6.1)에서 `exit 3`으로 끝나며 stderr 메시지를 쓰고 `/dev/termination-log`에 `termmsg`를 쓴 컨테이너는 lastState가 `reason: Error, exitCode: 3, message: termmsg`였고 로그에 stderr 메시지가 나왔다. 없는 실행 파일(`/no/such/binary`)은 처음에 STATUS `RunContainerError`였다가 곧 `CrashLoopBackOff`가 되었고 Last State는 `ContainerCannotRun`, exit code 127, 메시지에 `OCI runtime create failed ... no such file or directory`가 담겼다(이 클러스터의 docker 런타임에서 관찰한 값이며 다른 런타임에서도 같은지는 확인하지 못했다 [미검증]). 반례로 `sh -c nosuchcmd-xyz`(셸은 떴지만 명령이 없음)는 reason `Error`, exit code 127이었고, 앱이 직접 `exit 137`을 해도 reason은 `Error`, 137이었다. 메모리 50Mi 한도를 넘긴 컨테이너는 `OOMKilled`, 137이었다. `--previous`는 한 번도 재시작하지 않은 파드에서는 `previous terminated container "c" ... not found`로 실패했고, 새 컨테이너가 `Running`일 때는 직전 로그를 정상 출력했지만 재시작 대기 중(`Error` 상태)일 때는 `unable to retrieve container logs for docker://...`로 실패했으며 그 구간에는 옵션 없는 `kubectl logs`가 마지막 실행의 로그를 보여 주었다. 이 동작은 이 로컬 클러스터에서 관찰한 것이다.
(보충) 137이 128에 시그널 번호 9를 더한 값이라는 설명은 리눅스 종료 코드 관례이며 이번에 읽은 문서에서 확인한 내용은 아니다. 앱이 직접 `exit 137`을 해도 137이 기록되므로(위 실험) 137만으로 OOM이라 단정하지 말고 reason을 함께 본다.
