**모범 답변 (30~60초)**
컨테이너를 만들기 전에 kubelet이 설정을 조립하다가 실패하면 `CreateContainerConfigError`가 나옵니다. 대표적으로 환경 변수를 `configMapKeyRef`나 `secretKeyRef`로 참조했는데 ConfigMap·Secret이 없거나 그 안에 키가 없는 경우입니다. 같은 누락이라도 볼륨으로 마운트했다면 마운트 단계에서 막혀 `ContainerCreating`으로 보이는 점이 다릅니다. 둘 다 원인은 `describe` 이벤트 메시지에 그대로 나오므로 이름을 외우기보다 메시지를 읽는 것이 빠릅니다. 참조를 `optional`로 표시하면 대상이 없어도 시작하고 그 변수는 설정되지 않으므로, 필수가 아닌 설정에만 써야 합니다.

```yaml
env:
- name: X
  valueFrom:
    configMapKeyRef: {name: no-such-cm, key: k}   # 없으면 CreateContainerConfigError
    # optional: true 를 붙이면 변수 없이 시작
```

(공식 문서) Configure a Pod to Use a ConfigMap 페이지의 Optional 절은 ConfigMap 참조를 optional로 표시할 수 있고, 그러면 ConfigMap이 없거나 ConfigMap은 있지만 키가 없을 때 환경 변수나 마운트된 볼륨의 해당 설정이 비게 된다(예시 출력이 빈 출력)고 설명한다. 같은 페이지의 Restrictions는 optional이 아닌데 없는 ConfigMap이나 키를 참조하면 파드가 시작하지 않는다고 하며 상태 이름은 쓰지 않는다. Volumes 페이지는 ConfigMap을 쓰기 전에 만들어야 한다고 한다. (2026-10-27 원문 확인)
(실험 확인) Docker Desktop 단일 노드 클러스터(Kubernetes v1.36.1, 런타임 docker 29.6.1)에서 (1) 없는 ConfigMap을 `configMapKeyRef`로 참조한 파드는 STATUS `CreateContainerConfigError`, 컨테이너 상태 `Waiting`, 이벤트 `Error: configmap "no-such-cm" not found`, (2) ConfigMap은 있고 키만 없는 참조는 `Error: couldn't find key nokey in ConfigMap exp-opsv/has-cm`로 같은 상태, (3) 없는 Secret을 `secretKeyRef`로 참조한 경우(`Error: secret "no-such-secret" not found`)와 `envFrom`으로 없는 ConfigMap을 참조한 경우도 같은 상태였다. (4) 같은 없는 참조에 `optional: true`를 붙인 파드(ConfigMap이 없는 경우와 키만 없는 경우 모두)는 `Running`이었고 컨테이너 출력 `X=[]`와 `env | grep -c '^X='` 결과 0으로 보아 빈 문자열이 아니라 변수 자체가 설정되지 않았다. (5) 볼륨으로 마운트한 경우는 앞 질문처럼 `ContainerCreating`과 `FailedMount`였고, `optional: true`인 볼륨 ConfigMap은 파드가 `Running`이며 마운트 디렉터리에 파일이 없었다. `CreateContainerConfigError`라는 이름은 영문 쿠버네티스 문서 `/docs/` 1,057페이지 검색에서 나오지 않아 실험으로만 확인했다.
