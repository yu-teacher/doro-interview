**모범 답변 (30~60초)**
Helm은 쿠버네티스 애플리케이션을 패키지로 설치하고 관리하는 도구입니다. 차트는 관련된 쿠버네티스 리소스를 설명하는 파일 묶음으로, 차트 정보를 담은 `Chart.yaml`, 기본 설정값을 담은 `values.yaml`, 값과 합쳐져 매니페스트가 되는 템플릿이 든 `templates/` 디렉터리로 이뤄집니다. 차트를 클러스터에 설치하면 그 인스턴스가 릴리스라는 이름으로 만들어져 관리됩니다. 환경마다 다른 값은 `-f values-prod.yaml`이나 `--set`으로 덮어쓰고, 둘을 같이 쓰면 `--set`이 우선합니다. 설치, 업그레이드, 롤백을 할 때마다 릴리스 리비전이 1씩 올라가며 `helm rollback`으로 이전 리비전으로 돌아갈 수 있습니다.

```bash
helm install myapp ./mychart -f values-prod.yaml   # 릴리스 myapp 생성(리비전 1)
helm upgrade myapp ./mychart --set image.tag=1.2.0   # 리비전 2
helm rollback myapp 1                                # 리비전 3(1번 상태로 되돌림)
```

(공식 문서) Introduction to Helm 페이지는 Helm을 쿠버네티스의 패키지 매니저로 소개하고, 차트를 쿠버네티스 애플리케이션 실행에 필요한 리소스 정의를 모두 담은 Helm 패키지로, 릴리스를 쿠버네티스 클러스터에서 실행 중인 차트의 인스턴스(한 차트를 여러 번 설치하면 릴리스 이름이 다른 릴리스가 각각 생김)로 설명하며, 릴리스는 패키지된 차트에 값(보통 `values.yaml`)을 병합해 만든다고 한다. Helm Charts 문서는 차트 디렉터리 구조로 `Chart.yaml`(차트 정보), `values.yaml`(차트의 기본 설정값), `templates/`(값과 결합해 유효한 쿠버네티스 매니페스트를 만드는 템플릿), `charts/`(의존 차트), `crds/`를 든다. 같은 문서는 차트를 관련된 쿠버네티스 리소스 집합을 설명하는 파일 모음으로 정의하며 정해진 디렉터리 구조로 만들고 버전이 붙은 아카이브로 패키징할 수 있다고 한다. Using Helm 페이지는 `helm install`이 사용자가 정하는 릴리스 이름과 차트 이름을 받으며 차트를 설치하면 새 릴리스 오브젝트가 만들어진다고 하고, `--values(-f)`는 여러 번 줄 수 있고 오른쪽 파일이 우선하며 `--set`과 함께 쓰면 `--set`이 더 높은 우선순위를 가진다고 한다. 릴리스 버전은 증가하는 리비전으로 install, upgrade, rollback 때마다 1씩 오르고 첫 값은 1이며 `helm history`로 본다고 한다. Quickstart 페이지에 표시된 문서 버전은 Helm 4.3.1이다. (2026-10-27 원문 확인)
이 환경에는 Helm이 설치되어 있지 않아 위 명령은 실행하지 않았다(문서 근거만). 예시 코드는 문서의 설명을 바탕으로 쓴 것이다.
