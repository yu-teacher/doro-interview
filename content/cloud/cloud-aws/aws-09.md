**모범 답변 (30~60초)**
S3는 객체 스토리지입니다. 데이터를 객체 데이터와 메타데이터로 버킷에 저장하고, 버킷 이름과 객체 키, 버전 관리를 켰다면 버전 ID까지 합친 것으로 객체를 식별합니다. 그래서 파일 시스템처럼 마운트하는 것이 아니라 키로 가져오는 저장소이고, 용량을 미리 정하지 않아도 얼마든지 저장할 수 있습니다. 버킷과 객체는 기본적으로 비공개라서 권한을 명시적으로 줘야 접근됩니다. 반면 EBS는 EC2 인스턴스에 연결해 로컬 디스크처럼 쓰는 블록 스토리지라서 운영체제가 마운트해 파일 시스템을 올리는 용도에 맞습니다. 정적 파일이나 백업처럼 객체 단위로 꺼내 쓰는 데이터는 S3에, 서버의 디스크가 필요하면 EBS를 씁니다.

(공식 문서) S3 소개 페이지는 S3를 확장성·가용성·보안·성능이 뛰어난 객체 스토리지 서비스로 소개한다. 객체는 데이터와 메타데이터로 이루어지고 키가 버킷 안에서의 고유 식별자이며, 버킷+키+(선택) 버전으로 객체를 특정한다고 한다. 버킷과 객체는 기본적으로 비공개이고 명시적으로 권한을 줘야 접근할 수 있다고 한다. 버전 관리를 켜면 실수로 삭제하거나 덮어쓴 객체를 복구할 수 있다.
(공식 문서) EBS 페이지는 EBS 볼륨을 인스턴스에 붙여 로컬 하드 드라이브처럼 쓰는 블록 스토리지로 설명한다.
(보충) 파일 시스템처럼 마운트하지 않는다는 서술은 두 서비스의 정의를 대비한 일반적 설명이다.
실험하지 않았다. 클라우드 계정이 없어 문서 근거로만 썼다.
