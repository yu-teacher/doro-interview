**모범 답변 (30~60초)**
REST는 Roy Fielding이 박사논문에서 웹의 구조를 설명하며 제시한 아키텍처 스타일로, 특정 프로토콜이나 데이터 형식이 아니라 제약 조건의 묶음입니다. 제약은 클라이언트와 서버의 분리, 요청마다 필요한 정보를 모두 담는 무상태 통신, 응답이 캐시 가능한지 표시하는 캐시 제약, 균일 인터페이스, 계층형 시스템이고, 코드 온디맨드는 선택 사항입니다. 균일 인터페이스는 다시 리소스 식별, 표현을 통한 리소스 조작, 자기 서술적 메시지, 애플리케이션 상태 엔진으로서의 하이퍼미디어 네 가지로 나뉩니다. 제약마다 얻는 성질과 치르는 비용이 함께 있다는 점까지 말하면 좋습니다.

(원저자 자료) Fielding 박사논문 5장 5.1절은 아무 제약이 없는 상태에서 출발해 클라이언트-서버, 무상태, 캐시, 균일 인터페이스, 계층형 시스템, 코드 온디맨드 제약을 차례로 더하는 방식으로 REST를 유도한다. 5.1.2는 클라이언트-서버를 관심사 분리로 설명하며 UI 이식성, 서버 단순화, 구성요소의 독립적 진화를 이점으로 든다. 5.1.5는 균일 인터페이스가 REST를 다른 네트워크 기반 스타일과 구별하는 핵심 특징이라 하고, 네 가지 인터페이스 제약(리소스 식별, 표현을 통한 리소스 조작, 자기 서술적 메시지, 애플리케이션 상태 엔진으로서의 하이퍼미디어)으로 이루어진다고 하면서, 정해진 형식으로 전송하기 때문에 효율은 떨어진다는 대가도 적는다. 5.1.7은 코드 온디맨드가 가시성을 낮추므로 REST에서 선택적 제약이라고 한다. 5.3.2는 REST가 특정 프로토콜에 통신을 한정하지 않고 구성요소 사이의 인터페이스를 제약하는 것이며 웹의 주된 전송 프로토콜이 HTTP라고 설명한다.
이 질문은 개념 설명이라 실험하지 않았고 논문 5장 본문만 근거로 썼다.
