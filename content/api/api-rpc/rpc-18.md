**모범 답변 (30~60초)**
쿼리의 필드는 실행 순서가 결과에 영향을 주지 않아야 해서 서버가 순서를 자유롭게, 보통 병렬로 실행합니다. 반면 뮤테이션의 최상위 필드는 부수 효과가 있어서 스펙이 직렬로 실행하라고 하므로, 앞 필드가 끝난 뒤 다음이 시작되어 한 요청 안에서 경쟁 상태가 생기지 않습니다. 하지만 이것은 데이터베이스 트랜잭션이 아닙니다. 일부 필드는 성공하고 다른 필드는 에러가 날 수 있고, GraphQL이 이미 성공한 부분을 되돌릴 방법은 없습니다. 원자성이 필요하면 하나의 뮤테이션 필드 안에서 비즈니스 로직이 트랜잭션으로 처리하도록 설계해야 합니다.

(공식 문서) Mutations 페이지는 쿼리 필드는 병렬로, 뮤테이션 필드는 직렬로 실행되며 이 직렬 실행이 한 요청 안의 경쟁 상태를 막지만 데이터베이스 트랜잭션과는 다르다고 설명한다. 일부 뮤테이션 필드는 성공하고 다른 필드는 오류를 반환할 수 있으며 GraphQL이 성공한 부분을 되돌릴 방법이 없다고 한다.
(공식 문서) 스펙(2021년 10월판 6.2.2 Mutation, 6.3.1)은 뮤테이션의 최상위 선택 집합을 직렬로 실행해야 하고(should), 일반 실행에서는 최상위 뮤테이션 필드 외 필드의 해석이 부수 효과가 없고 멱등이어야 하므로 서버가 실행 순서를 자유롭게 정할 수 있다고 한다. 현행 초안도 같은 서술이다.
(보충) 원자성이 필요할 때 단일 뮤테이션 필드 안에서 비즈니스 계층이 트랜잭션을 처리하라는 조언은 일반적인 설계 원칙이다. 실제 서버로 직렬 실행을 돌려 보지는 않았다(graphql-js 없음).
