**모범 답변 (30~60초)**
AIP-158은 페이지 크기 `page_size`를 필수로 만들지 말라고 합니다. 값을 생략하거나 0을 보내면 오류 없이 서버가 정한 기본값을 쓰고 그 값을 문서에 적는 것이 좋다고 하며, 최대값보다 크게 보내면 최대값으로 낮춰 처리하라고 권고합니다. 음수는 잘못된 인자 오류로 거절합니다. 또 서버는 요청한 개수보다 적게, 심지어 0개를 주고도 마지막 페이지가 아닐 수 있습니다. 그래서 클라이언트는 개수가 적다고 끝났다고 판단하지 말고 다음 페이지 토큰이 비었는지로 끝을 판단해야 합니다. 페이지 크기는 중간에 바꿔도 되지만 필터 같은 다른 인자는 그대로 둬야 합니다.

(공식 문서) AIP-158은 `page_size`를 필수로 두면 안 되고(must not), 생략하거나 0이면 API가 적당한 기본값을 고르고(문서화 권고) 오류를 내면 안 된다고 한다. 최대치를 넘으면 최대치로 낮추는 것을 권고(should)하고, 음수면 `INVALID_ARGUMENT` 오류를 보내야 한다(must)고 한다. 요청한 개수보다 적게(0개 포함) 돌려줄 수 있고, 끝에 이르렀을 때만 `next_page_token`이 비어야 한다고 한다. 페이지를 넘기는 중 `page_size`를 바꾸면 서버는 새 크기를 따라야 하고, 다른 인자가 바뀌면 오류를 보내는 것을 권고한다. AIP-132는 `page_size` 주석에 최대값과 생략 시 기본값을 문서화하라고 한다. 예시 주석은 기본 50개, 최대 1000개다.
(실험하지 않았다) 위 동작은 문서 근거만으로 적었다.
