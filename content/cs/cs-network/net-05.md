**모범 답변 (30~60초)**
IPv4 주소는 32비트 값이고 앞부분은 네트워크를 가리키는 프리픽스, 나머지는 그 네트워크 안의 호스트를 가리킵니다. 서브넷 마스크나 CIDR 표기의 /24는 앞쪽 몇 비트가 프리픽스인지를 나타내며, 192.168.1.0/24는 앞 24비트가 네트워크이고 뒤 8비트로 주소 256개를 가집니다. 호스트 부분이 전부 0이거나 전부 1인 주소는 특별한 용도라서 보통 호스트에 못 쓰므로 /24에서 쓸 수 있는 호스트는 254개입니다. 옛 A·B·C 클래스 대신 임의 길이의 프리픽스를 쓰는 것이 CIDR이고, 라우터는 여러 경로가 겹치면 가장 긴 프리픽스가 맞는 경로를 고릅니다. 같은 서브넷인지는 마스크로 걸러낸 네트워크 부분이 같은지로 판단합니다.

(공식 문서) RFC 4632 §3은 클래스 A/B/C 대신 명시적 길이의 클래스리스 프리픽스를 쓴다고 하고, §3.1은 CIDR 표기를 '주소/유효 비트 수(0~32)'로 정의하며 172.16.0.0/16이 마스크 255.255.0.0, 192.168.99.0/24가 상위 24비트가 1인 마스크라는 예를 든다. 크기 표에서 /24=256개, /16=65,536개, /32는 단일 호스트 경로, /31은 점대점 링크다. 인터넷 포워딩이 최장 일치(longest match) 기준이라는 서술은 §5.1에 있다. RFC 1122 §3.2.1.3은 {네트워크, 호스트} 주소에서 호스트 번호가 전부 1(-1)인 값을 디렉티드 브로드캐스트로 정하고, 나열된 특수 경우를 빼면 호스트·네트워크·서브넷 번호 필드가 0이나 -1 값을 가질 수 없다고 한다. 이 규칙이 클래스·서브넷 시절 문서이고 CIDR 이전이라는 점은 주의가 필요하다. RFC 3021 §1은 일반 서브넷이 '호스트 2개 + 전부 0 네트워크 + 전부 1 브로드캐스트'로 링크당 4개 주소를 쓴다고 서술하며(그래서 /24는 254개), 점대점 링크에 한해 31비트 마스크 사용을 허용한다.
(실험 확인) Python 3.14.0 ipaddress 모듈로 계산했다. 192.168.1.0/24는 마스크 255.255.255.0, 주소 256개, 네트워크·브로드캐스트를 뺀 호스트 254개였고, 192.168.1.77/26의 네트워크는 192.168.1.64/26(브로드캐스트 .127)이었다. 192.168.1.10과 192.168.1.70은 /26 기준으로 서로 다른 서브넷이었다. /24를 /26으로 나누면 4개이고 192.168.0.0/24와 192.168.1.0/24는 192.168.0.0/23 하나로 합쳐졌다. 경로표(0.0.0.0/0, 10.0.0.0/8, 10.1.0.0/16, 10.1.2.0/24)에서 최장 일치를 직접 구현해 10.1.2.9는 /24, 10.1.9.9는 /16, 10.9.9.9는 /8, 8.8.8.8은 기본 경로를 고르는 것을 확인했다.
