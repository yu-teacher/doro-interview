**모범 답변 (30~60초)**
FCFS는 도착 순서대로 처리해 단순하지만 긴 작업 뒤에 짧은 작업이 줄줄이 기다리는 호위 효과가 있습니다. SJF는 짧은 작업부터 돌려 동시 도착 가정에서는 평균 대기 시간이 최소지만 실행 시간을 미리 알아야 하고 긴 작업이 굶을 수 있습니다. RR은 타임 퀀텀씩 번갈아 실행해 응답성이 좋지만 퀀텀이 너무 작으면 전환이 잦아집니다. 우선순위 방식은 낮은 작업이 굶을 수 있어 오래 기다린 작업의 우선순위를 올리는 에이징을 씁니다. MLFQ는 큐를 여러 개 두고 CPU를 오래 쓴 작업을 아래 큐로 내려 짧은 대화형 작업을 유리하게 합니다.

(공식 문서) sched(7)는 리눅스가 정적 우선순위별 실행 가능 리스트를 두고 가장 높은 우선순위의 비어 있지 않은 리스트에서 머리의 스레드를 고르며 모든 스케줄링이 선점형이라고 설명한다. 실시간 정책 SCHED_FIFO는 시간 분할 없이 같은 우선순위 안에서 FIFO로, SCHED_RR은 같은 방식에 시간 퀀텀을 더해 퀀텀을 다 쓰면 같은 우선순위 리스트의 끝으로 보낸다고 하고, 일반 정책 SCHED_OTHER는 실행 가능한데 못 돈 퀀텀마다 동적 우선순위를 올려 공정한 진행을 보장한다고 한다.
(실험 확인) 아래는 파이썬 모의 계산이며 실제 스케줄러가 아니다. 작업 P1=24, P2=3, P3=3(동시 도착, 단위 임의)의 평균 대기 시간은 FCFS(P1,P2,P3 순) 17.0, 짧은 것부터 하는 SJF(P2,P3,P1 순) 3.0, RR 퀀텀 4 또는 1일 때 약 5.67이었고 RR 퀀텀 1에서는 작업 전환이 9번, 퀀텀 4에서는 3번이었다. 동시 도착·비선점 가정에서 무작위 작업 묶음 200개를 모든 실행 순서와 전수 비교하자 SJF 순서가 항상 최소 평균 대기 시간이었다. 100 단위 작업 10개의 RR은 퀀텀 1, 5, 50, 1000에서 전환이 각각 999, 199, 19, 9번이었다. 짧은 작업이 매 틱 새로 도착하는 SJF 모의에서 길이 50인 작업은 1000틱이 지나도 한 번도 실행되지 못했고(기아), 우선순위를 남은 길이 − 0.5×대기 시간으로 하는 에이징을 쓰면 틱 148에 끝났다. 단순한 MLFQ 모의(큐 3개, 퀀텀 2/4/8, 퀀텀을 다 쓰면 강등)에서 길이 60 작업과 10틱마다 오는 길이 2 작업 5개를 돌리면 짧은 작업이 8, 18, 28, 38, 48에 끝났고(FCFS는 62~70) 긴 작업은 60 대신 70에 끝났다.
(원저자 자료) OSTEP 스케줄링 입문 장(cpu-sched)은 FIFO(FCFS)가 단순해 구현하기 쉽지만, 긴 작업이 앞에 있으면 짧은 작업이 줄줄이 기다려 평균 반환 시간이 나빠지는 호위 효과가 있다고 한다(100초 작업 뒤에 10초 작업 둘이면 평균 110초). 가장 짧은 작업부터 하는 SJF는 같은 예에서 평균을 50초로 줄이고, 모든 작업이 동시에 도착한다는 가정 아래에서는 평균 반환 시간이 최적이라고 하되 증명은 생략한다. 다만 SJF는 작업 길이를 안다고 가정하고, 응답 시간에는 좋지 않다. RR은 타임 슬라이스만큼 돌고 다음 작업으로 넘어가 응답 시간에 좋지만, 슬라이스를 너무 짧게 하면 컨텍스트 스위치 비용이 성능을 좌우하게 되고(10ms 슬라이스에 전환 1ms면 약 10% 낭비) 반환 시간은 매우 나쁘다고 하며, 공정성과 반환 시간은 서로 맞바꾸는 관계라고 설명한다. MLFQ 장(cpu-sched-mlfq)은 우선순위가 다른 여러 큐를 두고 높은 큐의 작업을 먼저 실행하며 같은 큐 안에서는 RR로 돌린다고 한다. 새 작업은 최상위 큐에 넣고, 할당 시간을 다 쓰면 한 단계 내려보내고, I/O 등으로 CPU를 일찍 내놓으면 우선순위를 유지해서, 작업 길이를 미리 모르는 채 짧은 대화형 작업을 우대하여 SJF를 근사한다고 한다. 대화형 작업이 많으면 긴 작업이 CPU를 전혀 받지 못하는 기아가 생기므로, 일정 시간마다 모든 작업을 최상위 큐로 올리는 우선순위 부스트를 둔다고 한다. 멀티프로세서 스케줄링 장(cpu-sched-multi)은 리눅스에 O(1) 스케줄러(MLFQ와 비슷한 우선순위 기반), CFS(결정적 비례 지분 방식), BFS가 등장했다고 적는다.
(보충) SJF가 평균 대기 시간을 최소로 한다는 서술은 OSTEP이 반환 시간 기준으로 말한 것과 지표가 다르며, 동시 도착에서 두 지표가 같은 순서를 최적으로 만든다는 연결은 책에 직접 없고 위 실험(모의 입력)으로만 확인했다. SJF에서 긴 작업이 굶을 수 있다는 서술도 책에 없고 위 모의 실험으로만 확인했다.
