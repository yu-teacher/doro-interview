**모범 답변 (30~60초)**
가상 메모리는 프로그램이 물리 메모리의 실제 배치를 몰라도 되도록 해 주는 추상화입니다. 프로그램이 메모리를 읽고 쓸 때 쓰는 주소는 전부 가상 주소이고, CPU의 MMU가 페이지 테이블을 보고 이것을 물리 주소로 변환합니다. 이 덕분에 흩어진 물리 메모리를 연속된 것처럼 보여 줄 수 있고, 지금 필요한 부분만 물리 메모리에 올리는 요구 페이징이 가능하며, 프로세스마다 주소 공간을 따로 줘서 서로를 보호하면서도 필요한 부분은 통제된 방식으로 공유할 수 있습니다.

(공식 문서) Linux 커널 문서의 Concepts overview(Virtual Memory Primer)는 가상 메모리가 물리 메모리의 세부 사항을 응용 프로그램에서 감추고, 필요한 정보만 물리 메모리에 두게 하며(요구 페이징), 프로세스 간 데이터 보호와 통제된 공유를 제공한다고 설명한다. 모든 메모리 접근은 가상 주소로 이루어지고 CPU가 이를 물리 주소로 번역하며, 물리 페이지 하나가 하나 이상의 가상 페이지로 매핑될 수 있다고 한다. Compaction 절은 가상 메모리 덕분에 흩어진 물리 페이지를 가상으로 연속된 범위로 보여 줄 수 있다고 한다. 매핑을 기술하는 것이 계층형 페이지 테이블이고 MMU가 번역을 맡으며, 사용자 프로세스마다 자기 메모리 컨텍스트(최상위 테이블 pgd)를 가진다고 page_tables 문서가 설명한다.
(실험 확인) macOS(Apple Silicon)에서 최적화를 끄고 컴파일한 C 프로그램으로 확인했다. `fork()` 직후 부모와 자식이 같은 가상 주소 `p`를 가졌는데, 자식이 `p[0]`을 'B'로 바꿔도 부모의 `p[0]`은 'A' 그대로였다. 같은 가상 주소가 프로세스마다 다른 물리 메모리를 가리킬 수 있다는 뜻이다. 같은 머신(RAM 24GB)에서 `malloc` 16GB도 성공했고, 그중 한 바이트를 쓰자 페이지 폴트가 1번만 났다. 요청한 만큼의 물리 메모리를 미리 쓰지 않는다는 뜻이다.
