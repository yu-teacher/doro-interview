**모범 답변 (30~60초)**
빅오는 입력 크기 n이 커질 때 실행 시간이나 메모리가 늘어나는 정도의 점근적 상한입니다. 양의 상수 c와 임계값 k가 있어서 n이 k 이상이면 f(n)이 c·g(n) 이하일 때 f는 O(g)라고 합니다. Ω는 반대로 하한이고, Θ는 위아래 모두 상수배로 묶이는 같은 차수를 뜻합니다. 그래서 n²+3n+4는 O(n²)이고, 3n+4처럼 더 작은 함수도 엄밀히는 O(n²)라 해도 틀리지 않으니 딱 맞는 차수를 말하려면 Θ를 써야 합니다. 또 최악인지 평균인지 어떤 경우를 재는지는 따로 밝혀야 합니다.

(공식 문서) NIST DADS는 f(n) = O(g(n))을 "양의 상수 c와 k가 있어 모든 n ≥ k에서 0 ≤ f(n) ≤ c·g(n)"으로 정의하고, 3n + 4도 엄밀히는 O(n²)이며 "딱 맞는" 경계는 Θ로 표현한다고 설명한다. Ω는 하한(0 ≤ c·g(n) ≤ f(n)), Θ는 상수 c₁, c₂로 위아래가 모두 묶이는 점근적으로 꼭 맞는 경계로 각각 정의되어 있다. 최악의 경우는 알고리즘이 가장 많은 시간·자원을 쓰게 하는 입력, 평균 경우는 모든 경우의 수학적 평균으로 따로 정의한다.
(실험 확인) NIST의 예인 n² + 3n + 4 < 2n²을 n = 1~10,000 전 구간에서 파이썬으로 검사했더니 n ≥ 5에서 모두 성립했고 n ≤ 4에서만 성립하지 않았다. NIST가 든 "n > 10"은 그 뒤로 항상 성립하는 한 가지 임계값이며, 정의의 k는 이렇게 어떤 값이든 하나 존재하면 된다는 점이 보인다.
