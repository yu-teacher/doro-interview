**모범 답변 (30~60초)**
이진 힙은 완전 이진 트리라서 포인터 없이 배열에 담을 수 있고, 0부터 세면 인덱스 k의 자식은 2k+1과 2k+2, 부모는 (k-1)을 2로 나눈 몫입니다. 삽입은 맨 끝에 넣고 부모와 비교하며 올리는 sift-up, 꺼내기는 루트에 마지막 원소를 두고 내려보내는 sift-down이고 둘 다 트리 높이만큼이라 O(log n)입니다. 이미 n개가 있다면 하나씩 넣는 대신 마지막 내부 노드부터 거꾸로 sift-down하는 bottom-up heapify로 힙을 만들면 선형 시간에 끝나는데, 아래 노드일수록 내려갈 거리가 짧기 때문입니다.

(공식 문서) NIST DADS는 이진 힙을 배열로 효율적으로 구현할 수 있고 1부터 세면 인덱스 i의 자식은 2i, 2i+1, 부모는 i/2라고 하며 삽입이 O(log₂ n)이라고 한다. 두 이진 힙의 병합은 O(n)으로, 두 힙 배열을 이어 붙이고 그 결과로 힙을 만드는 것이 최선이라고 한다. Python `heapq` 문서는 0부터 세는 인덱스에서 `a[k] <= a[2*k+1]`, `a[k] <= a[2*k+2]`가 성립하는 배열이 힙이라고 하고, `heapify`가 리스트를 제자리에서 선형 시간에 최소 힙으로 바꾼다고 한다.
(실험 확인) 파이썬으로 sift-up/sift-down 최소 힙을 직접 구현하고 값 비교 횟수를 셌다. 무작위 순서 n = 100,000개를 하나씩 `push`하면 227,783번(2.28n), 같은 데이터에 bottom-up heapify는 187,845번(1.88n)이었다. 내림차순 입력(최소 힙에 최악)에서는 `push`가 1,468,946번(14.7n)이었고 heapify는 199,978번(2.00n)이었다. n = 1,000, 10,000, 100,000 모두 heapify의 비교 횟수는 2n 이하였다. 힙에서 전부 꺼내는 데는 n = 100,000에서 2,831,365번(약 1.70·n·log₂n)이었다.
(원저자 자료) Open Data Structures 10.1절은 힙이 완전 이진 트리라서 높이 h가 log n 이하이고, 그래서 꺼내기(`trickleDown`)와 삽입이 모두 O(log n)이라고 설명한다. 11.1.3절은 n번 삽입하면 O(n log n)이지만, 자식이 없는 뒤쪽 절반을 건너뛰고 n/2-1번부터 0번까지 거꾸로 `trickleDown`하면 더 빨리 구성할 수 있다고 한다. 하위 힙의 높이가 1인 노드는 n/4개, 2인 노드는 n/8개처럼 높은 노드일수록 적고 `trickleDown`의 일은 높이에 비례하므로 총 일이 i·n/2^i의 합으로 묶여 O(n)이 된다고 증명한다.
