**모범 답변 (30~60초)**
해시 테이블은 키를 해시 함수에 넣어 나온 값으로 배열 위치를 정해서 저장하고 찾는 사전 구조입니다. 서로 다른 키가 같은 위치로 가는 것을 충돌이라 하고, 해결 방식은 크게 둘로 나뉩니다. 체이닝은 같은 위치에 연결 리스트 같은 구조로 항목을 이어 붙이고, 개방 주소법은 모든 항목을 테이블 안에 두고 충돌하면 다른 위치를 차례로 탐사합니다. 해시가 고르게 퍼지고 테이블이 충분히 크면 조회가 평균적으로 상수 시간이지만, 충돌이 한곳에 몰리면 느려집니다.

(공식 문서) NIST DADS는 해시 테이블을 키를 해시 함수로 배열 위치에 대응시키는 사전으로 정의하고, 충돌 해결을 개방 주소법, 체이닝, 별도 오버플로 영역으로 나눈다. 복잡도는 해시 함수와 충돌 해결 방식에 달려 있고 테이블이 충분히 크거나 커지면 상수가 될 수 있다고 한다. Java `HashMap` 문서는 해시 함수가 요소를 버킷에 고르게 퍼뜨린다는 가정에서 `get`·`put`이 상수 시간이라고 하고, C++ 표준 초안의 unordered 컨테이너 요구사항은 `find`를 평균 O(1), 최악 O(size)로 적는다.
(실험 확인) 모든 키의 `hashCode`가 같은 클래스로 Corretto 25.0.3 `HashMap`에 2,000개를 넣었더니 `equals` 호출이 약 202만 번(n²/2=200만 근처, 정확한 횟수는 실행마다 조금 다르다)이었고, 고르게 퍼지는 해시로는 0번이었다. CPython 3.14.0 `dict`에서 `__hash__`가 전부 1인 키 2,000개를 넣을 때 `__eq__` 호출은 1,999,000번(=n(n-1)/2)이었다.
