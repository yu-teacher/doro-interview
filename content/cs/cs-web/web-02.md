**모범 답변 (30~60초)**
401은 요청에 유효한 인증 자격 증명이 없어서 처리하지 않았다는 뜻이고, 표준에 따르면 401 응답에는 사용할 인증 방식을 알려 주는 WWW-Authenticate 헤더가 반드시 있어야 합니다. 클라이언트는 새 자격 증명을 실어 다시 요청할 수 있습니다. 403은 서버가 요청을 이해했지만 수행을 거부한다는 뜻이고, 자격 증명을 보냈다면 그것으로는 부족하다고 판단했다는 의미라서 같은 자격 증명으로 자동 재시도하지 말라고 권고됩니다. 그래서 로그인이 안 됐거나 토큰이 유효하지 않으면 401, 요청은 알아듣지만 허용하지 않으면 403으로 나눕니다. 리소스가 있다는 사실 자체를 숨기고 싶으면 403 대신 404를 써도 됩니다.

```
GET /me                        -> 401, WWW-Authenticate: Basic realm="x"
GET /admin  (Authorization 있음) -> 403
GET /admin  (Authorization 없음) -> 401
```

(공식 문서) RFC 9110 15.5.2는 401을 요청이 대상 리소스에 대한 유효한 인증 자격 증명이 없어서 적용되지 않았다는 뜻이라 하고, 401을 만드는 서버는 적용 가능한 챌린지가 담긴 WWW-Authenticate 헤더를 MUST 보내야 한다고 한다. 자격 증명을 보낸 요청에 401이 오면 그 자격 증명에 대한 인가가 거부됐다는 뜻이고 클라이언트는 새 자격 증명으로 다시 요청할 수 있다. 15.5.4는 403을 서버가 요청을 이해했지만 수행을 거부한다는 뜻이라 하고, 자격 증명이 있었다면 서버가 그것을 불충분하다고 본 것이며 클라이언트는 같은 자격 증명으로 자동 반복하지 말아야(SHOULD NOT) 하고, 자격 증명과 무관한 이유로도 금지될 수 있다고 한다. 같은 절은 금지된 리소스의 존재를 숨기려는 서버가 404로 응답해도 된다고(MAY) 한다.
(실험 확인) 위 블록은 Python 3.14 로 만든 연습용 서버에 curl 8.7.1 로 요청한 결과다. 어느 경로가 401이고 어느 경로가 403인지는 내 서버가 정한 규칙이다.
