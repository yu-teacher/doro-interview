**모범 답변 (30~60초)**
URI에서 ?, &, =, /, # 같은 예약 문자는 구성 요소를 나누는 구분자로 쓰이기 때문에, 이 문자를 구분자가 아니라 데이터로 쓰려면 퍼센트 인코딩을 해야 합니다. 방법은 해당 바이트를 % 뒤에 16진수 두 자리로 적는 것이고, 공백은 %20이 됩니다. 한글 같은 문자는 먼저 UTF-8 바이트로 바꾼 다음 바이트마다 인코딩하는 것이 보통이고, RFC 도 새 스킴의 텍스트 구성 요소에 그렇게 하라고 권합니다. 영문자, 숫자, 하이픈, 마침표, 밑줄, 틸데는 비예약 문자라 그대로 두면 됩니다. 인코딩은 URI를 조립할 때 구성 요소별로 한 번만 해야 하고, 이미 인코딩된 문자열을 또 하면 %가 %25로 바뀌어 값이 깨집니다.

```
a b&c=한/글?x#y
quote(safe='')   : a%20b%26c%3D%ED%95%9C%2F%EA%B8%80%3Fx%23y
quote(safe='/')  : a%20b%26c%3D%ED%95%9C/%EA%B8%80%3Fx%23y
이중 인코딩      : quote(quote("a b")) = a%2520b
```

(공식 문서) RFC 3986 2.1은 인코딩 형식을 % 다음 16진수 두 자리로 정의하고 16진수 대소문자는 같다고 하며, 생성자는 대문자를 쓰라고 권한다. 2.2는 예약 문자(gen-delims와 sub-delims)를 구분자로 쓰이는 문자로 정의하고, 데이터가 구분자 역할과 충돌하면 먼저 퍼센트 인코딩해야 한다고 하며, 예약 문자를 인코딩된 것으로 바꾸면 URI가 동등하지 않다고 한다. 2.3은 비예약 문자를 알파벳, 숫자, -, ., _, ~로 정의하고 이들의 인코딩형과 원문자형은 동등하다고 한다. 2.4는 인코딩은 URI를 구성 요소로 조립할 때 하고, 같은 문자열을 두 번 인코딩하거나 디코딩하면 안 된다고 한다. 2.5는 새 URI 스킴이 텍스트 구성 요소를 정의할 때는 UTF-8로 인코딩한 뒤 비예약 문자가 아닌 바이트만 퍼센트 인코딩하라고 한다.
(실험 확인) 위 블록은 Python 3.14 의 urllib.parse.quote 출력이다. Node v24.16.0 의 encodeURIComponent 는 safe='' 와 같은 결과였다. 두 함수가 어느 문자를 남기는지는 각 구현의 규칙이다.
(보충) 2.5의 UTF-8 권고는 새 스킴에 대한 것이고, http URL 에서 UTF-8 이 실제로 쓰이는 것은 관행이다. 폼 제출에서 공백을 +로 쓰는 것은 HTML 폼 인코딩 관행이며 RFC 3986 의 일반 규칙이 아니다. Python quote_plus('a b') 가 'a+b' 를 내는 것은 확인했지만 이 방식 자체는 이번에 읽은 문서에 근거가 없다.
