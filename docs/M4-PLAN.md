# M4 상세 계획: 내 질문 추가 (사용자 전용 질문)

> 상태: **초안 (2026-10-20)** — §9 의 결정(Q1~Q6)을 사용자가 확정하면 S1 부터 구현한다. 기준: [DESIGN.md](DESIGN.md) §6~§9·§12, [M3-PLAN.md](M3-PLAN.md)(시험·후보·PUT 규칙), [M2-PLAN.md](M2-PLAN.md)(노트·탈퇴 동기화).
> **M4 의 방향을 바꿨다.** 원래 M4 는 "편집자 화면 + Guard"였다. 공용 사전의 주제·질문은 앞으로도 AI 가 공식 문서를 근거로 만들어 **파일로 배포**하고(배포마다 DB 에 다시 반영되므로 화면 수정은 덮어쓰인다), 화면에서 고칠 사람은 사용자 한 명뿐이라 편집자 화면·Guard 는 만들지 않는다. 대신 강사님이 짚어 준 질문처럼 **내가 직접 더하고 싶은 질문**을 내 계정 안에서 추가·시험에 쓰게 한다.

## 1. 목표와 비목표

**목표**: 로그인한 사용자가 자기만 보는 질문을 추가·수정·삭제하고(제목, 내 답, 키워드, 난이도, 출처 표시 예: "강사 추천"), 공용 질문과 똑같이 **체크 → 랜덤 시험 → 다시 공부 후보**에 쓴다.

**비목표**: 다른 사람과 공유·공개, 가져오기 파일·AI 생성, 마크다운 렌더링(일반 텍스트만), 폴더·태그·주제 분류, 공용 사전의 편집, Guard·편집자 역할, 공용 검색에 내 질문 섞기, 내 질문에 대한 노트(내 답이 이미 내 글이다).

## 2. 가정 (착수 전 확인할 것)

| # | 가정 | 확인 방법 |
|---|---|---|
| A1 | 게이트웨이는 쓰기를 `PUT` 만 통과시킨다(DELETE·POST 는 403). 그래서 추가·수정·삭제 모두 PUT 이어야 하고 **서버·Doro 레포 변경이 없다** | S4 의 통합 e2e(게이트웨이 경유) |
| A2 | `quiz_*`·`user_progress` 는 질문을 `question_slug`(VARCHAR 60)로만 가리키고 외래키가 없다. 내 질문의 slug 를 `my-<UUID>`(39자)로 하면 스키마 변경 없이 담긴다 | S1 스키마 시험 |
| A3 | 시험은 질문이 사라진 경우를 이미 안전하게 다룬다(제목 없음 → "더 이상 공개되지 않는 질문", 건너뛰기만 가능, M3). 내 질문을 지워도 지난 시험 기록이 깨지지 않는다 | M3 `QuizServiceTest`, S3 에서 재확인 |
| A4 | 공용 응답(카테고리·주제·질문·검색)은 공개 캐시·ETag 대상이다. 내 질문이 여기에 섞이면 남에게 새거나 캐시가 오염된다 → **내 질문은 전용 엔드포인트로만** 읽는다 | S2 의 `ApiSurfaceTest`·캐시 헤더 시험 |

## 3. 결정 (권장안; 사용자 확인 대상은 §9)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **새 모듈 `mine`** 이 `my_question` 을 소유한다. `catalog` 는 사용자 상태가 없는 공용 읽기 전용으로 그대로 둔다 | 공용 콘텐츠와 사용자 글의 소유·노출 경계를 코드 구조로 고정한다 |
| D2 | **slug = `my-<UUID>`**, id 는 **클라이언트가 만든 UUID**(M3 와 같다). 같은 id 로 다시 보내면 같은 질문을 갱신(멱등) | 게이트웨이의 PUT 전용 규칙을 따르고 더블 전송이 중복을 만들지 않는다 |
| D3 | 쓰기는 전부 PUT: `PUT /api/v1/mine/{id}`(만들기·전체 교체), `PUT /api/v1/mine/{id}/deleted {deleted:true}`(삭제), 일괄 `PUT /api/v1/mine`(최대 50개) | DELETE 는 게이트웨이가 막는다(A1). 삭제는 행을 지우고 지난 시험 기록은 A3 대로 남는다 |
| D4 | 필드: 제목 1~200자(필수), 내 답 0~4,000자, 키워드 0~10개(각 1~40자), 난이도 `BASIC/DEEP/TRICKY`(기본 BASIC), 출처 표시 0~40자(예: "강사 추천"). 전부 **일반 텍스트**(NUL 거부, 마크다운·HTML 해석 없음), 사용자당 최대 300개 | 노트(M2)와 같은 위생 규칙, XSS 면적 제거, 남용 상한 |
| D5 | **체크는 공용 질문과 같은 `user_progress` 를 쓴다**(slug 만 다르다). 추가했다고 자동으로 "학습함"이 아니다 | 시험 풀 규칙("체크한 질문", "미학습 포함")이 하나로 유지된다. 강사님이 짚어 준 것을 추가해 두고 공부한 뒤 체크하는 흐름이 자연스럽다 |
| D6 | 시험 범위 선택에 **가짜 주제 "내 질문"**(`@mine`)을 더한다. 주제·카테고리 필터가 있으면 `@mine` 을 골랐을 때만 내 질문이 들어가고, 필터가 없으면(전부) 들어간다. 난이도 필터는 내 질문의 난이도에 그대로 적용 | 기존 범위 UI·`Scope.accepts` 를 거의 그대로 쓴다 |
| D7 | 시험에서 내 질문의 "모범 답변"은 **내가 적은 답**이다(없으면 "적어 둔 답이 없습니다"). 시험이 끝난 뒤 "사전에서 보기"는 `/mine/{id}` 로 간다 | 답 공개 시점에 `GET /api/v1/mine/{id}` 를 부른다(M3 의 "보기 전에는 내려오지 않는다"와 같다) |
| D8 | 의존 방향: `mine` → `account`(탈퇴 이벤트)만. `progress`·`quiz` → **`mine.read` 패키지**(`MyQuestionReader`: 존재 확인·풀 목록·제목 조회, JDK 타입만 반환). ArchUnit 로 고정 | M3 의 `progress.read`·`quiz.read` 패턴 그대로 |
| D9 | 탈퇴하면 `mine` 이 내 질문을 지우고, 질문을 지울 때 `MyQuestionDeleted` 이벤트로 `progress`(체크)·`quiz`(통계)의 해당 slug 행을 같은 트랜잭션에서 지운다. 지난 시험 문항(`quiz_item`)은 남긴다 | 고아 통계가 후보·현황에 끼지 않게 한다. 기록은 A3 로 안전하다 |
| D10 | 진도 막대(홈·현황)는 **공용 질문만** 센다. 내 질문은 "내 질문" 화면에서 `n개 중 m개 학습` 으로 따로 보인다 | 공용 진도의 분모(556)를 사용자가 바꾸지 못하게 한다 |
| D11 | 모든 `mine` 응답은 `Cache-Control: no-store`, 공용 검색·주제·카테고리 응답에는 절대 섞지 않는다. 남의 id 는 **404**(존재를 알리지 않는다) | A4, M2·M3 의 규칙 |

## 4. 데이터 (V9)

`my_question(id UUID PK, user_id UUID NOT NULL, title VARCHAR(200) NOT NULL CHECK(1..200), answer_text TEXT NOT NULL DEFAULT '' CHECK(≤4000), keywords TEXT[] NOT NULL DEFAULT '{}', tier VARCHAR(8) NOT NULL CHECK(BASIC|DEEP|TRICKY), source_label VARCHAR(40) NULL, created_at, updated_at)`, 인덱스 `(user_id, created_at)`. NUL 은 DB·서비스 이중 검사. 모듈 사이 외래키 없음. 키워드 개수·길이는 서비스에서 검사한다.

## 5. 작업 순서 (각 단계: 테스트 통과 → 로컬 커밋, 변이(◆) 확인, 푸시는 S4·S8 뒤)

### S1. 스키마·`mine` 모듈 틀·ArchUnit
V9, `mine`(`MyQuestionService`, `mine.read.MyQuestionReader`), 의존 규칙 갱신(`progress`·`quiz` → `mine.read` 만). ◆ 규칙 위반 import 를 일부러 넣어 빌드가 실패하는지.

### S2. 내 질문 API
`GET /api/v1/mine`(목록, 체크 여부 포함), `GET /api/v1/mine/{id}`, `PUT /api/v1/mine/{id}`, `PUT /api/v1/mine/{id}/deleted`, 일괄 `PUT /api/v1/mine`. 엄격한 본문(모르는 필드·잘못된 타입 400), 크기 상한 413, 사용자 id 는 토큰에서만, 남의 id 404, 상한 300(409). `ApiSurfaceTest` 에 자동 포함, `no-store`. ◆ 남의 id 조회를 허용하는 변이가 잡히는지.

### S3. 체크·시험·후보 연동
- `progress` 가 `my-…` slug 를 **내 것인지 확인**해 체크를 받는다(공용 가시성 검사와 합성).
- `QuizService` 풀에 `mine.read` 의 내 질문을 더하고(D6) 시험 문항의 제목·답 공개를 지원한다. 후보·현황의 제목 조회를 공용 + 내 질문으로 합성한다(`api` 계층).
- 삭제 이벤트(D9)와 탈퇴 정리, 시험 기록 보존(A3) 시험.
◆ 풀에 남의 질문이 들어가는 변이, 삭제 뒤 통계 잔존 변이.

### S4. 통합 e2e (게이트웨이 경유) → **푸시**
추가 → 체크 → 시험에 출제 → 답 공개 → 틀림 → 후보 → 삭제 → 지난 시험 결과가 깨지지 않음, 두 사용자 격리, DELETE 는 403·PUT 은 통과, 탈퇴 동기화가 내 질문을 지운다.

### S5. 웹: 내 질문 화면
`/mine`(목록·추가 폼·체크·출처 표시 배지·`n개 중 m개`), `/mine/:id`(보기·수정·삭제 확인창), 일괄 추가(제목을 줄 단위로 붙여넣기 → 여러 개, Q3). 초안 보호(`setDraftDirty`), 낙관적 체크, `APP_ROUTE_PATHS` 추가. 상단 메뉴에 "내 질문".

### S6. 웹: 시험·후보·현황 연동
시험 시작의 "내 질문" 범위, 진행 화면의 내 답 공개, 결과·후보·현황의 링크를 `my-` slug 면 `/mine/{id}` 로(`questionLink` 한 곳). 훑기는 이번에 제외.

### S7. 모바일 감사·접근성
새 화면 3종(목록+폼, 상세·수정, 삭제 확인창) × 폭 4 × 라이트·다크, 긴 제목·긴 단어·300개 목록. ◆ 터치 영역·대비를 일부러 깨 감사가 실패하는지.

### S8. 결과 기록 → **푸시**
이 문서 끝에 결과 절, DESIGN §6(`my_question`)·§6.0(`mine` 모듈)·§8(관리 줄 삭제)·§9(편집자 API 삭제, `mine` API)·§12 M4 행 정정.

## 6. 시험 계획 요약

서비스(실제 Postgres): 필드 검증 경계값, 멱등(같은 id), 사용자당 300 상한, 일괄 50 상한·부분 실패 없음(전부 또는 아무것도), 남의 id 404, 삭제 후 체크·통계 정리와 시험 기록 보존, 풀 구성(내 질문 포함·`@mine` 범위·난이도 필터·미학습 포함), 탈퇴 정리. API: 엄격 본문, 413, 비로그인 401, `no-store`, 공용 응답에 내 질문 없음(바이트 비교). 웹: 폼 검증·초안 보호·낙관적 체크·삭제 확인, 시험 중 답 공개 전 미요청. e2e: S4. 모바일 감사: S7.

## 8. 서버·Doro 변경

**없다.** 새 엔드포인트가 모두 `GET`/`PUT` 이고 경로는 기존 `/interview/api/` 아래라 게이트웨이 조각을 바꾸지 않는다. CD 가 배포하고 Flyway V9 가 서버에서 돌아간다.
