# 프론트 설계: 유저 친화적 · 모바일 우선 다시 짜기

> 상태: **F0~F5 구현 완료 (2026-10-21, §10 결과)** — §9 의 권장안을 사용자가 전부 확정했다. 이 문서는 구현 순서와 확인 기준을 정하고, 제품 규칙(풀·가중치·검수)은 [DESIGN.md](DESIGN.md) 가 원본이다.
> 근거: 운영 화면을 폰(375px)과 데스크톱에서 직접 열어 본 관찰(§2). 기능 수는 늘었는데(질문 은행·시험·훑기·현황·내 질문·AI 피드백) **화면 구조는 M1 때 그대로**라서, 처음 온 사람이 "무엇을 하는 곳이고 다음에 뭘 누르는지"를 알기 어렵다.

## 1. 목표와 비목표
**목표**
1. 처음 온 사람이 10초 안에 무엇을 하는 서비스인지 알고, 한 번의 탭으로 읽기나 시험을 시작한다.
2. 폰에서 **엄지 하나로** 쓴다: 자주 쓰는 동작은 화면 아래쪽, 읽는 글은 첫 화면 안에서 시작한다.
3. 지금의 약속은 유지한다: 접근성(대비·44px 터치 영역·키보드), 서비스 워커·오프라인 동작, 번들 예산, 일반 텍스트 렌더링, 모든 쓰기는 PUT.

**비목표**: 새 기능 추가(서버 API 변경은 거의 없다), 브랜드 캐릭터 제작, 다국어, 앱 스토어용 네이티브 앱.

## 3. 설계 원칙
1. **읽기 먼저**: 질문·답변 본문이 첫 화면에서 시작한다. 설정(필터·개념)은 접는다.
2. **엄지 영역**: 폰에서 주요 이동은 **아래 탭 바**, 한 화면의 주 동작(체크·다음·평가)은 **아래 고정 바**.
3. **한 화면 한 일**: 홈은 "오늘 할 일", 주제는 "고르기", 질문은 "읽기", 시험은 "집중".
4. **말을 쉽게**: 내부 용어를 쓰지 않는다(`필수도 3 · 필수` → "자주 나와요", `보충 있음` → "공식 문서 밖 설명 포함", `tier` → 난이도).
5. **모양은 역할**: 눌리는 것(버튼·링크)과 정보(배지·키워드)의 모양을 다르게 한다.
6. **안 깨지게**: 기존 접근성·모바일 감사·번들 예산·오프라인이 그대로 관문이다.

## 5. 화면별 제안
**홈 (로그인)** — 위에서 아래로: ① **오늘 할 일 카드**: [이어서 시험 보기 / 새 시험 시작] 큰 버튼, 다시 공부 후보 N개, 전체 진도 한 줄(링 또는 막대). ② **카테고리 칩 6개**(가로 스크롤)를 누르면 그 카테고리의 주제만 아래에 나온다(처음엔 마지막에 본 카테고리). ③ 주제 카드는 **작게**(제목·질문 수·진도 막대 한 줄, 폰 한 화면에 5개 이상).
**홈 (비로그인)** — ① 한 줄 소개와 "질문 은행 둘러보기 / 로그인하고 시작" 두 버튼 ② 자주 나오는 질문(필수도 3) 5개 미리보기 ③ 같은 카테고리 칩+주제 목록.
**탐색** — 카테고리 칩 + 검색 + 개념 탭(개념 목록은 별도 화면 대신 탭).
**주제** — 상단에 **난이도 분할 버튼**(전체/기본/심화/함정) 한 줄만. 나머지(필수도·보충·개념 칩)는 `필터` 버튼 → **아래에서 올라오는 시트**로 옮긴다. 활성 필터는 요약 한 줄로 보이고 한 번에 초기화. 질문 카드는 제목(코드 서식 적용)·난이도 점·"자주 나와요" 표시·체크 한 개.
**질문** — 순서: 제목 → 메타 한 줄(난이도·자주 나와요·공식 문서 밖 설명 여부) → **모범 답변** → "핵심 키워드"(알약, 눌리지 않음, 표시만) → 근거 접기 → 이어 볼 질문. 개념은 "관련 개념" 한 줄 링크 모음으로 모양을 달리한다. **아래 고정 바**: [학습함 체크] [다음 질문 →]. 책 근거·출처는 접힘.
**시험** — **집중 모드**: 탭 바를 숨기고 상단에 진행 막대·남은 문항, 내용은 질문·입력, **평가 버튼은 아래 고정**(맞음/틀림/건너뛰기). 모범 답변 공개 후 스크롤하지 않고도 평가할 수 있다.
**결과·현황·내 질문** — 숫자는 큰 글씨 카드, 목록은 간격을 줄인 행. 내 질문 추가는 아래 고정 `+` 버튼.

## 6. 시각 언어
- **색 토큰 유지**(대비 검증이 이미 되어 있다) + 의미 색 추가: 성공(맞음)·주의(틀림/후보)·정보. 다크 모드 **수동 전환**(시스템/밝게/어둡게)을 내 공부 화면에 둔다.
- **글자**: 본문 폰에서 17px·줄 간격 1.75, 제목 계층 3단계, 한글 `keep-all` 유지. 코드는 고정폭, **제목·목록의 `` `코드` `` 는 인라인 코드 서식**으로 그린다(P4).
- **모양**: 카드는 연한 면 + 얇은 테두리, 눌리는 요소는 채움/윤곽 버튼, 정보는 작은 라벨. 터치 영역 44px 이상(지금 기준 유지), 아래 바는 `safe-area-inset-bottom` 을 반영(`viewport-fit=cover`).
- **로딩**: "불러오는 중…" 대신 **뼈대(skeleton)** 와 빈 상태 일러스트 없이 문장+행동 버튼.
- **아이콘**: 라이브러리 없이 인라인 SVG 몇 개(탭 4개·검색·필터·체크·다음). 글자 라벨은 항상 함께 둔다.

모든 단계의 공통 관문: 모바일 감사(폭 4 × 라이트·다크, 터치 영역·대비·가로 스크롤), axe, 번들 예산(첫 화면 JS 150KB 이하), 서비스 워커 통합 e2e, 통합 e2e(게이트웨이 경유).
