# 복습 알림

학습한 질문을 시험(랜덤 면접·모의면접)에서 틀리면, **틀린 지 1·3·7일째 저녁 8시**(서울 시간)에 "다시 볼 질문 N개" 알림을 보낸다. 다시 풀어 맞히면 후보에서 빠지고, 또 틀리면 그날부터 다시 센다.

## 누구에게 무엇을
- 대상 질문은 **다시 공부 후보**와 같은 규칙이다: 체크했고, 마지막 출제 결과가 틀림이고, 지금 보이는 질문(공용 또는 내 질문). 그중 마지막으로 틀린 날이 오늘로부터 1·3·7일 전인 것만 센다(달력 날짜, `INTERVIEW_REMINDER_ZONE` 기준).
- 사용자마다 하루 한 건이다. 제목 "다시 볼 질문 N개", 본문은 대표 질문 제목, 누르면 `내 현황`(`<공개 경로>/stats`)이 열린다.
- 받을지 말지는 플랫폼 알림 서비스(doro-notify)가 판정한다. 사용자가 `내 공부 > 복습 알림`에서 **이 기기에서 받기**를 켠 기기에만 간다.
- 멱등 키가 `review:<날짜>:<사용자>` 라서 같은 날 두 번 돌아도 한 번만 간다. 보낼 시각에 서비스가 내려가 있었으면 그날 알림은 건너뛴다.

## 구조
- `reminder` 모듈: 대상 계산(`ReviewReminder`)과 기기 등록 대행(`PushSettings`). 다른 모듈은 읽기 창구(`catalog`, `mine.read`, `progress.read`, `quiz.read`)로만 읽는다(`ModuleRules`).
- 알림 서비스는 서비스 간 내부 API 로 부른다(호출자 토큰, Docker 내부망, 게이트웨이를 거치지 않음). 웹은 이 서비스의 `/api/v1/me/push*` 만 부르고, 이 서비스가 토큰의 사용자로 알림 서비스의 위임 API 를 부른다. 그래서 게이트웨이에 알림 경로를 따로 열지 않는다(GET·PUT 만 통과하는 기존 규칙 그대로).
- 기동할 때와 보내기 전에 알림 종류(`review`)와 공개 경로(`INTERVIEW_WEB_BASE_PATH`)를 알림 서비스에 등록한다(멱등).
- 웹: 서비스 워커(`web/sw/sw.ts`)가 푸시를 받아 알림을 띄우고, 누르면 앱 범위 안의 주소만 연다(`src/pwa/notificationTarget.ts`). 로그아웃하면 이 기기를 계정에서 떼어 낸다(같은 기기로 다른 사람이 로그인했을 때 이전 계정의 알림이 오지 않게).

## 켜기
기본은 꺼짐이다. 둘 다 서버의 `.env` 이고 값은 저장소에 두지 않는다.

| 어디 | 값 |
| --- | --- |
| 알림 서비스 `NOTIFY_INTERNAL_TOKENS` | 기존 목록 뒤에 `,interview:<토큰>`(32자 이상) |
| 이 서비스 `NOTIFY_SERVICE_TOKEN` | 같은 `<토큰>` |

알림 서비스는 `interview` 앱 등록 마이그레이션(doro-notify V5)이 배포돼 있어야 한다. 두 컨테이너를 다시 만들면(`--force-recreate`) 켜진다. 끄려면 `NOTIFY_SERVICE_TOKEN` 을 비운다(화면의 복습 알림 구역이 사라진다).

선택 변수: `NOTIFY_BASE_URL`(기본 알림 서비스 컨테이너 주소), `INTERVIEW_REMINDER_CRON`(기본 `0 0 20 * * *`), `INTERVIEW_REMINDER_ZONE`(기본 `Asia/Seoul`).

## 확인
- `내 공부 > 복습 알림 > 이 기기에서 받기` 후 **시험 알림 보내기**로 기기에 알림이 오는지 본다.
- 실행 결과는 로그 한 줄로 남는다: `review reminders: users=…, requested=…, failed=…`(사용자 id·알림 내용·토큰은 남기지 않는다).
