# M7 상세 계획: 꼬리질문 모의면접

> 상태: **M7a 구현 (2026-11-26, §11 결과)**. §10 은 사용자가 권장안대로 확정했다(Q1 본 질문 3·깊이 2, Q2 M7a 먼저 배포하고 1~2주 뒤 결정, Q3 세션 단위 한도, Q4 음성은 나중, Q5 PREREQ 규칙 그대로). M7b·M7c 는 아직 하지 않았다. 기준: [DESIGN.md](DESIGN.md) §7(출제)·§13, [M3-PLAN.md](M3-PLAN.md)(시험), [M6-PLAN.md](M6-PLAN.md)(AI 피드백), [CONTENT-GUIDE.md](CONTENT-GUIDE.md)(질문 연결).

## 0. 왜 하나

- 실제 면접은 질문 하나로 끝나지 않고 "그럼 ~는요?"로 파고든다. 지금의 랜덤 면접은 서로 관계없는 질문을 하나씩 낸다.
- 최근 30일 사용은 **읽기 위주이고 시험 API 요청은 7건뿐**이다. 연습 기능이 쓰이지 않는다. 모의면접은 "읽기 → 연습"으로 넘어가게 하는 기능이다.
- 꼬리질문 재료는 이미 있다. 사람이 검수한 질문 연결이 `FOLLOWUP` 758개(512개 질문이 하나 이상 가짐), `PREREQ` 591개, `RELATED` 1015개다(DB `question_link`). **꼬리질문의 1차 원천은 이 연결이고, AI 가 질문을 지어내지 않는다.**

## 1. 목표와 비목표

**목표**
1. **M7a (AI 없이)**: 본 질문 몇 개를 내고, 각 본 질문 뒤에 `FOLLOWUP` 연결을 따라 꼬리질문을 최대 2단계까지 이어 묻는다. 틀리면 `PREREQ` 로 한 단계 내려가거나 그 줄기를 끝낸다. 말하기 우선(60초 타이머, 답 텍스트는 선택). 끝나면 줄기별 결과를 보여 준다.
2. **M7b (AI 가 켜져 있을 때)**: AI 가 내 답을 보고 (빠진 키워드, 다음 꼬리질문 선택)을 돕고, 끝에 종합 리포트(강한·약한 개념)를 준다. AI 가 꺼져 있거나 실패하면 M7a 규칙으로 그대로 진행한다.
3. **M7c (선택)**: 브라우저 음성 받아쓰기, 내 질문(M4)의 AI 탐침.

**비목표**: AI 자동 채점(맞음/틀림은 계속 사용자가 고른다), AI 가 모범 답변을 지어내기, 자유 대화형 챗봇, 음성 합성(질문 읽어 주기), 회사별 질문 세트, 간격 반복(별도 과제), 다른 사람과 모의면접 공유.

## 3. 결정 (권장안; 사용자 확인 대상은 §10)

| # | 결정 | 이유 |
|---|---|---|
| D1 | **별도 표**: `mock_session`, `mock_turn`. `quiz_session.mode` 를 더하지 않는다 | 시험(M3 D2)은 "시작할 때 문항 순서를 전부 정한다"가 불변식이다. 모의면접은 답에 따라 문항이 늘어나므로 같은 표에 넣으면 그 불변식이 깨진다. 통계(`quiz_question_stats`)만 공유한다 |
| D2 | **본 질문은 시작할 때 정하고, 꼬리질문은 답할 때 하나씩 정한다.** 본 질문 풀 = `FOLLOWUP` 을 하나 이상 가진 질문 ∩ 내 체크(옵션 "미학습 포함"이면 보이는 질문 전체). 뽑기는 `QuizPicker.pick` 을 그대로 쓴다(가중 랜덤) | 출제 규칙을 새로 만들지 않는다. 연결이 없는 질문은 꼬리를 이을 수 없어 본 질문에서 뺀다 |
| D3 | **꼬리 규칙(M7a)**: 맞음 → 아직 이 세션에 안 나온 `FOLLOWUP` 중 하나(가중 랜덤), 깊이 2 까지. 틀림 → `PREREQ` 하나로 한 번 내려가고(깊이를 쓰지 않음) 그 뒤 줄기를 끝낸다. 후보가 없으면 줄기를 끝낸다. 건너뜀 → 줄기를 끝낸다 | 실제 면접관의 흐름(맞으면 파고들고, 막히면 기초를 확인하고 넘어감)을 단순하게 흉내 낸다. 상한이 있어 세션 길이가 예측된다(본 질문 3개 × 최대 4턴 = 12턴) |
| D4 | **다음 턴은 서버가 정하고 저장한다.** `PUT .../turns/{seq}` 로 결과를 보내면 응답에 다음 턴이 들어 있고, 그 턴은 이미 `mock_turn` 에 저장돼 있다. 같은 결과를 다시 보내면 같은 다음 턴을 돌려준다(멱등) | 새로고침해도 같은 질문이 이어진다. 클라이언트가 다음 질문을 고르면 결과가 조작 가능하고 재현이 안 된다 |
| D5 | **결과는 한 번 기록되면 고정**(M3 D3 와 같다). 같은 결과 재전송은 무시, 다른 결과는 409 | 다음 턴이 이미 그 결과로 정해졌기 때문이다 |
| D6 | **통계**: 출처가 `LINK`(실제 질문)인 턴의 결과는 `quiz_question_stats` 에 반영한다(시험과 같은 규칙). `AI_PROBE`(AI 탐침 질문) 턴은 반영하지 않는다 | 탐침은 질문 은행에 없는 문장이라 질문 단위 통계를 만들 수 없다 |
| D7 | **말하기 우선 화면**: 질문 → 60초 타이머(넘겨도 계속 가능, 표시만) → "모범 답변 보기" → 키워드 체크 → 맞음/틀림. 답 텍스트 입력은 접어 두고 선택이다. 답 텍스트가 없으면 AI 기능(M7b)은 그 턴에서 쓰지 않는다 | 폰에서 타이핑하는 부담이 시험이 안 쓰이는 이유 중 하나로 본다. 소리 내어 말하는 연습이 실제 면접에 가깝다 |
| D8 | **AI 의 역할을 좁힌다(M7b)**: 구조화 출력 `{missedKeywords: [...], next: {kind: LINK, slug} | {kind: PROBE, text, keyword}}` 만 받는다. `LINK` 는 서버가 넘긴 후보 목록(D3 의 후보) 안의 slug 여야 하고, `PROBE` 는 현재 질문 모범 답변의 빠진 키워드 하나에 대해 한 문장(≤120자)이어야 한다. 어긋나면 버리고 D3 규칙으로 대체한다 | AI 가 은행 밖 질문을 지어내거나 엉뚱한 주제로 새는 것을 구조로 막는다. 탐침도 "모범 답변에 있는 키워드"로 근거가 묶인다 |
| D9 | **프롬프트 주입 방어는 M6 D5 를 그대로 쓴다**(태그로 감싸기, 태그 무력화, 평문 출력, 웹은 일반 텍스트) + D8 의 출력 검증 | 내 답에 지시문이 있어도 다음 질문이 후보 밖으로 나갈 수 없다 |
| D10 | **AI 한도는 모의면접 세션 단위로 센다**: 세션 하나가 쓸 수 있는 호출은 `본 질문 수 × 최대 깊이 + 1`(리포트) 이하로 묶고, 하루 한도는 "AI 를 쓴 모의면접 세션 수"로 센다(기본 사용자 3/일, 전체 30/일) | 호출 단위(10/일)로 세면 모의면접 한 번에 한도가 바닥나 중간부터 AI 가 꺼진다. 세션 단위면 시작할 때 "AI 와 함께 / 없이"가 정해져 중간에 바뀌지 않는다 |
| D11 | **AI 가 실패하면 그 턴만 D3 규칙으로 대체**하고 세션은 계속된다(20초 제한, 재시도 없음, M6 와 같다). 실패한 호출은 한도에 세지 않는다 | 보조 기능이 연습을 막지 않는다 |
| D12 | **종합 리포트(M7b)**: 세션이 끝나면 AI 호출 1회로 강한·약한 개념과 다시 볼 질문을 요약한다. 입력은 질문 제목·결과·빠진 키워드뿐이고 답 원문은 보내지 않는다. AI 가 없으면 서버가 같은 표(줄기별 결과, 틀린 질문의 개념)를 규칙으로 만든다 | 리포트는 답 원문 없이도 만들 수 있다. 외부로 나가는 글을 줄인다 |
| D13 | **탈퇴·학습 초기화**: 기존 `AccountDeleted`·초기화 이벤트에 `mock_*` 정리 리스너를 더한다 | M2 D11, M3 와 같은 방식 |

## 4. 데이터 (V12)

- `mock_session(id UUID PK, user_id, main_count INT CHECK 1..5, max_depth INT CHECK 0..3, include_unlearned BOOL, ai_enabled BOOL, started_at, finished_at NULL, report TEXT NULL CHECK ≤4000자)`
- `mock_turn(session_id, seq INT, parent_seq INT NULL, depth INT, origin VARCHAR(10) CHECK IN ('MAIN','LINK','PREREQ','AI_PROBE'), question_slug VARCHAR(60) NULL, probe_text TEXT NULL CHECK ≤200자, probe_keyword TEXT NULL, result NULL|CORRECT|WRONG|SKIPPED, seconds NULL, answer_text NULL CHECK 1..2000자, missed_keywords JSONB NULL, answered_at NULL, PK(session_id, seq))`
  - `origin = AI_PROBE` 이면 `question_slug IS NULL AND probe_text IS NOT NULL`, 아니면 그 반대(CHECK)
  - 같은 세션에서 `question_slug` 유일(부분 유일 인덱스, NULL 제외)
- 외래키 없음(모듈 사이 규칙). 인덱스: `mock_session(user_id, started_at)`, AI 한도용 `mock_session(ai_enabled, started_at)`.

## 5. API (`/api/v1/mock`, 쓰기는 모두 PUT)

| 요청 | 설명 |
|---|---|
| `PUT /mock/{sessionId}` `{mainCount, maxDepth, includeUnlearned, scope, useAi}` | 시작. 본 질문을 뽑아 첫 턴을 만들고 돌려준다. `useAi` 는 AI 가 켜져 있고 한도가 남을 때만 참으로 저장된다. 같은 id 재전송은 같은 세션 |
| `GET /mock/{sessionId}` | 지금까지의 턴과 현재 턴(새로고침·재접속) |
| `PUT /mock/{sessionId}/turns/{seq}` `{result, seconds, answerText?}` | 결과 기록 → 다음 턴(없으면 `null` + `finished`)을 돌려준다(D4) |
| `PUT /mock/{sessionId}/finish` | 남은 줄기를 건너뛰고 끝낸다. 리포트를 만든다(멱등) |
| `GET /me/mock` | 최근 모의면접 목록(현황 화면) |

모든 응답은 `no-store`, 남의 세션은 404, 본문은 알려진 필드만 허용(M3 와 같다).

## 7. 시험 계획 요약

- **다음 턴 결정(순수 함수)**: 맞음 → FOLLOWUP, 깊이 상한, 틀림 → PREREQ 한 번 뒤 종료, 후보 없음·건너뜀 → 종료, 세션 내 중복 금지(순환 연결을 일부러 넣어도 끝남), 닫힌 질문 제외, 같은 난수로 재현.
- **서비스**: 풀(FOLLOWUP 없는 질문 제외, 체크/미학습 옵션), 멱등(같은 결과 재전송 → 같은 다음 턴), 다른 결과 409, 통계 반영(LINK·PREREQ 는 반영, AI_PROBE 는 안 함), 남의 세션 404, 탈퇴·초기화 정리.
- **AI(가짜 공급자)**: 후보 밖 slug → 규칙 대체, 탐침이 길거나 키워드가 모범 답변에 없음 → 대체, 깨진 JSON·시간 초과 → 대체 + 한도 안 씀, 내 답의 지시문(`ZZ-PWNED`)이 다음 질문을 바꾸지 못함, 세션 단위 한도(동시 시작 포함), 리포트 요청에 답 원문이 없음.
- **웹**: 타이머 표시, 답 텍스트 없이 진행, 새로고침 후 이어서, 오류별 문구, 일반 텍스트 렌더링, 모바일 감사(폭 4 × 라이트·다크).
- **e2e**: 게이트웨이 경유 PUT 통과, 시작 → 꼬리 2단계 → 틀림 → PREREQ → 종료 → 결과.
- **변이 확인**: 깊이 상한 제거, 중복 금지 제거, AI 출력 검증 제거, 통계에 탐침 반영 — 각각 시험이 실패해야 한다.

## 8. 위험

| 위험 | 완화 |
|---|---|
| 연결 품질이 고르지 않다(어떤 질문은 FOLLOWUP 이 1개뿐) | 본 질문을 FOLLOWUP 을 가진 질문으로 한정(D2), 줄기가 일찍 끝나도 다음 본 질문으로 넘어간다. 사용하면서 연결이 부족한 주제를 콘텐츠 작업 목록에 올린다 |
| AI 가 은행 밖 질문을 지어내거나 틀린 탐침을 낸다 | D8 출력 검증, 탐침은 모범 답변 키워드에 묶음, 탐침 턴은 통계에 안 넣음(D6) |
| 비용 | D10 세션 단위 한도, 리포트는 답 원문 없이(D12), 기본 꺼짐(M6 와 같은 스위치) |
| 사용자 글이 외부로 나감 | M6 D6 안내 + "AI 와 함께"를 시작할 때 고른다. 답 텍스트를 쓰지 않으면 아무것도 나가지 않는다 |
| 기능이 하나 더 늘어도 안 쓰인다 | S5 뒤 배포하고 사용을 본 다음 M7b 를 결정한다 |

## 9. 서버 반영

- **M7a**: 없음. 코드·스키마(V12)는 CD 로 배포된다. 쓰기는 PUT 만 쓰므로 게이트웨이 변경도 없다(A1).
- **M7b**: AI 를 켜려면 M6 §7 과 같은 서버 설정이 필요하다(사용자가 직접). 이미 켜져 있다면 추가 작업은 없다.

## 11. 결과 (M7a, 2026-11-26)

S1~S5 구현. AI(M7b)·음성(M7c)은 하지 않았다. 서버·게이트웨이 변경 없음(쓰기는 PUT 만, V12 는 표 추가뿐이라 되돌릴 수 없는 변경이 아니다).

### 바뀐 곳
- 백엔드: `V12__mock_interview.sql`, `CatalogReader.visibleLinks(kind)`(양 끝이 보이는 연결만), `quiz.MockPlanner`(다음 턴, 순수 함수), `quiz.MockService`, `api.MockController`(`/api/v1/mock`), 탈퇴·초기화 정리 리스너에 `mock_*` 추가, 오류 `QUIZ-400-02`(풀 없음). 시험과 모의면접이 같은 통계 반영(`QuizService.recordStats`)을 쓴다.
- 웹: `/mock`(시작), `/mock/:id`(진행·결과), 시험 시작 화면에 입구 링크. `APP_ROUTE_PATHS` 에 더해 서비스 워커 허용 목록도 따라왔다.

### 계획과 달라진 점
- **시작 화면의 범위는 난이도만** 고른다(주제 선택은 넣지 않았다). API 는 `topics`·`categories` 도 받는다.
- **규칙 리포트(D12 의 AI 없는 쪽)는 서버가 만들지 않고 화면이 턴 목록으로 계산**한다(줄기별 결과·맞음 비율·맞힌 꼬리 최대 깊이). `report` 열은 M7b 를 위해 비워 둔다.
- **`GET /me/mock`(최근 모의면접 목록)은 만들지 않았다.** 현황 화면은 시험과 같은 출제 통계로 모의면접 결과도 보여 준다(D6).
- 본 질문이 다른 줄기의 꼬리질문으로 먼저 나오면 본 질문으로 다시 묻지 않는다(그만큼 본 질문 수가 줄 수 있다).

### 변이(◆) 확인
깊이 상한 제거, 세션 내 중복 금지 제거, 틀림 → 기초 확인 제거, 통계 반영 제거, 결과 기록의 소유 확인 제거, 끝난 세션 기록 허용 — 모두 시험이 실패했다. 소유 확인 제거는 처음에 살아남았다: 마지막 조회가 다시 404 를 내서(실제 빈에서는 트랜잭션이 되돌린다) 시험이 쓰기 여부를 보지 않았기 때문이다. "남의 요청 뒤에 아무것도 바뀌지 않았다"는 단언을 더해 잡았다.

### 확인하지 못한 것
- 실제 휴대폰에서 소리 내어 답하는 흐름(타이머·접힌 입력)의 사용감. 모바일 감사는 레이아웃과 접근성만 잰다.

- 로컬 통합 e2e 는 셸의 기본 Java 가 21 이면 jar 가 뜨지 않는다(`UnsupportedClassVersionError`). Java 25 를 `JAVA_HOME` 으로 주고 돌렸다.
